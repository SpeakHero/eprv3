# 集中式授权策略映射方案说明

> **版本**：v1.0
> **日期**：2026-10-24
> **状态**：已落地（943 项后端测试 + 188 项前端测试全绿，Host 冒烟通过）
> **关联文档**：`集中式授权策略映射重构计划-20261024.md`（重构计划）、`权限整改与授权集中化重构总体执行计划-20261024.md`（总体执行计划）

---

## 一、背景与目标

原方案在每个控制器方法上硬编码 `[Authorize(Policy = "Permission:xxx")]` 标注（全量 87 处：71 方法级 + 16 类级），存在三个核心问题：

1. **授权策略与业务逻辑强耦合**：新增/调整规则需逐个修改控制器方法；
2. **维护成本高**：每次权限码调整涉及多文件修改与重新编译；
3. **遗漏风险**：新端点忘记标注即产生匿名可达的安全漏洞。

本方案将授权绑定关系从代码硬编码迁移至**模块规则基线 + 外部 JSON 覆盖**的集中式映射，由全局授权约定在应用启动期统一注入，控制器/动作方法上不再出现任何授权标注。

**达成指标**：控制器方法授权标注清零（87 → 0）；规则调整无需修改控制器代码；新增端点漏配由架构测试直接拦截。

---

## 二、总体架构

```
模块 EndpointPolicyMap（代码基线，每模块一个）
        │
        ▼  合并（控制器级 ∪ 动作级；JSON 同键覆盖；disabledKeys 删除）
config/common/authorization.json（外部覆盖层，可选）
        │
        ▼
EndpointPolicyCatalog（启动期定稿，Singleton，TryFind 查询）
        │
        ▼
EndpointPolicyConvention（IApplicationModelConvention，MvcOptions.Conventions[0]）
        │
        ▼  命中规则 → 单个 AuthorizeFilter（多 IAuthorizeData，CombineAsync 合并单策略单评估）
MVC 过滤器管线（AuthorizationMiddleware / 过滤器评估）
```

**关键设计决策**：

- **单过滤器多 IAuthorizeData**：命中规则的所有授权要求（租户上下文策略 + 权限码策略）装入**一个** `AuthorizeFilter`（构造器接受 `IEnumerable<IAuthorizeData>`），执行时经 `AuthorizationPolicy.CombineAsync` 合并为单一策略单次评估——与原「类级 + 方法级标注由端点元数据合并」语义严格等价（AND 叠加），避免多过滤器重复认证。
- **评估时机差异（D-10）已论证无害**：原特性走 `AuthorizationMiddleware` 早评估，注入过滤器走 MVC 过滤器管线晚评估。三点影响均成立且行为不变：① 黑名单失效令牌仍 401（认证在更早中间件完成）；② 许可先行逻辑不依赖评估时机；③ 已认证判定结果一致。
- **空规则携带 scheme**：命中空规则（仅认证端点）时注入一条 scheme-only 授权数据（`Policy = null, AuthenticationSchemes = OpenIddict 验证方案`），与原 `[Authorize(AuthenticationSchemes = ...)]` 等价，避免落入 DefaultPolicy 丢失 scheme。

## 三、规则模型

`EndpointPolicyRule`（`Qlx.Abstractions.Authorization`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `Controller` | string（必填） | 控制器名（不含 `Controller` 后缀，大小写不敏感） |
| `Action` | string? | 动作方法名；`null` 表示控制器级规则（该控制器所有动作继承） |
| `PermissionCode` | string? | 权限码，自动展开为策略名 `Permission:{code}` |
| `Policy` | string? | 显式策略名（如 `QlxPortalAdmin`）；与 `PermissionCode` 二选一 |
| `RequireTenantContext` | bool | 是否要求租户上下文（追加 `QlxTenantContext` 策略，与其他策略 AND 叠加） |
| `AllowAnonymous` | bool | 匿名豁免（命中后不注入任何授权过滤器） |

**合并语义**：

- 控制器级规则与动作级规则**并集**生效：`RequireTenantContext` 取或；策略集合 AND 叠加（控制器级在前）；`AllowAnonymous` 任一为真即真。
- JSON 覆盖层与代码基线按键 `Controller` / `Controller.Action` 合并：**同键整条替换**，新键追加。
- `disabledKeys`：按键删除规则（仅支持动作级键），删除后该动作回退为「仅认证」兜底。

## 四、三种维护方式

### 方式 1：模块规则基线（新增端点/新增模块）

每个模块一个 `*EndpointPolicyMap` 类（实现 `IEndpointPolicyMapProvider`），在模块 `ServiceCollectionExtensions` 注册：

```csharp
services.AddSingleton<IEndpointPolicyMapProvider, BasEndpointPolicyMap>();
```

**新增端点时的唯一动作**：在所属模块的 Map 类中追加一条规则。**漏配会被架构测试 `EveryPublicActionMustBeCoveredByRuleOrExemption` 直接拦截**（CI 失败），从机制上根治遗漏。

### 方式 2：JSON 覆盖（调整策略/紧急换码，无需重新编译）

编辑 `config/common/authorization.json`（节名 `endpointPolicies`）：

```json
{
  "endpointPolicies": {
    "rules": [
      { "controller": "TenantAdmin", "action": "GetOrgTree", "permissionCode": "bas.admin.org.menu.v2" }
    ],
    "disabledKeys": [ "File.Download" ]
  }
}
```

- `rules` 同键整条替换（上例将组织树端点权限码换成 `v2`）；
- `disabledKeys` 将 `File.Download` 降级为仅认证（紧急摘除权限码场景）。
- **修改后需重启 Host 生效**（Catalog 启动期定稿，保证评估一致性）。

### 方式 3：逃生舱（个别端点保留手写标注）

控制器/动作上保留 `[Authorize]` / `[AllowAnonymous]` 特性时，约定**跳过注入**（以手写标注为准）。用于个别端点的特殊授权需求（如组合 scheme、自定义策略）。架构测试 `NoPermissionPolicyHardcodeRegression` 仅禁止 `Policy = "Permission:..."` 形式的回退，不禁止其他手写标注。

## 五、JSON 防删机制

`EndpointPolicyCatalog` 构造时经 `QlxConfigurationExtensions.ResolveQlxConfigRoot` 解析配置根：

- `config/common/authorization.json` **缺失或为空**时，自动将当前生效的代码基线序列化写出到该路径（写失败仅告警，不阻断启动）；
- 文件**已存在**时不覆盖，以文件内容作为覆盖层加载。

效果：运维误删文件后重启 Host 即可自动重建基线快照；日常运维可直接以生成文件为底稿调整。

## 七、维护注意事项

1. **权限码必须在模块 Manifest 声明**：Map 中的 `PermissionCode` 若未在本模块 `Manifest.Permissions` 注册，策略未物化，运行时一律 403。架构测试 `EveryPermissionCodeInMapMustExistInModuleManifest` 已守护。
2. **JSON 修改需重启生效**：Catalog 为 Singleton 启动期定稿，不做热重载（有意取舍：避免运行期规则漂移与评估不一致）。
3. **控制器/动作名大小写不敏感**：匹配经 `StringComparer.OrdinalIgnoreCase`。
4. **自助端点模式**：登录用户自助端点（如消息中心 UnreadCount/MarkRead 等）声明为控制器级 `RequireTenantContext` + 动作级空规则，仅要求已认证租户用户，不绑定权限码。
5. **登录/令牌端点必须匿名**：`Authorization.Exchange` 等端点在 Map 中声明 `AllowAnonymous = true`——误配将导致无法登录（冒烟哨兵：POST /connect/token 匿名应返回 400 而非 401/404）。
6. **评审红线**：禁止在控制器上恢复 `Policy = "Permission:..."` 硬编码（架构测试守护）；禁止绕过 Map 直接在 JSON 中编造未在 Manifest 声明的权限码。
