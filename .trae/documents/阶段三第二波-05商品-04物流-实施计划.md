## 0. 自查自纠（本轮评审前自审结论）

| # | 原计划问题 | 修正 |
|---|-----------|------|
| S-1 | Wms 作业完成与 Stk 写流水分属两个 DbContext，无法共享事务；先写 Stk 后写 Wms 会出现「流水已记、作业未完成」或反向的脏状态 | 引入 **Wms 命令 Outbox**：`wms_stock_command_outbox` 与作业状态同事务写入，`WmsStockCommandDispatchJobHandler` 异步驱动 `IStockTxnCommandService`；Stk 侧以 `(SourceType, SourceDocNo, SourceLineNo, ItemId, WarehouseId, BatchNo, Direction)` 唯一索引实现幂等（at-least-once + 去重） |
| S-2 | `StockBalance.RowVersion(byte[] [Timestamp])` 仅 SQL Server 支持，Sqlite 单测无法建表 | 改 `long Version` 并发令牌（`OnModelCreating` 显式 `IsConcurrencyToken()`），服务内自增；两种提供方行为一致 |
| S-3 | 金额口径自相矛盾：既写 `amount = Round(qty*avg,2)`，又要求 `avg=(原金额+入金额)/(原数量+入数量)`，会产生累计漂移 | 明确：**金额为累计主值**，入库 `amount=oldAmount+Round(qty*unitCost,2)`，出库 `amount=oldAmount-Round(qty*avg,2)`，`qty=0 → amount=0`；`avg=Round(amount/qty,4)`，`qty=0` 时保留上次均价 |
| S-4 | 未定义跨模块共享枚举，Wms 只能传裸 int，易错 | Abstractions 新增 `Stock/StockContracts.cs`：`StockDirection`、`StockSourceType`、`StockPostStatus` 等数值枚举，Stk/Wms 共用 |
| S-5 | `IStockQueryService`（Stk 实现）与 `IWarehouseQueryService`（Wms 实现）存在 DI 循环风险 | 明确约束：两个查询实现**只依赖各自 DbContext**，互不注入；Wms 停用校验注入 `IStockQueryService`（仅接口），Stk 商品服务注入 `IWarehouseQueryService`（仅接口），无构造环 |
| S-6 | 成本字段权限只登记了权限点，未规定响应裁剪 | `stk.cost.field` 缺失时响应 DTO 的 `AvgCost/Amount/RefCostPrice/UnitCost` 置 `null`（字段级安全过滤，B-3-1），列表与详情一致 |
| S-7 | `PostStockTxnRequest` 缺少幂等键、来源行号、业务时间，无法支撑 Outbox 重投 | 请求记录补 `SourceLineNo`、`IdempotencyKey`、`OccurredAt`；`PostBatchAsync` 对已存在幂等键直接返回成功 |
| S-8 | 流水触发器未含回滚脚本与作用域说明 | 迁移 `Up` 建 `trg_stk_stock_txns_no_update_delete`，`Down` `DROP TRIGGER`；仅 SQL Server 生效，Sqlite 单测不建触发器由服务层「无更新方法」保证 |
| S-9 | 期初批次号前缀 `SP-QC` 不在既定前缀清单内 | 登记为偏差（详设未指定期初号段）；沿用 `SP-` 域前缀，避免自造新域；写入批次实施记录偏差表 |

| S-11 | 前端页面总数与路由矩阵未闭环（2A 实际 7 页） | §3.10 明确 2A=7 页（Wms 仓库档案 + Stk 六页）、2B=6 页，路由与 Manifest 菜单一一对应 |

### 3.4 库存台账算法与一致性（核心铁律）

1. 唯一写入口：`StockLedgerService`（实现 `IStockTxnCommandService`），**任何 API 不得直接改台账**。
2. 入/出公式（D-06 修正版）：
   - IN：`newQty=oldQty+q`；`newAmount=oldAmount+Round(q*unitCost,2)`；`avg=newQty==0?0:Round(newAmount/newQty,4)`。
   - OUT：`unitCost=当前avg`；`newAmount=oldAmount-Round(q*avg,2)`；`newQty=oldQty-q`；`newQty==0→newAmount=0`，`avg` 保留。
   - 负库存：`q > qtyOnhand - qtyLocked` → 整单回滚，返回 `ErrorCode=STK_INSUFFICIENT` + `ShortageQty`。
3. 批次：启用批次商品必填 `BatchNo`；入库按批次累计、出库按指定批次扣减；批次与总额同事务更新。
4. 流水：仅 INSERT，写 `balance_qty_after`/`balance_amount_after`；SQL Server 触发器禁止 UPDATE/DELETE（迁移 Up 建、Down 删）。
5. 并发：`Version` 并发令牌 + 事务内重算；`DbUpdateConcurrencyException` 整单重试 3 次，超限 409。
6. 幂等：同一 `IdempotencyKey` 重复投递直接返回既有结果，不重复写流水。
7. 一致性边界（S-1）：Wms 作业与命令同事务落 `wms_stock_command_outbox`；分发任务调用 Stk，成功后回写 `Dispatched`，失败保留待重试（指数退避，最大 10 次后转异常告警）。
