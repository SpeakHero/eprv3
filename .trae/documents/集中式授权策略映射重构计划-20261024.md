# 集中式授权策略映射重构计划

> **日期**：2026-10-24（v2，按评审意见调整技术路线）
> **背景**：权限交叉场景整改（fix-1）已为 Bas / Support 控制器补齐 72 处 `[Authorize(Policy = "Permission:...")]` 硬编码标注，权限点体系已生效。本计划在此基础上做结构性升级：把散落各控制器的方法级/类级授权标注迁移至**集中式规则目录 + 启动时授权约定注入**，消除硬编码。
> **评审决策（v2）**：技术路线采用**启动时 IApplicationModelConvention 注入**（复用 ASP.NET Core 原生授权管线，放弃运行时中间件）；配置载体采用**配置类兜底 + JSON 覆盖**，且 **JSON 文件不存在时启动自动生成默认配置落盘，防止 JSON 被误删导致规则丢失**。
> **关联**：`.trae/documents/权限交叉测试整改计划-20261024.md`（fix-1 的标注内容即本次迁移的规则基线，1:1 平移，行为不变；fix-1 遗留的编译验证并入本计划验证环节）；`.trae/rules/global-cache-layering-standard.md`（B-3 安全过滤在后端、V-2 授权以服务端为准）。

## 二、目标方案

### 2.1 总体结构

```
┌─ 规则声明层（配置类基线，随模块内聚）──────────────────┐
│  BasEndpointPolicyMap / SupportEndpointPolicyMap /     │
│  PortalEndpointPolicyMap（各实现 IEndpointPolicyMapProvider）│
└──────────────┬───────────────────────────────────────┘
               │ 启动时合并
┌──────────────▼───────────────────────────────────────┐
│  config/common/authorization.json（覆盖层）            │
│  · 存在 → 按 (controller, action) 键同键覆盖基线       │
│  · 不存在/空 → 用基线，并把基线序列化写出默认 JSON（防删）│
└──────────────┬───────────────────────────────────────┘
               │ 构建一次（启动期）
┌──────────────▼───────────────────────────────────────┐
│  EndpointPolicyCatalog（Singleton，启动时定稿）         │
│  (controller, action) 双级索引                        │
└──────────────┬───────────────────────────────────────┘
               │ 启动时注入
┌──────────────▼───────────────────────────────────────┐
│  EndpointPolicyConvention（IApplicationModelConvention）│
│  经 IConfigureOptions<MvcOptions> 注册（同              │
│  PermissionPolicyConfigurer 模式）                     │
│  按目录给每个 Action 注入 AuthorizeFilter               │
│  → 由 MVC 过滤器管线评估（时机差异见 D-10）             │
└──────────────────────────────────────────────────────┘
```

### 2.2 规则合并与解析语义

**合并（启动时一次）**：
1. 基线合并：同一 action 的有效规则 = 控制器级规则 ∪ 动作级规则（`RequireTenantContext` 取或、策略集合取并、`AllowAnonymous` 任一为真即真）——与现有"类级 + 方法级标注叠加"语义严格等价。
2. JSON 覆盖：`rules` 条目按 `(controller, action)` 键**同键覆盖**基线合并结果；**基线新增键不受旧 JSON 掩盖**（合并而非整体替换，防止版本升级新增端点规则被存量 JSON 吞掉）。
3. 禁用：`disabledKeys`（`"Controller"` 或 `"Controller.Action"`）删除对应规则——端点回退到"仅认证"默认兜底（**不会变成匿名放行**，安全降级方向固定）。

**注入（convention 对每个 Action）**：
- Action/Controller 已带 `[AllowAnonymous]` 或显式 `[Authorize]`（残留/逃生舱标注）→ **跳过不注入**，原生语义优先。
- 有效规则 `AllowAnonymous = true` → 不注入任何授权过滤器（显式匿名）。
- 有效规则存在 → 注入 `AuthorizeFilter`：
  - `RequireTenantContext` → 注入 `QlxPolicyNames.TenantContext` 策略过滤器（控制器级效果）
  - `PermissionCode` → 注入 `Permission:{code}` 策略过滤器
  - `Policy` → 注入该裸策略名过滤器（如 PortalAdmin）
  - 多个并存 = 多个过滤器叠加（AND，与原类级+方法级叠加一致）
  - 所有注入的过滤器统一携带 `AuthenticationSchemes = OpenIddictValidationAspNetCoreDefaults.AuthenticationScheme`（与原标注 scheme 语义一致）
- 目录 miss（无规则）→ 注入**仅认证**过滤器（带统一 scheme）兜底——等价现状（所有控制器当前均有类级认证要求），安全失败方向固定。

### 2.3 JSON 防删机制（评审要求）

启动构建 Catalog 时：
1. `config/common/authorization.json` 不存在或内容为空 → 使用代码基线，并将基线规则全量序列化为默认 JSON **写出到该路径**（info 级启动日志），运维随后可直接在文件上看到/调整全部规则。
2. 文件存在 → 读取合并。
3. 写文件失败（权限等）→ 警告日志，不影响启动（基线兜底仍在）。

> 配置变更在**重启后生效**（启动时注入路线的既定语义）；JSON 被删只需重启即自动重建，规则永不丢失。

## 三、具体变更

### 3.1 新建：抽象层（Qlx.Abstractions/Authorization）

**`EndpointPolicyRule.cs`**

```csharp
public sealed record EndpointPolicyRule
{
    public required string Controller { get; init; }          // 控制器名（不含 "Controller" 后缀）
    public string? Action { get; init; }                      // null = 控制器级
    public string? PermissionCode { get; init; }              // 权限码（内部转 Permission:{code} 策略）
    public string? Policy { get; init; }                      // 裸策略名（PortalAdmin 等非权限点策略）
    public bool RequireTenantContext { get; init; }           // 叠加 QlxTenantContext 策略
    public bool AllowAnonymous { get; init; }                 // 显式匿名豁免
}
```

**`IEndpointPolicyMapProvider.cs`**：`IReadOnlyList<EndpointPolicyRule> GetRules()`，模块可选实现，DI 多注册。

### 3.2 新建：BuildingBlocks/Authorization

| 文件 | 职责 |
|---|---|
| `EndpointPolicyOptions.cs` | `Rules: List<EndpointPolicyRule>`、`DisabledKeys: List<string>`；绑定 `endpointPolicies` 配置节（`IOptions<>`，启动时读取一次） |
| `EndpointPolicyCatalog.cs` | Singleton。注入 `IEnumerable<IEndpointPolicyMapProvider>`（DI 原生多注册解析；**不**注入 `IReadOnlyList<>`——避开 E-9 教训的集合语义坑，多 provider 合并由单测锁定）+ `IOptions<EndpointPolicyOptions>` + `IHostEnvironment` + 日志。构造时：读 JSON → 缺失则写出基线默认 JSON（防删）→ 合并建双级索引（键 `controller` / `controller.action`，序数不区分大小写）。`TryFind(controller, action, out rule)`：动作键 → 控制器键顺序命中后按 §2.2-1 合并；miss 返回 false |
| `EndpointPolicyConvention.cs` | `IApplicationModelConvention`。遍历 `ApplicationModel.Controllers` 的全部 Action，按 §2.2 注入 `AuthorizeFilter`（经 `new AuthorizeFilter(IEnumerable<IAuthorizeData>)` 构造，传入 `AuthorizeAttribute { Policy, AuthenticationSchemes }` 以保留 scheme）；跳过已带 `IAuthorizeData`/`IAllowAnonymous` 的 Action/Controller |
| `EndpointPolicyMvcConfigurer.cs` | `IConfigureOptions<MvcOptions>`：`options.Conventions.Insert(0, new EndpointPolicyConvention(catalog))`（插首位，保证先于其他约定） |
| `EndpointPolicyExtensions.cs` | `AddQlxEndpointPolicies(this IServiceCollection, IConfiguration)`：`services.Configure<EndpointPolicyOptions>(config.GetSection("endpointPolicies"))` + 注册 Catalog Singleton + 注册 `IConfigureOptions<MvcOptions>` |

### 3.3 新建：三个模块的规则映射（规则内容 = 现有标注快照，1:1 平移）

- `src/Qlx.Modules.Bas/BasEndpointPolicyMap.cs`：TenantAdmin 控制器级 `RequireTenantContext = true` + 26 条动作权限码（按现标注）+ TenantMenu 控制器级 1 条。
- `src/Qlx.Modules.Support/SupportEndpointPolicyMap.cs`：5 个控制器共 45 条；消息的自助端点（unread-count / 已读 / 删自己收件箱 / 全局项状态 / 订阅查询）只继承控制器级 TenantContext，无动作级权限码（与现状一致）。
- `src/Qlx.Modules.Portal/PortalEndpointPolicyMap.cs`：PortalAdmin / PortalRole / PortalRolePermission / PortalUserRole 四个控制器级 `Policy = QlxAuthConstants.Policies.PortalAdmin`；Me / PortalMenu / TenantMemberRole / SystemParameters 四个控制器级空规则（仅认证，显式声明供覆盖率断言）。
- 各模块 `ServiceCollectionExtensions` 追加 `services.AddSingleton<IEndpointPolicyMapProvider, XxxEndpointPolicyMap>();`

### 3.4 配置文件

`config/common/authorization.json` **不随代码提交**（由首次启动自动生成）；`.gitignore` 是否排除在执行时确认（若团队希望规则入版本管理则提交生成版，二者皆可，默认提交生成版以便评审追踪）。结构即 `endpointPolicies` 节：

```json
{
  "endpointPolicies": {
    "rules": [ { "controller": "TenantAdmin", "action": "CreateOrganization", "permissionCode": "bas.admin.org.action", "requireTenantContext": true } ],
    "disabledKeys": []
  }
}
```

### 3.5 修改：控制器清理（7 个文件）

- 移除 6 个 Bas/Support 控制器的全部方法级 `[Authorize(Policy = "Permission:...")]`（72 处）与类级 `[Authorize(...)]`；保留 `[ApiController]` / `[Route]` / `[AuditOperation]` 等无关标注；清理多余 `using`。
- 移除 Portal 4 个管理端控制器的类级 `[Authorize(...)]`；4 个仅认证控制器同样移除（convention 默认认证兜底 + 显式空规则声明）。
- 全库 Grep 确认匿名端点清单（`/connect/*` 为 OpenIddict 中间件直通，不走 MVC 授权；若有 MVC 匿名端点，规则表补 `AllowAnonymous = true` 条目）。

### 3.6 修改：Host 接线（Qlx.Host/Program.cs）

服务注册链追加 `.AddQlxEndpointPolicies(builder.Configuration)`（紧随 `AddQlxAuth` 之后）。**管线不动**（原生 `UseAuthorization` 评估注入的过滤器）。

## 六、假设与决策记录

| # | 决策 | 理由 |
|---|---|---|
| D-1 | 启动时 IApplicationModelConvention 注入（经 `IConfigureOptions<MvcOptions>`），弃用运行时中间件 | **评审决定**：复用原生授权管线（401/403/scheme/AllowAnonymous 语义全原生），结构最简单可靠；配置变更重启生效 |
| D-2 | 规则声明分布在各模块 MapProvider，应用集中在 Catalog/Convention | 与权限点"模块 Manifest 声明 + 集中注册"的既有模式一致；模块内聚、新增模块零接线 |
| D-3 | 配置类基线兜底 + JSON 覆盖；JSON 缺失时启动自动生成默认文件 | **评审决定**：防止 JSON 被误删导致规则丢失；运维可视、可调 |
| D-4 | JSON 与基线按键合并（非整体替换） | 防止版本升级新增端点规则被存量旧 JSON 掩盖 |
| D-5 | 无规则端点注入"仅认证"兜底过滤器 | 与现状等价，安全失败方向；架构测试强制零漏配 |
| D-6 | 显式 `[Authorize]`/`[AllowAnonymous]` 标注保留为逃生舱（convention 跳过） | 兼容存量/特殊端点，不破坏原生语义 |
| D-7 | 注入过滤器统一携带 OpenIddict Validation scheme | 与现有类级标注 `AuthenticationSchemes` 一致 |
| D-8 | disabledKeys 只降级到"仅认证"，永不降级为匿名 | 安全降级方向固定，防配置错误开口子 |
| D-9 | Catalog 启动时单次构建（`IOptions<>` 非热更） | 启动时注入路线的既定语义；如需热更，后续可在 Catalog 之上平滑升级（抽象已隔离） |
| D-10 | **已知差异（自查发现，如实记录）**：注入的 `AuthorizeFilter` 由 MVC 过滤器管线评估，执行时机晚于 `UseTokenBlacklist` / `UseModuleLicenseFilter` 中间件；现状 `[Authorize]` 元数据由 `AuthorizationMiddleware` 在二者之前评估 | 影响面论证后确认可接受：①黑名单中间件先行执行 → 黑名单令牌仍 401，对外表现不变；②许可过滤先行 → 匿名请求命中停用模块端点先收 404（原为先 401），泄露面仅限"模块许可状态"这一低敏信息，不泄露任何业务数据；③已认证请求的授权判定结果与现状完全一致。冒烟验证（§4.3）逐项比对状态码确认无回归 |
