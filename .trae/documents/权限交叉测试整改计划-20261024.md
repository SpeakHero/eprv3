## 一、现状关键事实（已探查确认）

1. **权限策略机制已存在但未接线**：
   - `src/Qlx.BuildingBlocks/Authorization/PermissionAuthorizationHandler.cs` 已实现 `PermissionRequirement(code)` 判定（租户上下文 TenantAdmin 零计算旁路 + `qlx_permissions` claim Split 包含匹配）。
   - 注册入口注释写明「各模块在各自 ConfigureServices 按需 AddPolicy」（`PortalServiceCollectionExtensions.cs:154-157`），但全项目仅 Portal 模块注册了 `PortalAdmin` 策略，**没有任何 `Permission:<code>` 策略被注册**，Bas/Support 控制器也未标注。
   - 权限点真源在模块 Manifest：Bas 6 个（`bas.admin.org/member/role` × menu/action，`BasModule.cs:33-40`）、Support 24 个（`SupportModule.cs:35-58`）、Portal 39 个。
2. **X-7 根因**：身份级令牌（无 `tenant_id` claim）调租户接口 → `TenantContextMiddleware` 解析为空 → `TenantDbContext` 抛 `InvalidOperationException("租户 Id 未初始化（0）")` → 500 直出。且 PermissionAuthorizationHandler 门户分支对 `is_portal_admin=1` 直接 Succeed，意味着仅加 Permission 策略无法拦住房门户管理员身份令牌访问租户接口，**必须另有租户上下文前置策略**。
3. **X-3 根因**：`stores/auth.ts:265-292` `enterTenant` —— JWE 令牌 `decodeJwtPayload` 返回 null 直接 return；`if (!this.memberRole)` / `if (this.permissions.length === 0)` 仅空值兜底，旧角色/旧权限残留。`enterPortalAdmin` 也不清 `memberRole`。
4. **X-4 根因**：`core/http.ts:38-46` `pickToken` 对 `/api/portal/admin/**` 恒用身份令牌（后端 `PortalAdmin` 策略本身正确：租户令牌→403）；`SiteHeader.vue:29-36` `visibleMenus` 仅按 `licensed()` 过滤，测试租户被授权了「门户管理」模块，故租户上下文仍显示门户入口；路由 `/portal/*` 守卫仅校验 `isPortalAdminAccount`，不校验 `portalAdminMode`。
5. **X-5 根因**：`TenantAdminService` 成员列表未按角色 `DefaultDataScope` 过滤（`TenantAdminService.cs:523/542` 仅做存取）；claim 常量 `qlx_data_scope` / `qlx_data_scope_dept` 已定义（`QlxClaimConstants.cs:76-79`）但消费端缺失。
6. **X-6 根因**：邀请固定写 `PendingInvite`（`TenantMemberAdmin.cs`），`ResetMemberPasswordAsync` 对 PendingInvite 抛 409，激活无出口。
7. **授权负向测试先例**：`tests/Qlx.BuildingBlocks.Tests/MultiTenancy/TenantIsolationRegressionTests.cs`（403 断言模式可复用）。

## 二、整改步骤（按 P0 → P1 → P2 顺序，每步编译验证）

### 步骤 1（P0）：后端权限策略补全 + 租户上下文前置拦截（X-1 / X-2 / X-7）

**1.1 公共层：策略自动注册器（新文件）**

- 新建 `src/Qlx.BuildingBlocks/Authorization/PermissionPolicyConfigurer.cs`：实现 `IConfigureOptions<AuthorizationOptions>`，注入 `IReadOnlyList<IModule>`，遍历全部 Manifest `PermissionDefinitions`，为每个权限码注册策略 `Permission:{code}`（`RequireAuthenticatedUser()` + `Requirements.Add(new PermissionRequirement(code))`）。模块启停/新增权限点零接线。
- 新建 `src/Qlx.Abstractions/Constants/QlxPolicyNames.cs`：`PermissionPrefix = "Permission:"`、`TenantContext = "QlxTenantContext"`、辅助方法 `Permission(string code)`。禁止散落字面量（硬编码三分归类）。
- `PortalServiceCollectionExtensions.cs` `AddAuthorization` 处追加：`options.AddPolicy(QlxPolicyNames.TenantContext, p => p.RequireAuthenticatedUser().RequireClaim(QlxClaimConstants.TenantId))`，并 `services.AddSingleton<IConfigureOptions<AuthorizationOptions>, PermissionPolicyConfigurer>()`。

**1.2 Bas 模块 `TenantAdminController.cs`：逐端点标注**

类级追加 `Policy = QlxPolicyNames.TenantContext`（与既有 AuthenticationSchemes 合并为一个 `[Authorize]`），动作级按映射表加 `[Authorize(Policy = "Permission:...")]`：

| 端点组 | 读（GET） | 写（POST/PUT/DELETE） |
| --- | --- | --- |
| `organizations/**` | `bas.admin.org.menu` | `bas.admin.org.action` |
| `members/**`（含 invite/toggle/reset/remove/import/resend） | `bas.admin.member.menu` | `bas.admin.member.action` |
| `roles/**`、`role-permissions`、`permissions` | `bas.admin.role.menu` | `bas.admin.role.action` |
| `modules` | `bas.admin.role.menu` | — |

TenantAdmin 由 Handler 零计算旁路，不受影响；普通成员只有被显式授予对应点才可通过。

**1.3 Support 五个控制器：同样两级标注**（类级 TenantContext + 动作级权限点）

| 控制器 | 端点 → 权限点 |
| --- | --- |
| `FileController` | upload→`support.file.upload`；download/preview/metadata→`support.file.download`；list→`support.file.menu`；delete、purge→`support.file.delete`；recycle/list→`support.file.menu`；restore→`support.file.restore`；acl 读写→`support.file.acl` |
| `JobController` | trigger→`support.job.trigger`；cancel→`support.job.cancel`；history/logs→`support.job.view`；definitions/configs 读→`support.job.view`、写→`support.job.config` |
| `MessageController` | inbox/sent/公告读→`support.message.read`；send→`support.message.send`；subscription 写→`support.message.subscription`；SSE stream 保持仅认证（长连接，订阅权限由服务层既有校验负责，不重复挂策略） |
| `ApprovalController` | todo/处理→`support.approval.todo`；initiate→`support.approval.initiate`；instances 读→`support.approval.instance`；flows 读写→`support.approval.flow`；delegates 读写→`support.approval.delegate` |
| `PrintController` | templates CRUD→`support.print.template`；render/preview→`support.print.render` |

实现时先逐控制器读现有端点清单再标注，上表为基准映射，遇未列端点按「读→menu/view 级、写→action 级」归位。

**1.4 X-7 验证**：身份级令牌（含门户管理员）访问 `/api/tenant/**`、`/api/support/**` → 统一 403（TenantContext 策略拦截），不再出现 500 内部细节。

### 步骤 2（P0）：前端切换企业状态收敛（X-3）

- `src/Qlx.Web/src/stores/auth.ts` `enterTenant`：`applyTenantTokenClaims` 之后，**以 `/me` 响应为权威无条件覆盖**：
  `this.memberRole = user.memberRole ?? ''`；`this.permissions = Array.isArray(user.permissions) ? user.permissions : []`。删除两处 `if (!x)` 兜底。JWE 不可解时 claims 不置空已有值、由 `/me` 覆盖，语义不变。
- `enterPortalAdmin`：显式清空 `this.memberRole = ''`、`this.permissions = []`（门户模式全通靠 `portalAdminMode` 旁路，不依赖残留值）。
- 新增 vitest 回归（并入 `stores/auth-session.spec.ts` 或新建 `auth-enter-tenant.spec.ts`）：①管理员→普通成员切换后 memberRole/permissions 被覆盖；②普通→管理员切换后权限完整恢复；③JWE（5 段假令牌）场景下 `/me` 兜底生效。

### 步骤 3（P1）：门户特权上下文隔离（X-4，前端收敛）

- `router/index.ts`：`/portal/*` 守卫在 `requiresPortalAdmin` 基础上追加 `auth.portalAdminMode` 校验，租户上下文内访问 → 重定向 `/workbench`。
- `components/SiteHeader.vue`：`visibleMenus` 与 `panelModules` 在**非门户管理模式**下排除 `portal` 模块编码的菜单组（门户管理/身份权限仅在门户管理模式展示）。
- `http.ts` `pickToken` **保持不变**（门户管理模式仍须身份令牌调 `/api/portal/admin/**`）；后端 API 级硬隔离（上下文标记）本期不做，理由：身份令牌即门户身份本体，跨域调用无越权增量，收敛属呈现层职责——记入报告遗留项。
- 补 vitest：路由守卫用例（租户上下文访问 `/portal/tenants` → 重定向）。

### 步骤 4（P1）：dataScope 数据范围过滤（X-5）

- `TenantAdminService` 成员/组织查询注入当前成员上下文（`ITenantContext` + `qlx_member_id` claim），按当前成员主要角色 `DefaultDataScope` 过滤：

## 三、决策与边界

1. **策略注册走 `IConfigureOptions<AuthorizationOptions>` 自动物化**，而非逐模块手写 AddPolicy——权限点新增零接线，与 Manifest 物化机制（E-9 教训：`IReadOnlyList<IModule>`）同构。
2. **门户特权不做 API 级硬隔离**（仅前端路由/菜单收敛）：身份令牌即门户身份，无越权增量；如产品要求硬隔离，后续以「上下文标记头 + 后端拒绝」另行立项。
3. **X-6 不新增激活端点**：复用「管理员重置密码 → 首登激活」通道，最小改动闭环。
4. **SSE stream 端点不挂权限策略**：长连接 + 服务层已有订阅校验，避免重复拦截。
5. **不做范围外重构**：不改动 PortalAdminController 既有策略、不动令牌结构/JWE、不引入新库。

## 四、风险

| 风险 | 缓解 |
| --- | --- |
| 权限点标注误伤正常业务读接口（如工作台依赖 members 读） | 步骤 1 实现前先核对待标注读接口的消费方；工作台若依赖，改挂 menu 级或服务层放开 |
| `PermissionPolicyConfigurer` 依赖 `IReadOnlyList<IModule>` 注册顺序 | Host 启动顺序已保证 AddQlxModules 在先；单测覆盖空模块集合不抛异常 |
| dataScope `Custom` 档表结构未就绪 | 按 Dept 降级 + 注释偏差，不阻塞本批 |
