# 缓存层合规审查与改造方案

> **版本**：v1.1（**已实施**，2026-10-23 全部 8 项改造落地并验收通过）
> **日期**：2026-10-23
> **审查依据**：`.trae/rules/global-cache-layering-standard.md` v1.1（C-1~C-7）
> **审查对象**：`src/Qlx.BuildingBlocks/Caching/*`（ICacheService / RedisCacheService / MemoryCacheService / CacheEntryOptions / CacheOptions / QlxCacheKey / CachingServiceCollectionExtensions）及全解决方案缓存使用点
> **结论**：通用缓存层**已存在且骨架合格**（唯一入口、提供方替换、SCAN 前缀删除、物理键前缀、默认过期），但对照强制标准存在 **8 项缺口（G-1~G-8）**，其中 G-1（跨实例防击穿）、G-2（空值缓存）、G-3（TTL 抖动）为**必须修复**项；审核通过后方可启动编码。

## 1 逐条符合度结论

| 规则 | 结论 | 现状证据 | 缺口 |
|---|---|---|---|

## 2 缺口清单与改造设计

### G-1 跨实例防击穿分布式锁（必须）

**位置**：`RedisCacheService.GetOrCreateAsync`

**设计**（进程内信号量保留为第一道，Redis 锁为第二道）：

```
1. Get 命中 → 返回
2. 进程内 keyLock（现有 SemaphoreSlim）→ 双重检查 Get
3. 尝试跨实例锁：SET {physicalKey}:lock {guidToken} NX EX 5
   ├── 获锁 → 再次 Get（防等待期间他实例已回填）
   │        ├── 命中 → 释放锁 → 返回
   │        └── 未命中 → factory 回源 → Set → 释放锁（Lua：校验 token 再 DEL，防误删他者锁）→ 返回
   └── 未获锁 → 随机退避 50~150ms → 重读 Get（循环，总等待上限 2s）
              ├── 期间命中 → 返回
              └── 超时仍未命中 → 直接回源但不写缓存（限流兜底：宁可是少量回源，不可雪崩；
                  写缓存权只属于持锁者，防无锁并发写入竞态）
4. factory 抛异常 → 释放锁，异常透传，不写缓存（配合 G-2：异常不缓存，仅 null 缓存）
```

- 锁 TTL 5s + factory 内部超时需 < 锁 TTL；锁不续期（短任务场景），factory 超 5s 视为设计错误，评审拦截。
- 死锁防护：锁带过期；token 校验删除（Lua 脚本 `if get==token then del`）。
- `MemoryCacheService` 不变（单实例语义），XML 注释补充「多实例部署必须使用 Redis 提供方」。

### G-2 NullMarker 空值缓存（必须）

**位置**：`RedisCacheService` / `MemoryCacheService` + `CacheEntryOptions`

**设计**：

1. 内部哨兵：`private sealed record NullMarker`（序列化为判别 JSON）。两提供方的 `GetOrCreateAsync` 中 factory 返回 `null` 时**自动写入 NullMarker**，TTL 取 `options.NullValueExpiration ?? TimeSpan.FromSeconds(30)`（30~60s 区间，调用方可配）。
2. `GetAsync<T>` 命中 NullMarker → 返回 `default`（对调用方透明，等同未命中语义但不再回源——注意：读路径区分「真空（无 key）」与「空值缓存」仅发生在 GetOrCreateAsync 内部：命中 NullMarker 时直接返回 default，**不触发 factory**）。
3. `CacheEntryOptions` 新增 `TimeSpan? NullValueExpiration { get; init; }`。
4. 显式 `SetAsync(key, null)` 同样落 NullMarker（语义统一：缓存「不存在」结论）。

### G-3 TTL 抖动（必须）

**设计（自动强制，优于调用方自觉）**：

1. 两提供方写入路径（`SetAsync` / `GetOrCreateAsync` 回填）对生效的绝对过期时长**统一自动施加 ±10% 随机抖动**（`expiry * (1 ± Random.Shared.NextDouble() * 0.1)`）。
2. `CacheEntryOptions` 新增 `bool DisableJitter { get; init; }`（默认 false；仅黑名单/租约等精确过期场景显式禁用并加注释说明理由）。
3. NullMarker TTL（G-2）同样加抖动。
4. 滑动过期不抖动（语义是访问续期）。

### G-4 RemoveByPrefixAsync 分批让出

**位置**：`RedisCacheService.RemoveByPrefixAsync`

- SCAN 游标流式收集，每满 **500** 个 key 即 `KeyDeleteAsync(批)` 并 `Task.Yield()` 让出；最后一批不足 500 照常删除；返回总删除数。
- `MemoryCacheService.RemoveByPrefixAsync` 遍历 `_knownKeys` 快照即可（进程内无阻塞风险），保持不变。

### G-5 PlatformSharedReader 迁移 ICacheService

**现状**：[PlatformSharedReader.cs](file:///e:/ERPv2/eprv3/src/Qlx.BuildingBlocks/MultiTenancy/PlatformShared/PlatformSharedReader.cs) 直用 `IMemoryCache` 进程内短缓存；[SupportServiceCollectionExtensions.cs](file:///e:/ERPv2/eprv3/src/Qlx.Modules.Support/SupportServiceCollectionExtensions.cs#L190) 配套注册 `IMemoryCache`。

**问题**：多实例下各进程缓存不一致、无跨实例失效手段；违反 C-1-1。

**改造**：构造注入由 `IMemoryCache` 改为 `ICacheService`，短 TTL 30s（经 G-3 自动抖动）；共享库故障降级本地语义保持不变；移除 Support 模块的 `IMemoryCache` 注册（若无其他消费方，同步清理 using 与注释）。

### G-6 规则文件键规范对齐（规则文件升 v1.2）

将 `.trae/rules/global-cache-layering-standard.md` C-1-2 修订为与实际一致：

> 缓存键必须经 `QlxCacheKey` 构建：租户级 `tenant:{tenantId}:{modulePrefix}:{businessKey}`（`BuildTenantKey`）；门户/平台级使用保留租户码 `_portal`；Redis 物理键自动附加实例名前缀（`CacheOptions.InstanceName`）；禁止散装字符串拼 key。

### G-7 坏值自愈

`RedisCacheService.GetAsync`：`JsonSerializer.Deserialize` 抛 `JsonException` 时捕获 → `KeyDeleteAsync` 清除坏 key → 返回 `default`（按未命中处理，走正常回源），并记 Warning 日志。

### G-8 架构测试守护

Architecture 测试新增断言（与 E-2-1 对齐）：

1. `Qlx.Modules.*` 程序集不得引用 `StackExchange.Redis` / `Microsoft.Extensions.Caching.Memory` / `Microsoft.Extensions.Caching.Abstractions`（`IDistributedCache`/`IMemoryCache`）。
2. `Qlx.Modules.*` 中类型不得声明 `IConnectionMultiplexer` / `IMemoryCache` / `IDistributedCache` 依赖（构造参数/字段扫描）。
3. BuildingBlocks 基础设施内部使用（RedisWorkerIdLease 等）维持白名单豁免并注释。

## 3 明确不做（Out of Scope）

- 缓存命中率/回源次数运行期指标（ICacheMetrics 埋点）：后续观测性批次统一设计；本次验证通过测试中工厂计数器完成。
- 二级缓存（内存 + Redis 分层）：当前无性能诉求，不引入复杂度。
- `cache.permission.sweep` 权限域清理任务：属权限体系重构方案 B-17，随权限批次实施，不在本方案。

## 4 测试计划

| 测试 | 要点 |
|---|---|
| `RedisCacheServiceDistributedLockTests` | 并发 50 调用同一过期 key → factory 仅执行 1 次（计数器断言）；未获锁者退避后读到同一值；锁释放后新调用可再获锁；factory 异常 → 锁释放、不写缓存 |
| `NullMarkerTests` | factory 返回 null → 仅 1 次回源，后续命中 NullMarker 不再回源；NullMarker TTL ≤ 60s 且带抖动；显式 SetAsync(null) 同语义 |
| `TtlJitterTests` | 同基线 TTL 写入 200 次，采样实际过期时间离散度 ∈ ±10% 且无聚集；DisableJitter=true 时精确等于基线 |

| `BadValueSelfHealTests` | 手工写入非法 JSON → Get 返回 default、坏 key 被清除、随后 GetOrCreate 正常回源 |
| `PlatformSharedReaderCacheTests` | 改 ICacheService 后短缓存命中/失效/降级语义不回归 |
