# 条件表达式引擎（Qlx.BuildingBlocks.Expressions）开发与使用指南

> 版本：1.0.0 beta ｜ 位置：`src/Qlx.BuildingBlocks/Expressions/` ｜ 测试：`tests/Qlx.BuildingBlocks.Tests/Expressions/`
>
> 面向对象：审批中心、业务模板、预警规则等一切需要「条件判断能力」的上层模块。

## 1. 组件定位

条件表达式引擎是一个**独立、可复用、可扩展**的通用公共组件：

- **不与任何业务耦合**：引擎核心不含任何业务运算符/函数/字段，位于 BuildingBlocks 公共层（仅依赖 Qlx.Abstractions）；
- **无侵入引用**：上层模块经工厂或 DI 拿到 `IConditionExpressionEngine` 即用，无需感知引擎内部实现；
- **标准扩展点**：业务方在不修改引擎核心代码的前提下，注册自定义运算符、自定义函数、自定义字面量解析器、自定义值转换器。

## 2. 架构设计

### 2.1 五层结构

| 层 | 关键类型 | 职责 |
|---|---|---|
| 契约层 | `IConditionBinaryOperator` / `IConditionUnaryOperator` / `IConditionShortCircuitOperator` / `IConditionFunction` / `IConditionLiteralParser` / `IConditionValueCoercer` / `IVariableResolver` | 全部扩展点接口，稳定不变 |
| AST 层 | `ConditionNode`（abstract record）+ 7 个子 record（literal/variable/unary/binary/function/list/ternary） | 判别联合多态求值；`IConditionNodeVisitor` 提供横向扩展点（渲染/校验/翻译） |
| 内置能力层 | `BuiltInOperators` / `BuiltInFunctions` / `ConditionValueOps` / `BuiltInValueCoercer` | 内置运算符与函数，本质上是「随引擎出厂的第一批扩展」 |
| 解析层 | `ConditionLexer`（词法）+ `ConditionParser`（递归下降 + 优先级爬升） | 文本 → AST；运算符绑定全部经注册表，解析器零硬编码 |
| 装配层 | `ConditionEngineOptions` / `ConditionRegistry` / `ConditionExpressionEngine` / 工厂 / DI 扩展 / JSON 互转 | 组合期注册 → 一次性构建不可变快照 → 运行期零修改 |

### 2.2 核心稳定 + 扩展无副作用的关键机制

1. **不可变注册表快照**：`ConditionRegistry` 在引擎构造时由 `ConditionEngineOptions` 一次性构建（`FrozenDictionary`），此后运行期**零锁、零修改**。业务扩展只发生在组合期，不可能在运行期污染核心引擎。
2. **冲突保护（向后兼容）**：注册符号/函数名与既有注册（含内置）冲突时抛 `ConditionExpressionException`（Kind = Registry）；仅显式 `allowOverride: true` 才允许覆盖，且只影响当前引擎实例——`ConditionExpressionEngineFactory.Default` 永远不受任何业务扩展影响。
3. **多态分发**：AST 以 `abstract record + 子 record` 承载，求值与渲染均经多态/访问者分发，引擎核心无 switch 节点分支；新增节点形态不需要修改既有逻辑。
4. **工厂模式**：`ConditionExpressionEngineFactory.Create(...)` 每次产出独立引擎实例；不同业务域的扩展相互隔离。

## 3. 快速开始

### 3.1 引擎获取（三选一）

```csharp
// 方式一：默认引擎（仅内置能力，进程级共享）
IConditionExpressionEngine engine = ConditionExpressionEngineFactory.Default;

// 方式二：工厂 + 扩展回调
var engine = ConditionExpressionEngineFactory.Create(options =>
{
    options.RegisterFunction(new AddDaysFunction());
});

// 方式三：DI 注册（推荐宿主应用使用；单例，组合期固化扩展）
services.AddQlxConditionExpressions(options =>
{
    options.RegisterBinaryOperator(new PowerOperator());
});

// 方式四：扩展门面 + DI（可访问宿主服务完成组合期配置）
services.AddQlxConditionExpressions((options, serviceProvider) =>
{
    new PurchaseConditionExtension().Configure(options);
});
```

### 3.2 基本用法

```csharp
// 直接求值（每次解析 + 求值）
bool ok = engine.Evaluate("total_amount > 50000 && status == 'Draft'",
    new DictionaryVariableResolver(
    [
        new KeyValuePair<string, object?>("total_amount", 60000m),
        new KeyValuePair<string, object?>("status", "Draft")
    ]));

// 编译制品（解析一次、多次求值——推荐热路径缓存）
ConditionExpression compiled = engine.Parse("amount > 100 ? 'big' : 'small'");
object? value = engine.EvaluateValue(compiled, variables);
bool pass = engine.Evaluate(compiled, variables);          // 布尔收敛：非布尔结果抛异常
```

> `ConditionExpression` 不可变、线程安全，可作为缓存键值跨线程共享。

### 3.3 expr_json 互转（审批中心 condition-builder 对接）

```csharp
// AST → expr_json（含 $type 判别符；> / < / & 等字符按平台统一 JSON 选项转义为 \uXXXX，语义等价）
string exprJson = compiled.ToJson();

// expr_json → 表达式制品（变量清单按 AST 重建；运算符求值时经注册表延迟解析）
ConditionExpression restored = ConditionExpression.FromJson(exprJson);
bool result = engine.Evaluate(restored, variables);

// 可读文本（对应审批中心 expr_text 字段，最小括号规范化）
string readable = restored.ReadableText;   // 如：total_amount > 50000 && status == 'Draft'
```

## 4. 表达式语法

### 4.1 运算符与优先级（从低到高）

| 优先级 | 运算符 | 说明 |
|---|---|---|
| 1 | `\|\|`（别名 `OR`） | 逻辑或，短路 |
| 2 | `&&`（别名 `AND`） | 逻辑与，短路 |
| 3 | `==`/`=`、`!=`/`<>` | 相等 / 不等 |
| 4 | `>`、`>=`、`<`、`<=` | 关系比较 |
| 5 | `+`、`-` | 算术加减（`+` 对字符串为拼接） |
| 6 | `*`、`/`、`%` | 算术乘除模 |
| — | `in` / `not in` | 成员判断（右操作数必须为列表或集合变量） |
| — | `!`（别名 `NOT`）、`-`、`+` | 一元前缀 |
| — | `条件 ? 真值 : 假值` | 三元取值 |

- 括号 `()` 显式控制优先级；列表字面量 `['A', 'B']`；下标不需要。
- 同级结合性默认左结合；自定义二元运算符可声明右结合（见 §5.1）。
- 变量两种写法等价：裸标识符 `total_amount`、参数变量 `${total_amount}`（名称可含中文与点号）。
- 字面量：整数 → `long`，小数 → `decimal`，科学计数 → `double`；字符串 `'...'` / `"..."` 等价，支持 `\n \t \r \\ \' \"` 转义与单引号双写 `''`；关键字 `true` / `false` / `null` 不区分大小写。

### 4.2 内置函数（21 个，名称不区分大小写）

| 类别 | 函数 |
|---|---|
| 成员 | `Between(v, low, high)` 双端包含；`Contains(s, sub)`、`StartsWith(s, prefix)`、`EndsWith(s, suffix)`（Ordinal）；`IsNull(v)`、`IsNotNull(v)`；`Length(s)` |
| 数值 | `Abs(x)`、`Min(...)`、`Max(...)`、`Round(x, digits?)`、`Floor(x)`、`Ceiling(x)` |
| 文本 | `Upper(s)`、`Lower(s)`、`Trim(s)`、`Substring(s, start, length?)` |
| 控制 | `If(cond, whenTrue, whenFalse)`、`Coalesce(...)` |
| 时间 | `Now()`、`Today()` |

## 5. 扩展开发指南

**总原则**：扩展实现必须**无状态且线程安全**（引擎单例并发调用）；注册只发生在组合期（引擎创建之前）。

### 5.1 自定义二元运算符（`IConditionBinaryOperator`）

```csharp
/// <summary>幂运算（示例：右结合）。</summary>
public sealed record PowerOperator : IConditionBinaryOperator
{
    public string Symbol => "**";
    public IEnumerable<string> Aliases => [];
    public ConditionPrecedence Precedence => ConditionPrecedence.Multiplicative;
    public bool IsRightAssociative => true;   // 同级右结合：2 ** 3 ** 2 = 2 ** (3 ** 2)

    public object? Apply(object? left, object? right, ConditionEvaluationContext context)
        => (decimal)Math.Pow(
            Convert.ToDouble(left, CultureInfo.InvariantCulture),
            Convert.ToDouble(right, CultureInfo.InvariantCulture));
}

// 注册
options.RegisterBinaryOperator(new PowerOperator());
```

- 优先级只能取内置 `ConditionPrecedence` 六档（保证与内置运算符的相对顺序可预期）。
- 若实现 `IConditionShortCircuitOperator`（`bool TryShortCircuit(leftValue, context, out result)`），左操作数已可确定结果时右操作数不求值（`&&`/`||` 即此机制，未解析变量在右操作数也不会报错）。
- 符号匹配不区分大小写仅对纯字母符号生效（如 `AND`）；符号类运算符（`**`）区分大小写。词法层对符号做**最长匹配**，且数字后跟字母的词素（如 `0x1F`）会完整送达字面量解析器。

### 5.2 自定义一元（前缀）运算符（`IConditionUnaryOperator`）

```csharp
public sealed record SquareRootOperator : IConditionUnaryOperator
{
    public string Symbol => "√";
    public IEnumerable<string> Aliases => [];

    public object? Apply(object? operand, ConditionEvaluationContext context)
        => Math.Sqrt(Convert.ToDouble(operand, CultureInfo.InvariantCulture));
}

options.RegisterUnaryOperator(new SquareRootOperator());   // 表达式：√(4 + 5) == 3
```

### 5.3 自定义函数（`IConditionFunction`）

```csharp
public sealed record AddDaysFunction : IConditionFunction
{
    public string Name => "AddDays";
    public int MinArgumentCount => 2;
    public int MaxArgumentCount => 2;

    public object? Invoke(IReadOnlyList<object?> arguments, ConditionEvaluationContext context)
    {
        var date = arguments[0] switch { DateTime dt => dt, _ => throw new FormatException("需要日期") };
        return date.AddDays(Convert.ToDouble(arguments[1], CultureInfo.InvariantCulture));
    }
}

options.RegisterFunction(new AddDaysFunction());   // 表达式：AddDays(orderDate, 5) > now()
```

- 参数个数在**求值期**由引擎按 Min/Max 校验；函数执行抛出的异常被引擎包装为 `ConditionExpressionException`（Kind = Evaluate，保留 InnerException）。
- 需要 DI 服务时经 `context.Services` 访问（见 `ThresholdFunction` 示例测试）。

### 5.4 自定义字面量解析器（`IConditionLiteralParser`）

```csharp
/// <summary>十六进制数字面量：0x1F → 31。</summary>
public sealed class HexLiteralParser : IConditionLiteralParser
{
    public bool TryParse(ConditionLiteralTokenKind tokenKind, string text, out object? value)
    {
        if (tokenKind == ConditionLiteralTokenKind.Number
            && text.StartsWith("0x", StringComparison.OrdinalIgnoreCase)
            && long.TryParse(text[2..], NumberStyles.HexNumber, CultureInfo.InvariantCulture, out var hex))
        {
            value = hex;
            return true;
        }

        value = null;
        return false;
    }
}

options.RegisterLiteralParser(new HexLiteralParser());   // 表达式：0x1F == 31
```

- 自定义解析器**先于**内置数字解析执行，按注册顺序首个命中生效；返回 `false` 交给下一个解析器 / 内置兜底。
- 典型用途：十六进制/二进制数字面量、领域编码字符串预解析为强类型值。

### 5.5 自定义值转换器（`IConditionValueCoercer`）

```csharp
public sealed record Money(decimal Amount);

public sealed class MoneyCoercer : IConditionValueCoercer
{
    public bool TryConvert(object? value, ConditionValueKind target, out object? converted)
    {
        if (target == ConditionValueKind.Numeric && value is Money money)
        {
            converted = money.Amount;
            return true;
        }

        converted = null;
        return false;
    }
}

options.RegisterValueCoercer(new MoneyCoercer());   // 表达式：price > 100（price 为 Money 类型变量）
```

- 跨类别比较时引擎按「自定义转换器（注册逆序在前）→ 内置转换器」链式尝试，递归深度 ≤ 2 防循环转换；两侧同类别的比较不经过转换器。

### 5.6 扩展门面（`IConditionExpressionExtension`）与覆盖保护

```csharp
/// <summary>采购域条件扩展：一个门面注册全部领域能力。</summary>
public sealed class PurchaseConditionExtension : IConditionExpressionExtension
{
    public void Configure(ConditionEngineOptions options)
    {
        options.RegisterLiteralParser(new HexLiteralParser());
        options.RegisterBinaryOperator(new PowerOperator());
    }
}

// 工厂路径
var engine = ConditionExpressionEngineFactory.Create(new PurchaseConditionExtension());

// 覆盖内置（谨慎使用：仅影响本引擎实例，默认引擎不受影响）
var custom = ConditionExpressionEngineFactory.Create(options =>
    options.RegisterFunction(new MyIsNullFunction(), allowOverride: true));

// 重复注册同一符号（未声明 allowOverride）→ ConditionExpressionException（Kind = Registry）
```

### 5.7 运行时开关

| 选项 | 默认 | 说明 |
|---|---|---|
| `MaxExpressionLength` | 8192 | 表达式最大字符数（防超长输入） |
| `MaxDepth` | 64 | 最大嵌套深度（防深递归栈溢出） |
| `ThrowOnUnresolvedVariable` | true | 严格模式：未解析变量抛求值异常；false 时按 `null` 参与运算 |
| `Services` | null | 引擎级服务提供程序（DI 路径自动注入） |

## 6. 空值与类型语义

| 场景 | 规则 |
|---|---|
| 逻辑上下文 | `null` 视为 `false`；非布尔值抛求值异常（禁止隐式数值转布尔） |
| 相等 `==` | `null == null` 为真；`null` 与非 null 比较为假 |
| 关系 `> < >= <=` | 任一侧为 `null` 不可比较，结果为 `false` |
| 数值提升 | 整型 / `decimal` 参与 `decimal` 运算；含 `float` / `double` 提升为 `double`；`decimal` 溢出回退 `double` |
| 除零 | `/`、`%` 除数为零抛求值异常；整型除法提升为 `decimal`（避免 `5/2=2` 截断） |
| 日期族 | `DateTime` / `DateTimeOffset` / `DateOnly` / `TimeOnly` 跨形态比较统一归一 `DateTime`；日期相减返回 `TimeSpan` |
| 枚举 | 枚举可与同名字符串或底数数值比较 |
| 字符串拼接 | `+` 任一侧为字符串时按不变文化格式拼接 |

## 7. 错误处理

所有引擎级错误统一抛 `ConditionExpressionException`（继承 `BusinessException`），上层只需捕获此类型：

| Kind | 错误码 | 典型场景 |
|---|---|---|
| `Parse` | `CONDITION_EXPR_PARSE_ERROR` | 非法字符、括号不配对、函数未注册、超长 / 超深、非法 JSON 载荷 |
| `Evaluate` | `CONDITION_EXPR_EVAL_ERROR` | 变量未解析（严格模式）、除零、类型不兼容、函数执行异常 |
| `Registry` | `CONDITION_EXPR_REGISTRY_ERROR` | 扩展注册符号 / 函数名冲突且未声明 allowOverride |

异常携带 `Position`（错误字符偏移）与 `ExpressionSnippet`（片段），可直接用于前端定位。

## 8. 性能与质量保障

- **压测结论**（CI 宽松预算口径，实际量级约为预算 1/10，见 `ConditionExpressionPerformanceTests`）：
  - 简单条件解析 10 000 次 ≪ 5s；编译制品求值 100 000 次 ≪ 5s；
  - 300 子句大表达式解析 < 2s、求值 1 000 次 < 5s；30 层嵌套解析 100 次 < 2s。
- **边界防护**：长度上限、嵌套深度上限、除零、数字词素歧义（`123abc` 报解析错误）、`in` 右操作数类型校验、扩展异常包装（`ConditionExtensionGuard`：引擎异常与取消异常原样上抛，其余包装保留 InnerException）。
- **测试规模**：`tests/Qlx.BuildingBlocks.Tests/Expressions/` 共 5 个测试类（核心行为 / 扩展机制 / JSON 互转 / 可读文本 / 性能），与既有测试合计 323 个用例全量通过，构建零警告（TreatWarningsAsErrors）。

## 9. 线程安全与使用约定

1. `IConditionExpressionEngine`、`ConditionExpression`、`ConditionNode`、全部内置运算符/函数均为不可变对象，**线程安全、可缓存、可单例**；
2. 自定义扩展实现必须无状态（需要状态的经 `context.Services` 访问 DI 服务）；
3. 上层模块缓存 `ConditionExpression` 制品即可获得「解析一次、多次求值」的最佳吞吐；DI 场景直接构造函数注入 `IConditionExpressionEngine`；
4. 引擎实例创建后配置不可变更——运行期注册（反射改 Options 等）不在支持范围，这是「扩展无副作用」承诺的边界。
