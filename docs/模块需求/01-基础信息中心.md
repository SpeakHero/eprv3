s# 模块需求详设：01 基础信息中心

> 对应《项目需求.md》4.1 ｜ 版本 v1.0 ｜ 2026-10-20
> 上游约束：《saas-architecture-spec.md》（多租户、组织树数据权限、双层审计）、《项目需求.md》4.0 通用能力（单据编号、状态机、审批、导入导出、打印、日志）。本模块为全平台唯一基础数据底座，其余 10 个业务模块全部引用本模块数据，禁止私自维护副本。

## 2. 核心实体与字段明细

### 2.1 组织架构 org_node

| 字段 | 类型 | 必填 | 说明 / 校验 |
|------|------|------|------------|
| org_id | bigint PK | 是 | 主键，租户内唯一 |
| org_code | varchar(20) | 是 | 组织编码，全局唯一，规则：`ORG-类型码-流水`（如 ORG-GS-01）；启用后不可改 |
| org_name | varchar(64) | 是 | 组织名称，同级下不重名 |
| org_type | enum | 是 | GROUP 集团 / SUB 子公司 / DEPT 部门 / PROJ 项目 |
| parent_id | bigint | 否 | 上级节点；集团根节点为空 |
| leader_person_id | bigint | 否 | 负责人（引用人员主数据） |
| effect_date | date | 是 | 生效日期 |
| expiry_date | date | 否 | 失效日期；空=长期有效 |
| status | enum | 是 | ENABLED 启用 / DISABLED 停用 |
| sort_no | int | 是 | 同级排序号 |
| version | int | 是 | 版本号，每次结构调整+1，历史版本存入 org_node_history |

管控：停用前置校验——无在办业务单据、无在职人员、无关联在用仓库/项目，否则给出阻断清单。

### 2.2 岗位 position

| 字段 | 类型 | 必填 | 说明 / 校验 |
|------|------|------|------------|
| position_id | bigint PK | 是 | 主键 |
| position_code | varchar(20) | 是 | 岗位编码，全局唯一 |
| position_name | varchar(64) | 是 | 岗位名称 |
| org_id | bigint | 是 | 所属组织（仅可挂 DEPT/PROJ 级） |
| duty | text | 否 | 职责说明 |
| headcount_plan | int | 是 | 编制数，≥0 |
| headcount_actual | int | 是 | 在岗人数（由人员任职记录实时汇总，只读） |
| status | enum | 是 | ENABLED / DISABLED；停用前置：在岗人数=0 |

### 2.3 商品分类 item_category

| 字段 | 类型 | 必填 | 说明 / 校验 |
|------|------|------|------------|
| category_id | bigint PK | 是 | 主键 |
| category_code | varchar(20) | 是 | 分类编码，全局唯一，按层级规则生成（如 01-建材，0101-钢材，010101-螺纹钢） |
| category_name | varchar(64) | 是 | 分类名称 |
| parent_id | bigint | 否 | 上级分类 |
| level_no | int | 是 | 级次（1~4 级，级数上限参数可配） |
| status | enum | 是 | ENABLED / DISABLED；被商品引用后禁止删除，仅可停用 |
| unit_group_id | bigint | 否 | 默认计量单位组（新增商品时带出） |

### 2.4 计量单位 unit / 换算 unit_conversion

unit：unit_id、unit_code（唯一）、unit_name、unit_group_id、precision（小数位）、status。
unit_conversion：conv_id、unit_group_id、from_unit_id、to_unit_id、rate（换算率，>0，精度 8 位小数）、status。
管控：换算率变更写入变更日志（旧值/新值/操作人/时间），已被出入库单引用期间的历史数据不追溯重算。

### 2.5 供应商 supplier（主表）

| 字段 | 类型 | 必填 | 说明 / 校验 |
|------|------|------|------------|
| supplier_id | bigint PK | 是 | 主键 |
| supplier_code | varchar(20) | 是 | 供应商编码，全局唯一（SUP-流水） |
| supplier_name | varchar(128) | 是 | 全称，与营业执照一致 |
| uscc | varchar(18) | 是 | 统一社会信用代码，全局唯一，格式校验 |
| supplier_type | enum | 是 | 生产厂家 / 经销商 / 劳务分包商 / 服务商 / 其他 |
| contact / phone | varchar | 是 | 联系人、联系电话 |
| grade | enum | 是 | A / B / C / BLACKLIST 黑名单；默认 C，黑名单全局禁采 |
| status | enum | 是 | PENDING 待准入 / ACTIVE 合作中 / FROZEN 冻结 / CLOSED 终止 |
| created_by / created_at | - | 是 | 登记人与时间 |

子表：
- supplier_cert（资质证照）：cert_id、cert_type（营业执照/生产许可证/安全资质等）、cert_no、issue_org、effect_date、expiry_date、file_id（影像）、status。
- supplier_bank（银行账户）：bank_id、bank_name、account_name、account_no、is_default、status；账户新增/变更需审批留痕。
- supplier_invoice（开票信息）：invoice_id、title、tax_no、bank_info、addr_phone、invoice_type（专票/普票/数电票）。
- supplier_grade_log（评级历史）：log_id、old_grade、new_grade、reason、approved_by、created_at。

### 2.6 客户 customer（主表）

结构同供应商，差异字段：

| 字段 | 类型 | 必填 | 说明 / 校验 |
|------|------|------|------------|
| credit_grade | enum | 是 | A / B / C / D；下调自动触发在售订单复检 |
| credit_limit | decimal(18,2) | 是 | 信用额度，默认 0；调整走分级审批 |
| credit_used | decimal(18,2) | 是 | 已占用额度（在途应收实时汇总，只读） |
| payment_terms | varchar(256) | 否 | 默认回款条款（下单带出） |

子表：customer_bank（回款账户）、customer_invoice、customer_credit_log（额度/等级变更历史）。

### 2.7 人员主数据 person

| 字段 | 类型 | 必填 | 说明 / 校验 |
|------|------|------|------------|
| person_id | bigint PK | 是 | 主键 |
| person_code | varchar(20) | 是 | 工号，全局唯一（EMP-流水 / LAB-流水区分员工与劳务） |
| person_name | varchar(64) | 是 | 姓名 |
| person_type | enum | 是 | EMP 员工 / LAB 劳务人员 |
| id_type / id_no | enum+varchar(18) | 是 | 证件类型+证件号；身份证号全局唯一防重，AES 加密存储、页面脱敏（前 6 后 4） |
| mobile | varchar(11) | 是 | 手机号，格式校验 |
| emergency_contact / emergency_phone | varchar | 否 | 紧急联系人 |
| org_id / position_id | bigint | 员工必填 | 所属组织与岗位（劳务人员可为空，挂班组） |
| employ_status | enum | 是 | PROBATION 试用 / REGULAR 在职 / SUSPENDED 停职 / LEFT 离职 |
| entry_date / leave_date | date | 是/否 | 入职日期 / 离职日期 |
| bank_card_no | varchar(32) | 否 | 银行卡号，加密存储、脱敏展示 |
| is_deleted | bit | 是 | 逻辑删除标记 |

管控：敏感字段（证件号、银行卡、联系方式）按角色脱敏；本人/HR/授权管理员可见全量。

### 2.8 数据字典 dict_type / dict_item

dict_type：type_code（唯一）、type_name、owner_level（GROUP 集团级 / SUB 子公司级）、org_id（子公司级归属）、status。
dict_item：item_id、type_code、item_code（类型内唯一）、item_name、sort_no、status、is_system（系统内置项不可删）。
管控：集团级字典子公司只读；被引用字典项禁止物理删除，仅可停用。

### 2.9 编码规则 code_rule

| 字段 | 类型 | 必填 | 说明 / 校验 |
|------|------|------|------------|
| rule_id | bigint PK | 是 | 主键 |
| biz_type | varchar(32) | 是 | 业务对象（组织/商品/供应商/客户/人员/各单据），唯一 |
| prefix | varchar(16) | 是 | 编码前缀 |
| segments | json | 是 | 分段定义（固定码/年月/流水段长度），如 `CG-PO-{yyyyMM}-{seq:4}` |
| seq_current | bigint | 是 | 当前流水号（数据库原子自增，防并发重号） |
| status | enum | 是 | ENABLED / DISABLED |

管控：规则一经启用不可修改规则本身，仅可扩展流水区段；所有发号经统一发号服务，禁止模块自行拼号。

## 3. 业务规则与校验

| # | 规则 | 说明 |
|---|------|------|
| R1 | 唯一性 | 组织码、岗位码、分类码、供应商/客户统一社会信用代码、人员证件号、商品码全部租户内唯一，重复阻断并提示已存在记录 |
| R2 | 引用保护 | 被业务单据引用的基础数据禁止删除，仅可停用；停用后新单据不可引用，历史单据照常显示 |
| R3 | 供应商准入 | status=PENDING 的供应商不可被采购订单引用；BLACKLIST 全模块拦截并弹提示 |
| R4 | 资质到期 | 供应商资质到期前 N 天（参数，默认 30）推送预警；到期未更新自动置 FROZEN，解冻需重新准入审批 |
| R5 | 客户信用 | 信用额度校验公式：`credit_used + 本单金额 ≤ credit_limit`；超限冻结提交并提示走特批流程 |
| R6 | 架构版本 | 组织树每次变更（新增/停用/调级/合并）生成版本快照，支持按日期回看历史架构，历史单据按发生时架构口径展示 |
| R7 | 人员防重 | 同一证件号仅允许一条有效（非 LEFT 且未删除）记录；离职再入职走"再入职"流程复用原 person_id |
| R8 | 字典两级 | 子公司级字典仅本子公司可见可用；集团级字典全租户只读共享 |
| R9 | 编码发号 | 发号服务保证连续不重复、作废不回收；单据号规则遵循 `业务前缀+组织码+年月+流水`（4.0 通用约定） |
| R10 | 变更审批 | 供应商银行账户/开票信息、客户信用额度、商品分类停用等关键变更必须审批通过后生效，全程留痕 |

## 4. 审批流配置建议

| 单据 / 事件 | 触发条件 | 建议审批链 | 说明 |
|------------|---------|-----------|------|
| 组织架构调整 | 全部 | 集团人力资源负责人 → 集团总经理 | 涉及子公司层级调整需抄送子公司负责人 |
| 供应商准入 | 全部 | 采购负责人 → 子公司总经理 | 涉及黑名单解除需集团级终审 |
| 供应商银行/开票信息变更 | 全部 | 采购负责人 → 财务负责人 | 财务核验账户一致性 |
| 客户准入 | 全部 | 销售负责人 → 子公司总经理 | — |
| 客户信用额度调整 | 额度 ≤ 阈值A | 销售负责人 → 财务负责人 | 阈值参数化 |
| 客户信用额度调整 | 额度 > 阈值A | 销售负责人 → 财务负责人 → 集团分管副总 | — |
| 商品分类停用 | 被引用分类 | 基础数据管理员 → 集团运营负责人 | 需确认无在途业务 |
| 编制调整 / 超编入职 | 全部 | 子公司总经理 → 集团人力资源负责人 | 超编强制集团终审 |

## 5. 权限点清单

**菜单权限**：基础信息中心（一级）→ 组织架构 / 岗位 / 商品分类 / 计量单位 / 供应商 / 客户 / 人员主数据 / 数据字典 / 编码规则 / 变更日志（二级）。

**按钮权限**（示例，按页面）：新增、编辑、删除（未引用时）、停用/启用、导入、导出、提交审批、查看影像、查看敏感字段明文、评级调整、编码规则维护。

**数据权限**：随组织树继承——集团角色可见全部；子公司角色仅可见本公司及其下级节点数据；项目角色仅本项目。供应商/客户/商品分类/字典为租户级共享数据，全员只读引用、专岗维护。

**字段权限**：person.id_no、person.bank_card_no、person.mobile 为敏感字段，默认脱敏；明文查看需单独授权并记录查看日志。

## 6. 与其他模块联动

| 触发事件 | 目标模块 | 数据流 |
|---------|---------|-------|
| 供应商置黑名单 / 资质到期冻结 | 采购管理 | 实时拦截下单，推送预警至通知中心 |
| 客户信用等级下调 / 额度调整 | 销售管理 | 触发在售订单复检任务；新订单按新额度校验 |
| 组织停用 / 项目结项 | 全部业务模块 | 阻断以该组织为归属的新单据；在途单据给出迁移或完结指引 |
| 岗位编制变更 | 人员管理 | 更新超编校验基线 |
| 商品分类停用 | 商品管理 | 该分类下商品批量提示，禁止新增商品挂入 |
| 人员离职生效 | 登录体系（架构规格） | 自动停用其 tenant_member 账号与全部角色授权 |
| 编码规则停用 | 全部模块 | 对应业务对象暂停新建，提示管理员 |

## 7. 期初与历史数据处理

| 事项 | 处理方式 |
|------|---------|
| 期初范围 | 组织架构、岗位、商品分类与单位、供应商、客户、人员六类主数据，上线前通过统一导入模板批量导入 |
| 导入校验 | 编码唯一性、证件号格式、引用关系（岗位→组织、人员→岗位/组织）全部校验，错误行生成错误清单下载修正 |
| 期初审批 | 批量导入结果提交管理员复核确认后一次性生效，生成期初批次号备查 |
| 历史架构 | 上线前正在进行的组织调整，以最近一期生效架构为准录入，历史沿革不补录（仅备注说明） |
| 历史合作记录 | 供应商/客户的历史合作金额不强制补录，以系统上线日为合作记录起点；如需补录走单独导入通道并标注"补录" |
| 数据冻结 | 期初生效后，导入通道关闭，后续变更一律走线上审批流程 |
