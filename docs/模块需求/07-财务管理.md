## 2. 核心实体与字段明细

### 2.1 会计凭证 voucher / 分录 voucher_entry

voucher：voucher_id、voucher_no（`CW-PZ-{yyyyMM}-{seq}`，按月编号）、period（会计期间 yyyy-MM）、source_type（MANUAL 手工/AUTO 自动）、source_doc_no（自动凭证来源单据）、summary、total_debit/total_credit（借贷合计，强制相等）、status（待审核→已审核→已过账；红冲标记）、org_id（核算主体=公司）。
voucher_entry：entry_id、voucher_id、subject_code（会计科目）、aux_org/aux_person/aux_customer/aux_supplier/aux_project（辅助核算维度）、debit_amount、credit_amount、summary。
管控：已审核凭证禁止修改/删除，只能红冲；自动凭证按模板生成，人工不可编辑（错则红冲原凭证并修正模板）。

### 2.2 科目表 account_subject / 凭证模板 voucher_template

account_subject：subject_code（按会计准则编码）、subject_name、level、parent_code、direction（借/贷）、aux_required（辅助核算要求）、status、owner_level（集团统一科目，子公司只读引用）。
voucher_template：tpl_id、biz_type（入库单/出库单/报销单/收付款单等）、entry_rules（json：借贷科目+金额取数表达式）、status、version。

### 2.3 费用报销单 expense_claim

主表：claim_id、claim_no（`CW-BX-{orgCode}-{yyyyMM}-{seq}`）、person_id、org_id、expense_type（字典：差旅/招待/办公/车辆等）、total_amount、offset_loan_amount（冲抵借款金额）、pay_amount（实付=总额-冲抵）、project_id（可关联项目）、status。
明细 claim_item：item_id、expense_date、amount、invoice_flag（是否有票）、invoice_id（关联票据模块发票，查重 R3）、attachment_id。

### 2.4 个人借款单 loan_doc

loan_id、loan_no（`CW-JK-…`）、person_id、amount、purpose、expect_return_date、balance（未冲抵余额）、status。报销时可选冲抵，余额为 0 自动结清；超期未还预警。

### 2.5 付款申请单 payment_apply

| 字段 | 类型 | 必填 | 说明 / 校验 |
|------|------|------|------------|
| pay_id | bigint PK | 是 | 主键 |
| pay_no | varchar(32) | 是 | `CW-FK-{orgCode}-{yyyyMM}-{seq}` |
| pay_type | enum | 是 | PURCHASE 采购/EXPENSE 费用/PREPAY 预付/DEPOSIT 保证金/LABOR 劳务/RENT 租金 |
| biz_ref_no | varchar(32) | 条件必填 | 业务依据单号（对账单/报销单/合同等），R2 |
| payee_type / payee_id | enum+bigint | 是 | 收款方（供应商/客户/员工/劳务公司） |
| amount | decimal(18,2) | 是 | 付款金额；不得超业务依据可付余额 |
| bank_account_id | bigint | 是 | 付款账户；工资类强制专户 |
| plan_check_result | enum | 是 | 资金计划校验结果（计划内/超计划/无计划），R8 |
| status | enum | 是 | 通用状态机 + 已支付/已核销 |

支付回写 payment_record：record_id、pay_no、pay_date、bank_serial_no、actual_amount、operator_id。

### 2.6 到账登记 receipt_record / 应收应付 ar_ap

receipt_record：receipt_id、bank_account_id、amount、receive_date、payer_name、bank_serial_no、claim_status（未认领/部分认领/已认领）、claimed_amount。
ar_doc（应收）：ar_id、source_doc_no（销售出库/租金结算等）、customer_id、amount、received_amount、balance、due_date、aging_days（系统计算）、status。
ap_doc（应付）：结构对称（供应商维度），含 retention_amount（质保金挂账）与 retention_due_date。
核销 writeoff_doc：双向多对多核销记录（回款↔应收、付款↔应付）。

### 2.7 预算 budget / 预算占用 budget_occupy

budget：budget_id、year/month、org_id、expense_type/project_id、amount、version、status（编制中→已生效→已调整）。
budget_occupy：occupy_id、budget_id、source_doc_no、occupy_amount、actual_amount、status（占用中/已转实际/已释放）。

### 2.8 银行账户 bank_account / 流水 bank_statement / 资金计划 fund_plan

bank_account：account_id、account_no（唯一）、bank_name、account_type（基本/一般/工资专户/保证金户）、org_id、currency、status（开户申请中/正常/销户中/已销户）。
bank_statement：stmt_id、account_id、txn_date、amount、direction、counterparty、bank_serial_no（唯一防重）、match_status（未勾对/已勾对/差异）。
fund_plan：plan_id、month、org_id/project_id、inflow_plan、outflow_plan、actual_inflow、actual_outflow、gap_amount（系统计算）、status。

### 2.9 承兑汇票 bill_of_exchange

bill_id、bill_no（票面号码，唯一）、direction（RECV 应收/PAY 应付）、drawer（出票人）、accept_bank（承兑行）、amount、issue_date、due_date、status（在库/已背书/已贴现/已托收/已到期收款/逾期）、operation_log（背书/贴现/托收逐笔登记子表）。

## 3. 业务规则与校验

| # | 规则 | 说明 |
|---|------|------|
| R1 | 借贷平衡 | 凭证借贷合计强制相等，不等禁止保存 |
| R2 | 付款有据 | 付款申请必须关联已生效业务依据（对账单/报销单/合同/结算单）；无依据付款仅允许走特批通道并限期补录 |
| R3 | 发票查重 | 报销明细挂接发票时调用票据模块查重接口，已报销/已入账发票禁止二次使用 |
| R4 | 费用标准 | 报销金额超「职级×费用类型」标准时，强制填写超标说明并审批链升级一级 |
| R5 | 预算硬控 | 报销/采购申请提交时实时校验预算余额：余额内正常流转；超预算自动升级审批并标记「超预算」；预算占用在单据生效时转实际、驳回时释放 |
| R6 | 凭证时序 | 已审核凭证不可改；红冲生成全额负数凭证并关联原凭证；月末结账后该期间凭证锁定，调整走次月 |
| R7 | 账龄预警 | 应收账龄超 N 天（参数，默认 30/60/90/180 分级）自动预警；超 90 天生成专项催收任务 |
| R8 | 资金计划校验 | 付款申请提交时校验月度资金计划：无计划/超计划的强制升级审批；计划外大额付款（>阈值）需集团审批 |
| R9 | 银企勾对 | 银行流水与账面收支逐笔勾对，未勾对差异限期 N 天处理；工资专户流水单独台账，禁止与经营账户混用 |
| R10 | 承兑汇票管控 | 票据到期前 N 天（参数，默认 15）预警托收；背书转让需审批并联动应付核销；逾期未托收进异常清单 |
| R11 | 成本自动取数 | 项目/订单成本仅允许从采购入库、领用出库、劳务结算、报销单据自动归集，禁止手工平调；月末结转需财务负责人审批 |
| R12 | 专户专款 | 农民工工资专户资金仅可用于劳务工资发放；专户付款申请自动校验用途，其他用途阻断 |

| 单据 / 事件 | 触发条件 | 建议审批链 | 说明 |

## 5. 权限点清单

**菜单**：财务管理 → 凭证管理 / 费用报销 / 个人借款 / 付款申请 / 收款认领 / 应收应付 / 成本核算 / 预算管理 / 银行账户 / 银行对账 / 资金计划 / 承兑汇票 / 财务报表。

**按钮**：凭证录入/审核/过账/红冲、模板配置、报销发起、借款发起、付款发起/支付登记、收款认领/核销、预算编制/调整/生效、账户维护/开销户申请、流水导入/勾对、计划编制、汇票登记/背书/贴现/托收、报表导出、合并报表查看。

**数据权限**：会计/出纳按所属公司；财务负责人本公司全量；集团财务角色跨公司汇总与合并报表；员工仅本人报销/借款/工资条。薪酬相关凭证分录按 R11（人员模块）隔离。

**字段权限**：银行账号完整号码仅出纳与财务负责人可见；资金余额类指标按角色开放（资金日报对非财务管理层可只开放汇总值，参数可配）。

## 6. 与其他模块联动

| 触发事件 | 目标模块 | 数据流 |
|---------|---------|-------|
| 采购入库/退货生效 | 采购管理 | 生成应付暂估/红冲凭证（按模板） |

| 工资表/劳务工资表生效 | 人员管理 | 生成费用/成本凭证与付款任务；专户发放回写 |

## 7. 期初与历史数据处理

| 事项 | 处理方式 |
|------|---------|
| 科目期初余额 | 按上线月初科目余额表导入（含辅助核算维度），借贷平衡校验后锁定 |
| 往来期初 | 应收/应付按客户/供应商逐笔或汇总导入（挂「期初余额单」），与科目余额核对一致 |
| 库存期初核对 | 存货科目余额与商品管理期初库存金额核对一致（联动 05 模块期初过账） |
| 银行账户期初 | 各账户上线日余额导入并与银行对账单核对；专户单独核对 |
| 在途票据 | 在库承兑汇票逐张登记期初，到期日自动纳入预警 |
| 历史凭证/报表 | 历史凭证不迁移；上线前报表以原系统/手工台账为准归档，系统报表自上线月起输出 |
| 预算期初 | 上线当年预算按剩余月份拆分导入，已发生费用导入为「已执行」保证执行率连续 |
