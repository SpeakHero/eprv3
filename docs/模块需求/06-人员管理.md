# 模块需求详设：06 人员管理

> 对应《项目需求.md》4.6 ｜ 版本 v1.0 ｜ 2026-10-20
> 覆盖正式员工全生命周期与建筑劳务人员用工全过程。人员主数据本体在《01-基础信息中心.md》（person 实体），本模块承接其上的业务流程；账号与权限联动架构规格 6.x 登录体系；工资发放对接《07-财务管理.md》资金与专户；劳务票据对接《08-票据管理.md》；项目维度联动《10-项目管理.md》。

## 2. 核心实体与字段明细

### 2.1 人事异动单 hr_change

| 字段 | 类型 | 必填 | 说明 / 校验 |
|------|------|------|------------|
| change_id | bigint PK | 是 | 主键 |
| change_no | varchar(32) | 是 | `RY-YD-{orgCode}-{yyyyMM}-{seq}` |
| person_id | bigint | 是 | 异动人员（引用 person） |
| change_type | enum | 是 | ENTRY 入职/REGULAR 转正/TRANSFER 调岗/PROMOTE 晋升/DEMOTE 降职/LEAVE 离职 |
| from_org_id/from_position_id | bigint | 条件必填 | 原组织/岗位（入职除外） |
| to_org_id/to_position_id | bigint | 条件必填 | 新组织/岗位（离职除外） |
| effect_date | date | 是 | 生效日期 |
| handover_note | text | 离职必填 | 交接事项清单 |
| status | enum | 是 | 通用状态机；生效后自动更新 person 与任职记录 |

任职记录 person_post_log：log_id、person_id、org_id、position_id、start_date、end_date、change_no（来源异动单）。

### 2.2 排班 schedule / 考勤 attendance

schedule：sch_id、org_id/project_id、person_id、work_date、shift_code（班次字典：早/中/晚/休）、status。
attendance：att_id、person_id、att_date、check_in/check_out（打卡时间）、source（考勤机/移动端/手工补录）、abnormal_type（NONE/缺卡/迟到/早退）、import_batch_id。

### 2.3 请假/加班/出差申请 hr_leave_apply

apply_id、apply_no（`RY-QJ-…`/`RY-JB-…`/`RY-CC-…`）、person_id、apply_type、leave_type（年假/事假/病假等字典）、start_time、end_time、duration（小时/天）、reason、attachment、status。
额度表 leave_quota：person_id、leave_type、year、total_quota、used_quota、remain_quota。

### 2.4 月度考勤汇总 att_summary

sum_id、person_id、month、work_days、overtime_hours、leave_deduct、late_count、confirm_status（待确认/本人已确认/异议中）、confirm_at、locked（确认后锁定）。

### 2.5 薪资模板 salary_template / 工资表 payroll

salary_template：tpl_id、tpl_name、bind_scope（岗位/职级）、items（json：薪资项+计算方式+是否固定）、status。
payroll（主表）：payroll_id、payroll_no（`RY-GZ-{orgCode}-{yyyyMM}-{seq}`）、org_id、month、total_amount、status（草稿→待审批→审批中→已生效→已发放）。
payroll_item（明细）：id、payroll_id、person_id、base、performance、subsidy、deduction、social_insurance、tax、net_amount、att_ref（考勤汇总引用）。
管控：net_amount 由系统按模板公式计算，禁止手工改单项；调整需改模板或考勤后重算。

### 2.6 劳务用工需求单 labor_demand

| 字段 | 类型 | 必填 | 说明 / 校验 |
|------|------|------|------------|
| demand_id | bigint PK | 是 | 主键 |
| demand_no | varchar(32) | 是 | `RY-YG-{orgCode}-{yyyyMM}-{seq}` |
| project_id | bigint | 是 | 用工项目（占用项目预算-人工科目） |
| work_type | varchar(64) | 是 | 工种（字典） |
| headcount | int | 是 | 需求人数，>0 |
| period_start / period_end | date | 是 | 工期 |
| est_amount | decimal(18,2) | 是 | 预估劳务费 |
| status | enum | 是 | 通用状态机；未批准不得进场登记（R4） |

### 2.7 劳务实名制档案 labor_profile（扩展 person）

| 字段 | 类型 | 必填 | 说明 / 校验 |
|------|------|------|------------|
| profile_id | bigint PK | 是 | 主键 |
| person_id | bigint | 是 | 关联 person（person_type=LAB） |
| id_photo_file_id | bigint | 是 | 身份证影像（正反面） |
| face_photo_file_id | bigint | 是 | 人脸照片（闸机/人脸识别底图） |
| work_type | varchar(64) | 是 | 工种 |
| team_name | varchar(64) | 是 | 所属班组 |
| certs | json | 条件必填 | 资格证/特种作业证列表（按工种要求强制，R5） |
| contract_file_id | bigint | 是 | 劳动合同/用工协议影像 |
| register_status | enum | 是 | 已登记/已进场/已退场 |

进退场记录 site_record：record_id、person_id、project_id、type（IN 进场/OUT 退场）、record_date、demand_no（关联用工需求）、operator_id。

### 2.8 劳务工资表 labor_payroll / 专户发放 special_pay

labor_payroll：lp_id、lp_no（`RY-LWGZ-…`）、project_id、month、total_amount、att_ref（考勤归集引用）、status。
明细：person_id、att_days、day_rate（日工资标准）、gross、deduct、net。
special_pay：pay_id、lp_no、bank_account_id（专户账户）、pay_date、pay_amount、bank_serial_no（银行流水号）、voucher_file_id（发放凭证影像）、status。

### 2.9 资质证照 cert_profile

cert_id、owner_type（ORG 企业/PERSON 人员）、owner_id（org_id 或 person_id）、cert_type（字典：营业执照/安全生产许可证/建造师/特种作业操作证等）、cert_no、issue_org、effect_date、expiry_date、file_id、status（有效/临期/过期，系统按日期自动判定）。

## 3. 业务规则与校验

| # | 规则 | 说明 |
|---|------|------|
| R1 | 超编管控 | 入职/调入提交时校验目标岗位 `headcount_actual < headcount_plan`，超编强制走集团审批链 |
| R2 | 跨公司异动 | 调出公司负责人 → 调入公司负责人 → 集团 HR 三方审批 |
| R3 | 离职权限 | 离职审批生效当日自动停用系统账号与全部角色（联动架构规格 tenant_member 状态）；审批未通过前权限保留 |
| R4 | 未批不进 | 劳务用工需求未生效，该项目的进场登记功能对相关人员阻断 |
| R5 | 证件强制 | 进场登记校验：身份证影像、人脸照片、用工协议必齐；特种工种（电工/焊工/高处作业等字典配置）必须持有效特种作业证，缺一禁止进场 |
| R6 | 实名制合规 | 未实名登记（labor_profile 不完整）人员禁止进场；实名数据满足住建部建筑工人实名制管理要求，支持监管平台报送格式导出 |
| R7 | 考勤闭环 | 月度考勤汇总经本人线上确认后锁定；异议期 N 天（参数，默认 3），异议由 HR 复核处理 |
| R8 | 算薪一致性 | 劳务工资表必须基于已锁定考勤归集核算；用工登记、考勤、工资表三方人数/天数一致方可提交发放审批 |
| R9 | 专户专款 | 农民工工资仅可从工资专户发放；发放金额 ≤ 专户可用余额；发放流水与凭证影像强制归档（监管必查） |
| R10 | 证照预警 | 证照到期前按 30/15/7 天三级自动预警至本人、直接主管、部门负责人；过期证照人员禁止排班进场，企业证照过期触发合规预警 |
| R11 | 薪酬隔离 | 薪酬数据按角色严格隔离：HR 与财务按公司范围可见，本人仅可见本人工资条，其余角色不可见任何薪酬字段 |
| R12 | 发放联动 | 工资表审批生效后推送财务生成付款任务；发放完成回写 payroll.status=已发放 |

## 4. 审批流配置建议

| 单据 / 事件 | 触发条件 | 建议审批链 | 说明 |
|------------|---------|-----------|------|
| 入职/转正 | 编制内 | 部门负责人 → HR 负责人 | — |
| 入职/调入 | 超编 | 部门负责人 → HR 负责人 → 集团总经理 | R1 |
| 调岗/晋升/降职 | 公司内 | 调出部门负责人 → 调入部门负责人 → HR 负责人 | — |
| 跨公司异动 | 全部 | 调出方负责人 → 调入方负责人 → 集团 HR 负责人 | R2 |
| 离职 | 全部 | 部门负责人 → HR 负责人 | 关键岗位加签子公司总经理 |
| 请假 | ≤3 天 | 直接主管 | >3 天加部门负责人；>7 天加 HR |
| 加班/出差 | 全部 | 直接主管 → 部门负责人 | — |
| 员工工资表 | 全部 | HR 负责人 → 财务负责人 → 子公司总经理 | 按公司分级 |
| 劳务用工需求 | 全部 | 项目经理 → 子公司分管副总 | 超项目预算升级集团 |
| 劳务工资表 | 全部 | 项目经理 → 劳务管理负责人 → 财务负责人 → 子公司总经理 | R8 校验前置 |
| 证照停用/复用 | 全部 | HR 负责人 | — |

## 5. 权限点清单

**菜单**：人员管理 → 岗位编制 / 人事异动 / 排班考勤 / 请假加班出差 / 薪酬管理 / 劳务用工 / 实名制管理 / 进退场登记 / 劳务工资 / 资质证照 / 专户台账。

**按钮**：异动发起、编制调整、排班维护、考勤导入/补录、申请发起、考勤汇总/锁定、模板维护、算薪/重算、工资表提交、工资条查看、用工需求发起、实名登记、进场/退场登记、证照维护、专户发放登记、监管报表导出。

**数据权限**：集团 HR 全集团；子公司 HR 仅本公司；项目经理仅本项目劳务人员（含其考勤与工资，不含正式员工薪酬）；员工本人仅本人数据（考勤、工资条、证照）。

**字段权限**：证件号、银行卡号脱敏（继承基础中心规则）；薪酬字段仅 HR/财务/本人可见；劳务工资对项目外人员不可见。

## 6. 与其他模块联动

| 触发事件 | 目标模块 | 数据流 |
|---------|---------|-------|
| 离职/退场生效 | 登录体系（架构规格） | 停用 tenant_member 账号与角色；劳务工号同步停用 |
| 用工需求/工资关联项目 | 项目管理 | 占用项目人工预算；劳务结算归集项目人工成本 |
| 工资表/劳务工资表生效 | 财务管理 | 生成付款任务与费用/成本凭证；专户发放回写资金台账 |
| 劳务结算关联 | 票据管理 | 劳务发票/完税凭证核验，票不齐挂起付款（R8 与票据模块双向校验） |
| 证照过期 | 通知中心 | 三级预警推送；过期人员排班/进场阻断同步至排班与实名制页面 |
| 编制调整 | 基础信息中心 | position.headcount_plan 更新留痕 |
| 异动生效 | 基础信息中心 | person 组织/岗位/状态自动更新，任职记录追加 |

## 7. 期初与历史数据处理

| 事项 | 处理方式 |
|------|---------|
| 在职人员期初 | 正式员工与在场劳务人员批量导入（继承基础中心导入通道），任职记录以当前岗位为期初起点 |
| 期初考勤/假期额度 | 上线当年已用年假等额度按期初表导入，保证额度校验连续 |
| 历史薪酬 | 历史工资数据不迁移；工资条查询自上线后首个算薪月开始 |
| 在场劳务人员 | 已进场人员补录实名制档案与人脸底图；证件不齐者限期补齐，逾期禁止进场 |
| 证照档案 | 企业与关键岗位人员证照批量导入并核验有效期，临期/过期证照导入即触发预警清单 |
| 专户期初 | 工资专户账户余额与财务期初核对一致；历史发放凭证按监管要求保留原件，电子影像可批量挂接 |
