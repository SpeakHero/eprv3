# 支撑功能详设：02 信息中心

> 对应《项目需求.md》5.1 通知中心 ｜ 版本 v1.0 ｜ 2026-10-20
> 全局（门户→租户）与租户内统一消息枢纽。实时推送采用 **SSE 单向通讯，禁止前端轮询**；邮件为已实现通道；**短信预留统一接口，不实现具体供应商**；消息模板可定制；支持用户间收发与系统级 API 调用收发。审批类消息触发源为《01-审批中心.md》。

## 2. 核心实体与字段明细

### 2.1 消息 message

| 字段 | 类型 | 必填 | 说明 / 校验 |
|------|------|------|------------|
| msg_id | bigint PK | 是 | 主键 |
| scope | enum | 是 | GLOBAL 全局（门户下发）/ TENANT 租户内 |
| source_type | enum | 是 | SYSTEM 系统事件 / API 系统调用 / USER 用户私信 / ANNOUNCEMENT 公告 |
| msg_type | varchar(32) | 是 | 消息类型（字典）：TODO 待办 / RESULT 结果 / URGE 催办 / ALERT 预警 / TASK 任务 / NOTICE 系统通知 / ANN 公告 / PM 私信 |
| priority | enum | 是 | NORMAL / IMPORTANT / URGENT（紧急弹窗+角标强提醒） |
| title / content | varchar/text | 是 | 渲染后的标题与内容（服务端转义，R11） |
| template_id | bigint | 系统消息必填 | 来源模板（私信/公告可为空） |
| biz_ref | json | 否 | 跳转上下文 {biz_type, biz_id, biz_no} |
| sender_id | bigint | 否 | 发送人（系统消息为空） |
| channel_mask | int | 是 | 渠道位掩码：bit0 站内 / bit1 邮件 / bit2 短信（预留） |
| created_at / expire_at | datetime | 是 | 创建时间 / 归档时点 |

接收表 message_inbox：inbox_id、msg_id、receiver_id、read_status、read_at、deleted（个人删除不影响他人）。

> **全局项（GLOBAL）不落本表**：平台公告/消息只存共享库 `glb_msg_messages` **一份**；租户库仅 `msg_global_state`（`GlobalId` + 用户已读/回执），收件箱由应用层「全局项 ∪ 本租户自建项」合并，去重键 `GlobalId`，禁止跨库 JOIN。详见《多租户数据库模式补充设计.md》§5.11。

### 2.2 消息模板 message_template

tpl_id、tpl_code（唯一，系统调用引用键）、tpl_name、msg_type、channel（SITE 站内 / EMAIL 邮件 / SMS 短信，按渠道各一份）、subject（邮件标题模板）、content_tpl（正文模板，支持 `${var}` 占位符）、var_schema（json：变量名/类型/必填/示例值）、status、version。
管控：渲染引擎对变量值做 HTML 转义防 XSS；模板修改产生新版本，调用方按 tpl_code 始终取最新启用版本。

### 2.3 订阅偏好 subscription

sub_id、user_id、msg_type、channel、enabled。审批待办/催办等关键类型默认 enabled 且锁定（不可关闭，R-Sub）。

### 2.4 发送记录 send_log

log_id、msg_id、channel、receiver（用户/邮箱/手机号）、status（PENDING/SUCCESS/FAILED）、fail_reason、retry_count、sent_at。失败按指数退避重试，上限 N 次（参数），超限告警至管理员。

### 2.5 SSE 连接 sse_connection

conn_id、user_id、tenant_id、conn_token（一次性握手令牌，短时有效）、last_event_id、connected_at、client_info。服务端维护 user→连接集合，支持同一用户多标签多连接。

### 2.6 系统调用凭证 api_credential / 调用日志 api_call_log

api_credential：cred_id、app_key（唯一）、app_secret（哈希存储）、owner（调用方：门户/业务模块/外部系统）、scope（可发消息类型集合 + GLOBAL/TENANT 范围）、rate_limit（次/分）、status。
api_call_log：log_id、app_key、tpl_code、receiver_count、status、fail_reason、created_at。

## 3. 实时推送设计（SSE 规范）

| 项 | 规范 |
|---|------|
| 连接 | `GET /api/message/stream`，Header 携带租户 Token + conn_token（由页面加载时向鉴权接口换取）完成租户与用户归属校验；响应 `text/event-stream` |
| 事件 | `event: message.created`（新消息摘要）、`message.read.sync`（他端已读同步未读数）、`announcement`（公告置顶变更）；data 为 JSON 摘要（msg_id、msg_type、priority、title、biz_ref） |
| 可靠性 | 每条事件带租户内单调递增 event id；断线重连携带 `Last-Event-ID`，服务端补发遗漏事件；心跳 30s 发送 comment 行保活 |
| 多标签页 | 与页面架构（浏览器原生多标签）一致：优先 SharedWorker 维持单连接 + BroadcastChannel 分发至各标签；环境不支持时退化为每标签独立连接，服务端按用户聚合限流（连接数上限参数） |
| 禁止轮询 | 前端不得以定时器/轮询拉取消息列表或未读数；未读计数=首屏快照+SSE 增量维护 |
| 降级策略 | SSE 断开仅提示「实时推送已断开，重连中」并自动重连；恢复后按 Last-Event-ID 补齐；**不启用轮询降级** |

## 4. 业务规则与渠道策略

| # | 规则 | 说明 |
|---|------|------|
| R1 | 紧急强提醒 | priority=URGENT 消息前端弹窗+角标强提醒，需用户主动关闭 |
| R2 | 默认渠道矩阵 | 按 msg_type 配置（可改）：待办/催办=站内+邮件；预警=站内（可配加邮件）；公告/私信/结果=站内；矩阵含短信位但当前不发送 |
| R3 | 事件去重 | 同一 biz_ref+msg_type+receiver 在去重窗口（参数，默认 5 分钟）内仅生成一条 |
| R4 | 待办闭环 | 待办类消息对应业务处理完成后自动置已读并从未读计数消除（审批中心回调触发） |
| R5 | 模板强制 | 系统类消息必须经模板渲染（tpl_code+变量），禁止拼接裸文本；公告/私信除外 |
| R6 | 邮件通道 | 租户级 SMTP 配置（系统管理参数组）；异步队列发送，失败重试与超限告警 |
| R7 | 短信预留 | 统一接口 `ISmsSender.send(phone, tplCode, vars)` 已定义并纳入渠道矩阵、模板与日志体系；无默认供应商实现，配置显式标记「未接入」；矩阵勾选短信时调用降级为站内发送并记录「短信未接入」日志 |
| R8 | 用户私信 | 仅租户内用户互发；附件可选（安全扫描开关）；私信仅记录消息日志，不进入业务审计留痕 |
| R9 | 系统调用管控 | 凭证鉴权 + scope 校验 + 限流；仅允许按 tpl_code 发模板消息；门户下发全局消息使用 scope=GLOBAL 的门户侧凭证，**只写共享库 `glb_msg_messages` 一份**，不逐租户复制 |
| R10 | 消息留存 | 默认保留 12 个月（参数），到期自动归档，归档消息只读可查、不再推送 |
| R11 | 内容安全 | 消息内容服务端渲染与存储双重转义，前端仅白名单标签渲染，防 XSS |
| R12 | 订阅锁定 | 审批待办、催办、系统公告为强制订阅，用户不可关闭；其余类型可自助开关渠道 |
| R13 | 全局消息生效 | GLOBAL 消息存共享库一份，全租户用户**只读优先读取**（`Published` + `Scope/TargetTenantIds` 过滤）后与本地收件箱合并；租户库只存已读状态，新用户/新租户在有效期内立即可见，无需补发副本；`ForceAccept=1`，租户不可拒收/删除 |

## 5. 与审批中心联动规则

| 审批中心事件 | 消息动作 |
|-------------|---------|
| 节点任务创建 | message(TODO) → 任务人（含委托/加签，注明来源） |
| 实例终态（通过/驳回/终止） | message(RESULT) → 发起人；驳回含驳回意见摘要 |
| 超时催办 / 手动催办 | message(URGE) → 当前处理人，priority=URGENT（手动催办可选） |
| 委托生效/撤销 | message(NOTICE) → 代理人与委托人 |
| 连续催办上报 | message(URGE) → 上级审批人，priority=URGENT |

审批中心仅调用信息中心系统接口，不直接触达任何渠道。

## 6. 权限点清单

**菜单**：消息中心（全员）→ 消息 / 私信 / 订阅偏好；消息管理（管理员）→ 公告 / 模板 / 渠道配置 / 系统调用 / 发送记录 / 归档查询。

**按钮**：已读/全部已读/删除（个人收件范围）/跳转/回复；公告发布/置顶/撤下；模板编辑/预览/启停；凭证签发/吊销/限流调整；失败重发。

**数据权限**：用户仅本人收件箱与私信；发送记录按公司范围（管理员）；全局公告仅门户角色可发布；调用日志仅系统管理员。

**字段权限**：app_secret 仅签发时可见一次，此后不可查询（哈希存储）；接收人手机号/邮箱在非必要页面脱敏。

## 7. 与其他模块联动

| 触发事件 | 目标模块 | 数据流 |
|---------|---------|-------|
| 业务预警（库存/回款逾期/证照到期/账龄/匹配异常/超支） | 各业务模块 → 本模块 | 经系统调用接口按 tpl_code 发送 ALERT 消息 |

| SSE 握手鉴权 | 登录体系（架构规格 6.x） | 复用租户 Token，握手令牌一次性 |
| 发送/调用日志 | 日志体系（D13） | 租户内日志只落本租户库 `log_*`；平台发布动作只写门户库 `plog_audit`，租户 ack 回传 `plog_push_receipt`；两侧互不复制 |
| 预警规则条件 | 审批中心（condition-builder） | 预警触发条件复用条件表达式组件（biz_scope=ALERT_RULE） |

## 9. 落地偏差（2D，2026-10-23）

2D 信息中心批次编码完成后的实现与本文档设计的差异记录（表结构以迁移为准）：

| # | 偏差项 | 说明 |
|---|--------|------|
| 1 | 表命名 | 共享库全局消息表实际命名为 `glb_messages`（非 `glb_msg_messages`），遵循共享库 `glb_` 统一前缀；租户侧 6 张表 `msg_messages / msg_message_inboxes / msg_message_templates / msg_message_subscriptions / msg_message_send_logs / msg_message_global_states` |
| 2 | 渠道分发管线 | 邮件/短信/推送补发刻意不走 job_executions 管线（`IMessageDispatchEnqueuer` 直连 Hangfire）：避免 JobExecutionRunner 终态通知递归产生新消息；重试与降级由 MessageDeliveryExecutor 负责（重试超限降级站内 + DegradedToInApp 标记位） |
| 3 | 推送回执 | §7「租户 ack 回传 `plog_push_receipt`」暂缓：推送渠道（Web Push/短信）尚未接入、无回执来源，门户库表未建；推迟到渠道接入批次 |
| 4 | 人工重试 | `POST /api/support/messages/sent/{id}/retry` 经 `forceRetry=true` 通道入队，绕过自动重试上限强制尝试一轮（已送达渠道仍跳过）；发送记录查询 `GET .../send-logs` 仅发送方可查看 |
| 5 | 全局任务/公告 | `glb_tasks` 全局任务中心（§2.x）延后至任务域批次；本批次仅交付 `glb_messages` 全局消息 |
| 6 | 共享库读取缓存 | `IPlatformSharedReader` 用进程内 IMemoryCache 短缓存（`InboxCacheSeconds` 默认 30s，参数化）；多实例部署时各节点独立过期，可接受（正文变更频率低） |
| 7 | SSE 续传边界 | `Last-Event-ID` 超出环形缓冲窗口（`BufferCapacity` 默认 1000）或大于已分配最大 Id 时判为不可信（IsInRange=false），端点按全新连接处理、不补发历史（与 §3「回 400」设计不同）；客户端应走收件箱 API 全量刷新 |
| 8 | 收件箱合并分页 | 本地项与全局项内存归并排序（本地取 pageIndex×pageSize 窗口 + 全局项数量上限参数兜底），非数据库层 UNION；全局项量级（<100）下可接受 |
| 9 | PlatformSharedDbContext 迁移 | 继承 TenantDbContext 复用 snake_case/前缀装配（覆写前缀 glb_），位于 Qlx.BuildingBlocks；迁移经独立设计时工厂生成（只生成未应用） |
| 10 | 实体主键生成 | ~~msg_ 实体迁移快照为 ValueGeneratedOnAdd（雪花拦截器未挂入 SupportTenantDbContext 配置链路，与 Entity 注释不符）；SQL Server 生产环境依赖迁移默认自增，待 ID 体系批次统一接管~~ **已由 ID 体系批次解决**：雪花 ID 改 EF 值生成器（`SnowflakeIdValueGenerator` + `SnowflakeKeyConvention.Apply(modelBuilder, this)`，模型构建期捕获根容器引用、首次 NextId 才惰性解析生成器，规避 workerId 租约初始化早于迁移的时序冲突）；SupportTenantDbContext/PortalDbContext/TenantLogDbContext 三处接入，重建单迁移 `AddSupportTenantSchema` 快照全部 ValueGeneratedOnAdd |
| 11 | 模板种子触发点 | 8 类消息模板种子（SupportSeedService）随租户开通管线调用，本批次租户开通接线待门户侧批次完成；订阅记录按用户首次访问时服务内自动补齐（8 类，TODO/URGE 锁定） |
| 12 | 短信/推送渠道 | ISmsSender 保持 NotConfigured 桩（R7）；Web Push 未实现；矩阵勾选短信时按降级标记 DegradedToInApp 落站内 |
