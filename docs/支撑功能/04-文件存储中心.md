# 支撑功能详设：04 文件存储中心

> 对应《项目需求.md》五章支撑功能（系统管理能力扩展）｜ 版本 v1.0 ｜ 2026-10-20
> 平台级公共能力：统一承载全平台文件的上传、存储、下载与权限管控，**禁止业务模块自行存储文件**。权限模型参考 **Windows ACL**（安全描述符 + ACE + 继承机制）；业务模块附件按规则**自动归类**；支持**跨业务模块调用**（统一 file_id 引用 + 实时权限校验）；《03-后台任务中心.md》的结果文件纳入**临时存储区**（TTL 自动清理）。存储后端抽象统一接口（本地/MinIO/OSS 可插拔）。

## 2. 核心实体与字段明细

### 2.1 存储对象 storage_object（目录与文件统一树）

| 字段 | 类型 | 必填 | 说明 / 校验 |
|------|------|------|------------|
| object_id | bigint PK | 是 | 主键（对外引用统一为 file_id，目录亦可被引用授权） |
| parent_id | bigint | 否 | 父目录；根为业务域 bucket |
| object_type | enum | 是 | FOLDER 目录 / FILE 文件 |
| name | varchar(256) | 是 | 名称，同级唯一；文件保留原始文件名 |
| biz_domain | varchar(32) | 是 | 业务域（purchase/sale/hr/finance/invoice/temp/system…），归类依据 |
| path | varchar(1024) | 是 | 物化路径（/purchase/po/2026/10/），加速树查询 |
| hash | char(64) | 文件必填 | 内容 SHA-256，秒传去重依据 |
| size / mime | bigint/varchar | 文件必填 | 字节数 / MIME 类型（白名单校验） |
| current_version | int | 文件必填 | 当前版本号 |
| owner_id | bigint | 是 | 所有者（上传人/创建人），隐含完全控制 |
| inherit_acl | bit | 是 | 是否继承父级 ACE（断继承=false，留痕） |
| status | enum | 是 | NORMAL / RECYCLED 回收站 / PURGED |

### 2.2 文件版本 file_version

version_id、object_id、ver_no（自增）、hash、size、storage_path（物理存储键）、created_by/at。
管控：历史版本只读；回滚=生成新版本指向旧内容，不物理覆盖。

### 2.3 ACL 访问控制项 acl_entry（参考 Windows ACE）

| 字段 | 类型 | 必填 | 说明 / 校验 |
|------|------|------|------------|
| ace_id | bigint PK | 是 | 主键 |
| object_id | bigint | 是 | 作用对象（文件或目录） |
| subject_type | enum | 是 | USER 用户 / ROLE 角色 / ORG 组织（参考 Windows 的用户/组主体） |
| subject_id | bigint | 是 | 主体 ID |
| perm_mask | int | 是 | 权限位掩码：bit0 读取（下载/预览）/ bit1 写入（上传新版本/重命名）/ bit2 删除 / bit3 管理（改 ACL）/ bit4 分享（生成外链） |
| ace_type | enum | 是 | ALLOW / DENY（**拒绝优先**，同 Windows） |
| inherit_src | bigint | 否 | 继承来源对象（本对象显式设置为空）；继承链断点由 inherit_acl 控制 |
| propagate | bit | 是 | 是否向下传播（作用于子对象，类似 Windows「应用于子文件夹及文件」） |

### 2.4 ACL 模板 acl_template / 归类规则 classify_rule

acl_template：tpl_id、tpl_name、biz_domain、entries（json：subject_type+subject_ref+perm_mask 集合）、status。
classify_rule：rule_id、biz_module（模块编码）、doc_type（单据类型，可空=模块默认）、target_path（目标目录，支持 {yyyy}/{MM} 变量）、acl_tpl_id、priority、status。

### 2.5 临时文件 temp_file（后台任务结果）

temp_id、object_id（关联存储对象）、exec_id（后台任务执行实例）、owner_id（任务发起人）、expire_at（到期时点，默认 7 天参数）、status。由《03-后台任务中心.md》结果落地时自动登记。

### 2.6 分享外链 share_link

link_id、object_id、token（一次性签发）、perm（仅读取）、expire_at、password（可选）、created_by、access_count。外链访问免登录但全量留痕。

### 2.7 文件操作日志 file_op_log

log_id、object_id、action（UPLOAD/DOWNLOAD/PREVIEW/ACL_CHANGE/DELETE/RESTORE/SHARE/RENAME/MOVE）、operator_id、ip、detail、created_at。只增不改，进入双层审计。

## 3. 权限判定模型（参考 Windows 有效权限计算）

| 项 | 规则 |
|---|------|
| 隐含主体 | 所有者（owner_id）隐含完全控制；租户系统管理员隐含完全控制（操作仍留痕） |
| 继承 | 对象继承父级链全部 propagate=true 的 ACE；inherit_acl=false 阻断继承，仅保留显式 ACE（操作需「管理」权限并留痕） |
| 判定顺序 | ① DENY 优先：任一命中 DENY 即拒绝；② 累加 ALLOW：用户本人+其角色+其组织链的 ALLOW 权限位取并集；③ 无任何 ALLOW 命中=拒绝（默认拒绝，同 Windows） |
| 有效权限查看 | ACL 编辑页提供「有效权限」模拟：输入用户实时计算其权限位与来源 ACE（参考 Windows「有效访问」选项卡） |
| 授权粒度 | 目录授权+继承传播实现批量管控；单文件可断继承做特例（如薪酬附件仅 HR 角色可读） |

## 4. 业务规则与校验

| # | 规则 | 说明 |
|---|------|------|
| R1 | 统一入口 | 全平台文件仅经本中心存取（SDK/REST 统一接口）；业务模块库表仅存 file_id 引用，禁止存物理路径 |
| R2 | 自动归类 | 业务上传携带 biz_module+doc_type → 按 classify_rule 落目录（路径变量按当月展开）并套默认 ACL 模板；无规则命中进 /unclassified 并告警管理员补规则 |
| R3 | 跨模块调用 | 调用方凭 file_id 访问，实时按第 3 节判定权限；无权限返回 403 并留痕尝试记录；禁止模块间约定绕过授权 |
| R4 | 临时区 TTL | 后台任务结果文件到 expire_at 自动转 RECYCLED 并清理物理文件；临时区默认 ACL=仅发起人与管理员可读 |
| R5 | 类型与大小 | MIME/扩展名白名单与单文件大小上限按业务域参数配置（影像类默认 20MB，源文件类默认 50MB）；超限阻断 |
| R6 | 内容安全 | 上传异步病毒/恶意内容扫描，命中隔离区并告警；可执行文件类型全平台禁传 |
| R7 | 秒传去重 | 同 hash 文件秒传：仅登记新版本引用，不重复占用物理存储（引用计数管理物理文件生命周期） |
| R8 | 版本管控 | 同名上传生成新版本；历史版本仅「读取」权限可取；回滚留痕 |
| R9 | 回收站 | 删除=软删进回收站（保留期参数，默认 30 天），期间可还原；到期或手动 PURGE 才物理删除；物理删除需「删除」权限+留痕 |
| R10 | 数电票源文件 | XML/OFD 源文件（票据模块）归类目录 ACL 模板默认禁止删除与覆盖，满足电子会计凭证存档合规 |
| R11 | 配额管控 | 按业务域/租户配额（参数）；超 90% 预警，超 100% 阻断新上传（临时区除外但加速清理） |
| R12 | 访问留痕 | 下载/预览/权限变更/外链访问全部记录 file_op_log；敏感目录（薪酬/证件）访问额外告警审计角色 |

## 5. 权限点清单

**菜单**：文件中心（管理员）→ 文件管理器 / 归类规则 / ACL 模板 / 临时文件区 / 用量看板 / 文件审计 / 回收站。

**按钮**（叠加 ACL 判定）：上传、下载、预览、重命名、移动、删除、还原、ACL 编辑、外链分享、规则配置、模板维护、审计导出。

**数据权限**：以 ACL 判定为准（第 3 节模型），不再另设数据范围；菜单入口与按钮权限先行拦截，ACL 做最终裁定。

**字段权限**：storage_path 物理路径对任何前端角色不可见；hash 仅系统管理员可见。

## 6. 与其他模块联动

| 触发事件 | 目标模块 | 数据流 |
|---------|---------|-------|
| 附件上传/引用 | 全部业务模块 | 合同影像、证照、票据影像与源文件、签收影像、人脸底图等统一 file_id 引用，按 R2 自动归类 |
| 结果文件落地/清理 | 后台任务中心 | 执行完成写临时区（关联 exec_id）；消息 biz_ref 附下载入口（经 ACL 校验，发起人与管理员可取） |
| 完成通知携带下载 | 信息中心 | 消息中下载链接带短期签名令牌，点击时实时权限判定 |
| 打印/报表导出 | 各模块导出功能 | 导出文件走临时区，TTL 同 R4 |
| 审计归档 | 审计体系（架构规格） | file_op_log 入租户内审计；ACL 变更与外链访问为重点审计项 |
| 离职人员文件 | 人员管理 | 离职触发其 owner 文件移交规则（默认转交部门负责人，参数可配） |
| 存储后端切换 | 系统管理 | 存储提供方参数组（本地/MinIO/OSS），迁移工具后台任务执行 |

## 7. 期初与历史数据处理

| 事项 | 处理方式 |
|------|---------|
| 目录骨架初始化 | 按 11 个业务模块+支撑功能预建业务域与标准目录树，导入默认归类规则与 ACL 模板 |
| 存量文件迁移 | 期初需挂接的历史影像（证照、合同、专户凭证等）经批量迁移工具（后台任务）导入，按归类规则落位并生成 file_id 对照表回写业务数据 |
| 迁移校验 | 迁移完成输出「数量/容量/失败清单」报告，失败项重跑；对照表抽样人工核验 |
| 历史权限 | 存量文件统一按目标目录 ACL 模板授权，不设逐文件历史权限；特例文件迁移后人工调整并留痕 |

| # | 偏差点 | 说明 |
|---|--------|------|
| 1 | 任务码扩展 | 除下载/预览/分片组装/格式转换/回收站清理/临时清理 6 个 ASYNC/桩任务外，补充 6 个同步任务码：file.acl.set、file.metadata、file.list、file.delete、file.restore、file.recycle.list（同步交互语义，处理器内部仍按任务化通道执行） |

## 9. 落地偏差（2F 后端公共能力，2026-10-23）

2F-F1 阶段（导入导出 / 打印 / 方法级审计）与文档及方案 §4.23 的实现偏差记录如下：

| # | 偏差点 | 说明 |
|---|--------|------|
| 1 | 模板引擎选型 | RazorLight 2.3.1 在 .NET 10 运行时编译失败（探测工程 restore/build 通过、运行时 Razor 编译引擎初始化异常），按方案 §7-R2 预案切换 Scriban 6.2.1：数据占位 `{{ 模型字段 }}`、QR 占位 `{{qrcode:内容}}`（自定语法）。**引擎公共组件归口 BuildingBlocks/Printing（ScribanHtmlTemplateRenderer + QrCodePlaceholderRenderer），Support 只组合调用**——B-0 架构断言①要求 Support 程序集仅引用 Abstractions/BuildingBlocks，第三方包（Scriban/QRCoder，同 MailKit 先例）统一由 BuildingBlocks 承载；IPdfRenderer 保留 NullPdfRenderer 占位（抛 NotSupportedException），PDF 渲染器随实际交付选型接入 |
| 2 | 异常类型收敛 | BusinessException 为抽象类不可直接实例化，导入/打印的自定义错误码业务异常统一改用 ConflictException(message, errorCode)（IMPORT_FILE_INVALID / IMPORT_DICTIONARY_VALIDATOR_MISSING / PRINT_TEMPLATE_SYNTAX），未明确定义语义仍抛 NotFoundException |
| 3 | 失败审计语义 | 验收要求「成功/异常分支均留痕」二选一：过滤器在异常分支写失败审计（操作码追加 :FAILED 后缀，如 DELETE:FAILED）后异常原样上抛由全局异常中间件包装响应——失败动作绝不记为成功，且不重复写审计 |
| 4 | 导出/批量导入任务码 | 新增 file.export（长数据量导出 ASYNC）与 file.import.batch（批量导入 ASYNC）两个 Support 域任务码，产出/源文件均经 2B 文件中心存储（导出落 /temp/export/yyyy/MM 临时域，回收站/临时清理任务统一 TTL 管控），完成经 IMessageService 站内通知 |
| 5 | 按需任务不进 Manifest | ExportJobHandler/BatchJobHandler 为按需触发任务（无周期调度语义），跟随 FileUploadHandler 先例不注册进 SupportModule.Manifest.Jobs，仅 DI 登记 IJobHandler 由工厂分发 |
| 6 | 模板注册表默认兜底 | BuildingBlocks 侧 AddQlxImportExport 提供 EmptyImportTemplateRegistry 默认实现（Find 返回 null），业务模块按需以 IImportTemplateRegistry 自定义注册覆盖；导入落点 IImportRowSink / 导出数据源 IExportDataProvider / 字典校验 IImportDictionaryValidator 同为模块侧注册契约 |
| 7 | 公共助手复用 | SHA-256 计算提取 FileJobHelpers.ComputeSha256HexAsync 公共方法（原 FileUploadHandler 私有实现改为复用），导出任务秒传去重复用同一路径 |
| 8 | 导入列类型常量改名 | ImportColumnDataTypes.String 因 CA1720（标识符含类型名）更名为 Text（字典取值仍为 "string"，模板 JSON 契约不变） |
| 9 | 审计过滤器接入面 | Host MVC 管线 AddQlxOperationAudit() 全局注册；本期标注 FileController（5）/JobController（3）/MessageController（4）/ApprovalController（5）/PrintController（3）关键写方法，TargetType/TargetId 经特性 TargetIdParam 从路由参数解析，其余控制器随模块交付逐批标注 |
