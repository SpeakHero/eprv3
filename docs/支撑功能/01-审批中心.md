# 支撑功能详设：01 审批中心（流程审批）

> 对应《项目需求.md》4.0 统一审批流引擎 + 5.2 流程配置中心 ｜ 版本 v1.0 ｜ 2026-10-20
> 平台级公共能力：全部业务单据统一接入，禁止各模块自建审批逻辑。**条件表达式为独立公共组件（condition-builder）**，审批分支、预警规则、预算校验、信用规则等场景复用同一组件（遵循"公共组件提前到公共层复用"约定）。消息推送经《02-信息中心.md》，本文不重复渠道设计。

## 2. 核心实体与字段明细

### 2.1 流程定义 apr_flow_definitions

| 字段 | 类型 | 必填 | 说明 / 校验 |
|------|------|------|------------|
| def_id | bigint PK | 是 | 主键 |
| def_code / def_name | varchar | 是 | 定义编码/名称 |
| biz_type | varchar(32) | 是 | 单据类型（采购申请/销售订单/报销单等，字典注册） |
| org_scope | json | 是 | 适用组织范围（全租户 / 指定公司 / 部门集合） |
| version | int | 是 | 版本号；唯一索引 biz_type+org_scope+version |
| design_json | json | 是 | 设计器图数据（节点、连线、属性全量） |
| status | enum | 是 | DRAFT 草稿 / ENABLED 启用 / DISABLED 停用 |

### 2.2 流程节点 apr_flow_nodes（定义态）

node_id、def_id、node_key、node_type（APPROVAL 审批 / BRANCH 条件分支 / CC 抄送）、node_name、approver_type（ROLE 角色 / POSITION 岗位 / DEPT_LEADER 部门负责人 / USER 指定人 / FIELD_USER 单据字段人员 / INITIATOR 发起人）、approver_ref、sign_mode（COUNTERSIGN 会签 / ORSIGN 或签）、timeout_hours、timeout_action（URGE 催办 / ESCALATE 上报上级）、allow_add_sign、reject_mode（STEP_BACK 逐级 / TO_INITIATOR 直达发起人）、sort_no。

### 2.3 条件分支 apr_flow_branches（定义态）

> **v2.0 变更**：原字段 `expr_id`（引用独立条件表达式表）改为 `expr_json`（AST JSON 直接内嵌，由条件表达式引擎 `Parse` 产出，复用 `ConditionExpression.ToJson()` 格式）。独立 `condition_expr` 表规划已整体删除（D15）。

branch_id、def_id、from_node_key、to_node_key、expr_json（AST JSON，`$type` 判别符）、priority（优先级，先匹配先走）、is_default（兜底分支，每条分支线仅一条）。

### 2.4 流程实例 apr_instances

inst_id、inst_no、def_id、def_version、biz_type、biz_id、biz_no（冗余单据号）、initiator_id、org_id、current_node_key、status（RUNNING / COMPLETED / REJECTED / CANCELED / TERMINATED）、started_at、ended_at、snapshot_json（提交时单据关键字段快照，分支条件求值依据，防止审批中途改单影响判定）。

### 2.5 节点任务 apr_tasks

task_id、inst_id、node_key、node_name、approver_id（实际处理人）、source_type（NORMAL / DELEGATE 委托 / ADD_SIGN 加签）、source_from（来源人）、status（PENDING / APPROVED / REJECTED / SKIPPED / CANCELED）、opinion、ip、due_at（超时时点）、handled_at、duration_sec。

### 2.6 操作日志 apr_op_logs

log_id、inst_id、action（SUBMIT / APPROVE / REJECT / ADD_SIGN / DELEGATE / URGE / WITHDRAW / TERMINATE）、operator_id、detail、ip、created_at。只增不改。

### 2.7 委托 apr_delegates

delegate_id、delegator_id、agent_id、biz_types（范围，空=全部）、start_time、end_time、status。委托期间任务自动转代理人，以委托人名义留痕并标记 source_type=DELEGATE。

## 3. 业务规则与校验

| # | 规则 | 说明 |
|---|------|------|
| R1 | 唯一生效流程 | 同一 biz_type+组织范围仅允许一个 ENABLED 版本；单据提交时锁定 def_version |
| R2 | 版本隔离 | 流程修改产生新版本；在途实例继续按旧版本流转，不受影响 |
| R3 | 条件求值 | 分支条件在节点完成时基于实例快照求值；按 priority 从高到低匹配；全部未命中走 is_default；无兜底且未命中→实例置异常，转流程监控人工处理并告警 |
| R4 | 会签/或签 | 会签须全员通过，任一驳回即整体驳回；或签第一人处理即决，其余任务自动 SKIPPED |
| R5 | 加签 | 支持前加签/后加签；加签任务完成后回到原节点继续；加签链留痕 |
| R6 | 驳回策略 | 按节点 reject_mode 执行：逐级驳回回上一节点，跨级驳回直达发起人（单据回草稿） |
| R7 | 撤回 | 下一节点无任何处理动作时发起人可撤回；撤回后实例 CANCELED、单据回草稿 |
| R8 | 超时处理 | 任务到 due_at 未处理自动催办（经信息中心）；连续催办 N 次（参数）未处理自动上报上级审批人（与 4.12.6 通用模式一致） |
| R9 | 委托生效 | 委托有效期内新任务自动转派；委托可随时撤销；留痕显示「XX 委托 YY 处理」 |
| R10 | 留痕完整性 | 全部动作记录操作人/时间/意见/IP/委托关系；日志只读不可删，进入双层审计 |
| R11 | 事件回调 | 实例终态（COMPLETED/REJECTED/TERMINATED）经事件总线回调业务模块驱动单据状态机（4.0）；业务模块禁止轮询实例状态 |
| R12 | 表达式唯一实现 | 条件表达式组件全平台唯一，各场景统一引用 expr_id，禁止各模块自写条件判断 UI |
| R13 | 发起人避让（可选） | 节点审批人=发起人本人时自动跳过或转指定人（按流程配置） |

## 4. 典型审批链配置示例（映射各模块详设建议链）

| 单据 | 条件分支（表达式） | 节点链 | 说明 |
|------|------------------|-------|------|
| 采购申请 | total_amount < 50000 | 部门负责人 → 结束 | 阈值引用系统参数，表达式按参数变量配置 |
| 采购申请 | 50000 ≤ total_amount ≤ 500000 | 部门负责人 → 子公司分管副总 → 结束 | — |
| 采购申请 | total_amount > 500000 或 over_budget = true | 部门负责人 → 子公司总经理 → 集团分管副总 → 结束 | 超预算字段由预算校验回写快照 |
| 费用报销 | over_standard = true 或 over_budget = true | 部门负责人 → 子公司总经理 → 财务负责人 → 结束 | 标准内走「部门负责人 → 财务审核」 |
| 合同评审 | is_standard_tpl = false 或 amount > 阈值D | 业务 → 财务 → 法务/风控 → 子公司总经理 → 集团分管副总 | 标准模板小额走简化链 |
| 劳务工资表 | 无分支 | 项目经理 → 劳务管理负责人 → 财务负责人 → 子公司总经理 | 一致性校验（R8，人员模块）为提交前置 |

## 5. 权限点清单

**菜单**：流程管理（管理员）→ 流程定义 / 版本管理 / 流程监控 / 字段元数据 / 表达式库；我的审批（全员）→ 待办 / 已办 / 我发起的 / 委托设置；时效分析（管理层）。

**按钮**：流程新建/编辑/启停/版本对比/导出；表达式新建/试算/启停；待办处理/加签/催办/撤回/批量处理；委托设置/撤销；监控干预（跳转/终止）。

**数据权限**：集团管理员可配置全租户模板流程；子公司管理员仅本组织范围流程；待办仅本人（含被委托）可见；时效分析按组织树继承。

**字段权限**：IP、设备信息等留痕字段仅审计角色可见。

## 8. 落地偏差（2E）

2E 编码相对本文详设的实现偏差与边界约定，逐条记录如下（与 `docs/阶段二支撑功能开发方案-v2.md` 2E 章节一致）：

1. **终态事件契约复用**：`ApprovalCompletedEvent` 已在 2A 冻结契约 `Qlx.Abstractions/Approvals/ApprovalResponse.cs` 定义，本批次直接复用未新建文件；终态经 `IEventBus.PublishDurableAsync`（Outbox at-least-once）发布，订阅方幂等（R11）。
2. **审批人解析契约分层**：2A 冻结的 `IApprovalApproverResolver` 不含节点类型/快照上下文，无法承载组织侧解析。新增细粒度契约 `IApprovalApproverSource`（Support 兜底实现 INITIATOR/USER/FIELD_USER，Bas 实现 ROLE/DEPT_LEADER，宿主 DI 聚合轮询，模块零互引）；组织上下文经 bizData 约定键 `orgId` 透传。
3. **分支未命中语义**：R3「无兜底且未命中→实例置异常」落地为状态 `TERMINATED` + 告警消息（msg.alert.warning）+ 操作留痕，语义一致、状态值归口实例状态机；`EnsureBranchDefaults` 在启用前校验「每个审批节点必须有出边 + 每条来源线必须有兜底」，从源头阻断该场景。
4. **R13 发起人避让**：以节点级 `SkipIfInitiator` 配置落地（仅当节点审批人恰为发起人本人时自动通过并沿分支线继续），默认关闭。
5. **任务催办字段**：`apr_tasks` 增补 `urge_count`/`urge_last_at` 两列（R8 节流与上限判定依据），详设表结构清单未含。
6. **Bas 组织侧解析范围**：ROLE→成员主要角色、DEPT_LEADER→组织管理员承担；POSITION（岗位）类型本期未实现，节点配置该类型时解析为空并按「解析不到审批人」拒绝提交。
7. **查询分页边界**：2A 冻结契约查询方法（待办/已办/我发起的）无分页参数，实现以固定 Take 上限返回，分页待 2F 前端联调批次扩充契约（新增方法、不改既有签名）。
8. **阈值参数化待办**：超时小时/催办上限/节流间隔/批量等走强类型 `SupportApprovalsOptions`（config/tenant/support/approvals.json），**接入 por_parameters 系统参数表为 2F 待办**；种子流程金额分支阈值（50000/500000 两档）为示例默认值，待 2F 迁移为参数变量。
9. **委托实体命名**：实体类名 `ApprovalDelegation`（CA1711 禁用 Delegates 后缀），物理表名仍为 `apr_delegates` 不变。
10. **操作人身份注入**：审批操作人一律由 Controller 从服务端身份上下文注入，前端请求体不可传，防越权伪造。
11. **或签他决状态值**：R4「其余任务自动 SKIPPED」落地为任务状态 `CANCELED`（任务状态机无 SKIPPED 态），留痕文案「或签他决自动取消」。
12. **撤回终态值**：R7「撤回后实例 CANCELED」落地为实例状态 `WITHDRAWN`（与 CANCELED 语义分离：撤回=发起人主动，驳回=审批人否决），单据回草稿由订阅方按终态事件驱动不变。
13. **同事务判定时序**：节点完成判定/兄弟任务取消均在 `SaveChangesAsync` 之前执行，EF 追踪态滞后（DB 态仍为旧值）——统一采用「物化后按内存态二次过滤/判定」模式，禁止以 DB 端状态过滤直接判定同事务内刚决任务。
14. **待办通知时机**：任务生成即经信息中心发送 `msg.todo.generated`（write-through 持久化之外的尽力推送，失败仅告警不阻断审批主流程）；催办/结果/预警模板同批接入。
15. **快照取值类型**：快照整数解析强制 `long`（显式装箱规避三元隐式转 double），金额类比较精度不受损；FIELD_USER 字段值兼容单字符串/逗号分隔/JSON 数组三形态。
16. **条件引擎 DI 注册**：`IConditionExpressionEngine` 默认以 `TryAddSingleton`（引擎工厂单例）注册于 Support 模块服务集合，宿主可前置注册自定义实现覆盖（R12 全平台唯一实现约束不变）。
17. **流程定义懒种子运行时触发**：4 条默认流程（含节点/分支）由 `ApprovalFlowRegistry.EnsureTenantSeededAsync` 按需懒种子——服务侧查库为空时先种子再重查一次，不依赖租户开通管线时序；冒烟验证（qlx_dev 重建库）4 流程/10 节点/13 分支落库正确。
