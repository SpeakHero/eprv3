## 一、生产环境四库拓扑

```
 ┌────────────────────────────────────────────────────────────────────┐
 │  SQL Server 实例 A（门户 + 共享库）                                  │
 │  ┌─────────────────────┐  ┌──────────────────────────────────────┐ │
 │  │ qlx_portal          │  │ qlx_shared                           │ │
 │  │ (por_* + plog_*)    │  │ (glb_* + Hangfire*)                 │ │
 │  │ 控制面（唯一）        │  │ 全局公共数据面                       │ │
 │  └─────────────────────┘  └──────────────────────────────────────┘ │
 └────────────────────────────────────────────────────────────────────┘
 ┌────────────────────────────────────────────────────────────────────┐
 │  SQL Server 实例 B（租户数据面）                                     │
 │  ┌─────────────────────┐  ┌──────────┐  ┌──────────┐               │
 │  │ qlx_tenant_shared   │  │ qlx_t_01 │  │ qlx_t_02 │  ...          │
 │  │ 租户共享库（N 租户）  │  │ 独立租户  │  │ 独立租户  │               │
 │  └─────────────────────┘  └──────────┘  └──────────┘               │
 └────────────────────────────────────────────────────────────────────┘
```

> 同一生产环境始终**只有以上三类库**：门户库、共享库、（租户共享库 + 独立租户库集群）。
> 审计/日志不单独建库，见 §3 日志与审计路由。

## 二、数据库账号分离（强制）

| 账号 | 归属库 | 权限 | 用途 | 说明 |
| --- | --- | --- | --- | --- |
| `qlx_portal_app` | `qlx_portal` | db_datareader + db_datawriter + ALTER SCHEMA（EF Migration） | 门户宿主 | 含 OpenIddict、租户路由、模块许可、参数表 |
| `qlx_portal_ddl` | `qlx_portal` | db_owner（临时） | 首次部署迁移 | 迁移完成后应降级为 db_owner 以下 |
| `qlx_shared_app` | `qlx_shared` | db_datareader + db_datawriter + ALTER SCHEMA | 平台发布全局项 + Hangfire Worker | 门户侧（写全局公告/任务）与 Hangfire Worker 使用 |
| `qlx_shared_reader` | `qlx_shared` | db_datareader only | 租户侧只读 `glb_*` | `Qlx:PlatformShared:ReadOnlyConnectionString`；**禁止写** |
| `qlx_tenant_writer` | `qlx_tenant_shared` + 所有独立租户库 | db_datareader + db_datawriter + ALTER SCHEMA + VIEW SERVER STATE | 租户宿主业务写入 | 应用连接，含 RLS 会话上下文 |
| `qlx_tenant_migrate` | `qlx_tenant_shared` + 独立租户库 | db_owner（仅限迁移期） | 首次部署/模块扩展迁移 | 迁移完成后必须回收权限 |
| `qlx_backup` | 全部四库 | db_backupoperator + VIEW SERVER STATE | 定时备份 | 不可写业务表 |
| `qlx_metrics` | 全部四库 | db_datareader + PROCESS + VIEW SERVER STATE + SELECT 特定 DMVs | Prometheus/OpenTelemetry 指标采集 | 见 §5 监控 |

**铁律**：
1. 门户库账号**绝对禁止**用于租户数据库连接（防误用 por_* / plog_*）；
2. 共享库只读账号 `qlx_shared_reader` 必须以 `ApplicationIntent=ReadOnly` 连接，禁止路由主副本写入；
3. 独立租户库账号必须在**实例 B** 上创建，不能在实例 A 上复用；
4. 迁移账号 `qlx_portal_ddl` / `qlx_tenant_migrate` **仅限首次部署 + 模块升级窗口**使用，完成后立即回收权限；
5. 所有账号密码必须经 Data Protection 加密存放于密钥管理服务，**禁止明文写入 config 文件**。

## 三、配置文件与密钥引用

### 3.1 开发 vs 生产

| 配置项 | 开发环境 | 生产环境 |
| --- | --- | --- |
| `ConnectionString`（门户/审计/共享库） | `Server=(localdb)\MSSQLLocalDB;Database=qlx_portal;...` 明文 | `Server=prod-sql-a;Database=qlx_portal;User Id=qlx_portal_app;Password={DP:portal_conn_string};...`（密码经 Data Protection 引用） |
| `Qlx:Tenancy:SharedDatabase:DbHost/DbPort/DbName` | 明文 | 明文（仅主机端口库名，无敏感信息） |
| `Qlx:Tenancy:SharedDatabase:ReadOnlyPassword` | 明文 | `DP:shared_reader_password`（密钥引用） |
| `Qlx:PlatformShared:ConnectionString` | 明文 | 明文主机 + `DP:shared_conn_string` 密码引用 |
| `Qlx:PlatformShared:ReadOnlyConnectionString` | 可空（回退主连接） | **必须显式配置**且 `ApplicationIntent=ReadOnly` |
| `Qlx:Audit:ConnectionString` | 明文 | 明文主机 + `DP:audit_conn_string` |
| `Qlx:Ids:Obfuscation:Salt` | 明文 | `DP:hashids_salt` |
| `Qlx:DataProtection:*` | 本地目录 | Azure Key Vault / 集中式目录 + 加密 |
| `Qlx:Cache:*` | Provider=Memory | Provider=Redis + 密码引用 |
| `Qlx:Tenancy:DevelopmentFallback:Enabled` | true | **必须 false**（`ValidateOnStart` 强制） |

> **密钥引用约定**：`DP:{purpose}` 表示经本地 Data Protection 解密注入；Azure Key Vault 可改用 `Azure:{secret_name}` 前缀并在启动期注入 `ISecretResolver`。

## 四、生产环境检查清单

### 4.1 部署前（Pre-deploy）

| # | 检查项 | 通过标准 | 失败后果 |
| --- | --- | --- | --- |
| P-01 | 四库连接串全部就绪 | Portal/Shared/租户共享库/独立租户库迁移账号分别连通 | 启动期 EnsureDatabaseExists/MigrateAsync 失败 |
| P-02 | 账号隔离已生效 | 门户账号不能连租户库（跨 DB 拒绝）；共享库只读账号验证 `ApplicationIntent=ReadOnly` 生效 | 误写/越权 |
| P-03 | Data Protection 密钥目录集中式 | 目录权限仅限应用账号；密钥至少 3 份副本；密钥轮转流程已演练 | 凭据无法解密、多实例 workerId 租约冲突 |
| P-04 | `DevelopmentFallback.Enabled=false` | `ValidateOnStart` 强制，Production 环境启动立即抛出 | 生产环境误连 LocalDB 空库 |
| P-05 | SQL Server 版本 ≥ 2019 | RLS + 过滤索引（`[Status] < 5`）全部生效 | RLS 表无法创建、唯一索引 SQL 语法错误 |
| P-06 | 防火墙/网络连通性 | 门户宿主能访问实例 A + 实例 B；租户宿主能访问实例 B；只读账号访问实例 A/B 的只读端口 | 启动失败/运行期连接异常 |

### 4.2 部署后（Post-deploy）

| # | 检查项 | 通过标准 | 失败后果 |
| --- | --- | --- | --- |
| A-01 | `/health` 返回 200 + Healthy | 所有健康探针 Green（数据库、缓存、雪花租约、Data Protection） | 宿主启动失败 |
| A-02 | 共享库迁移**只执行一次** | 并发启动多宿主，`__EFMigrationsHistory_*` 表每模块各 1 行，应用锁 `qlx:migrate:tenant_shared` 生效 | 共享库迁移冲突/重复 |
| A-03 | 租户路由行数据库模式正确 | 存量租户全部 Isolated + 凭据为空；新建 Shared 租户路由行凭据为空、Isolated 租户凭据经 Data Protection 解密非空 | 路由解析失败/凭据解密异常 |
| A-04 | RLS 策略覆盖全部租户业务表 | `sys.security_policies` 数量 == 业务表含 TenantId 的数量；RLS 策略 FILTER 谓词正确 | 隔离层缺失/裸 SQL 越权 |
| A-05 | 升级流水线首次调度正常 | `por_tenant_upgrade_jobs` 无残留；Dispatcher 扫描周期 15s；手动登记 Pending 任务 30s 内进入 Preparing | 升级静默失败 |
| A-06 | 巡检周期执行 | `por_isolation_audit_records` 24h 内有新行；严重发现能触发 ISOLATION_AUDIT_ALERT 审计 | 隔离缺陷无法被自动发现 |
| A-07 | 日志/审计分流正确 | 门户操作（promote/retry）→ `plog_operation`；租户登录 → 本租户库 `log_login`；两侧无同一 ID 重复 | 日志重复/跨库直查 |
| A-08 | 备份策略已落地 | 见 §5 备份策略；首次完整备份已完成；恢复演练已通过 | 数据库故障无法恢复 |
| A-09 | 监控告警已接入 | Prometheus 采集到全部 §6 指标；严重告警通道已配置（短信/企业微信/钉钉） | 故障无法及时发现 |

### 4.3 周期性检查（Weekly）

| # | 项 | 通过标准 |
| --- | --- | --- |
| W-01 | SQL Server 数据库可用空间 | 所有四库剩余 > 20%；共享库剩余 > 30%（全局项写频高） |
| W-02 | 雪花 workerId 租约分布 | `Qlx:Ids:Snowflake:LeaseProvider=Redis` 时 Redis 中 `qlx:worker:*` 键数量 == 活跃宿主数 |
| W-03 | Hangfire 待执行任务积压 | `hangfire_Job` 表 Pending > 100 触发告警 |
| W-04 | 审计日志保留期限 | `plog_audit`/`plog_operation`/租户库 `log_*` 早于 RetentionDays 的行已被清理 |
| W-05 | Data Protection 密钥过期天数 | 距离下一次密钥过期 > 30 天 |

## 五、备份与恢复策略（简要版）

> 完整 SOP 见 [备份与恢复SOP.md](备份与恢复SOP.md)，本节仅保留频率速查与关键提醒。

### 5.1 四库备份频率速查

| 库 | 全量 | 差异 | 日志 | 保留 | 恢复影响 |
| --- | --- | --- | --- | --- | --- |
| `qlx_portal` | 每日 02:00 | 每 6h | 每 15min | 30d | 全部租户 |
| `qlx_shared` | 每日 03:00 | 每 4h | 每 15min | 30d | 全部租户（含 Hangfire） |
| `qlx_tenant_shared` | 每周六 01:00 | 每日 | 每 30min | 30d | **所有 Shared 模式租户** |
| `qlx_tenant_*` | 每日 04:00 | 每 6h | 每 15min | 14d | 仅该租户 |

### 5.2 关键提醒

1. `qlx_tenant_shared` 恢复前**必须停掉所有 Shared 租户宿主**（不可接受新写入）；
2. Hangfire 表不可与 `qlx_shared` 独立备份（恢复必须一起）；
3. 门户库恢复后**必须校验路由行指向的物理库是否存在**，不存在则标记 `ProvisioningFailed`；
4. 恢复演练至少每季度一次。

## 六、升级窗口 SOP（简要版）

> 完整 SOP 含阶段流程图、失败回滚场景、模块迁移 SOP 见 [备份与恢复SOP.md](备份与恢复SOP.md) §3/§4，本节仅保留关键节点速查。

### 6.1 升级流水线阶段

```
Preparing ──► Copying ──► Verifying ──► Cutover ──► Done ──► [30d保留] ──► Cleaned
  │            │           │          │           │                        │
  │            │           │          │           │                        └── 自动清理残留
  │            │           │          │           └── 路由切换完成
  │            │           │          └── ~5秒停机
  │            │           └── 行数 + 哈希
  │            └── 键集分页（业务正常读写）
  └── 建库 + 迁移 + RLS
```

### 6.2 失败处理速查

| 失败阶段 | 自动处理 | 运维操作 |
| --- | --- | --- |
| Preparing / Copying / Verifying | Failed + 独立库保留 + 路由不变 | `POST .../upgrade-job/retry`（断点续跑） |
| Cutover（极罕见） | 事务回滚 + 路由保持 Shared | 同上，手动重试 |
| 3 次仍失败 | — | 手动比对 + 手动改路由 |

> **铁律**：升级完成后**无自动降级入口**（设计铁律 A8）。紧急回滚参见完整 SOP §3.4。

## 七、监控指标清单（简要版）

> 完整指标定义、Prometheus 告警规则示例、Grafana 看板设计、与备份/恢复/升级联动规则见 [监控告警配置.md](监控告警配置.md)，本节仅保留指标分类速查。

### 7.1 指标分类速查

| 类别 | 关键指标 | 级别 |
| --- | --- | --- |
| **共享库** | 连接数 / 慢查询数 / 磁盘剩余 | warning / critical |
| **门户库** | 路由失败率 / 连接数 | critical（路由失败）/ warning |
| **租户共享库** | **RLS 缺失数** / **跨租户可疑数** / RLS 绕过尝试 | 全部 critical（隔离红线） |
| **独立租户库** | ProvisioningFailed 数 / 连接数 | critical / warning |
| **迁移** | 失败次数 / 并发冲突数 / 卡住数 | critical / warning |
| **升级** | 失败数 / 卡住数 / 校验不一致数 | warning / critical |
| **日志** | 队列丢弃数 / 批量失败数 | warning / critical |
| **雪花** | 租约冲突数 | critical |
| **Health** | 探针成功率 | critical |

> **技术选型**：OpenTelemetry Metrics + Prometheus Exporter + Grafana。告警通道：critical → 短信 + 企业微信 + 钉钉；warning → 企业微信群。
