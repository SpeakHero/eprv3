### 3.2 独立库预配链路（实测时序）

```
POST /api/portal/admin/tenants (databaseMode=Isolated)

       ② sp_getapplock 会话级应用锁 qlx:migrate:tenant:{tenantId}
       ③ shared → log → bas → support 按拓扑序 MigrateAsync + RLS 安装（本环境关闭）
       ④ 全部成功 → 租户 Active / 路由 Ready
实测：02:30:06 创建 → 02:31:04 完成（58 秒）
```

## 4. 问题清单与复现步骤

### P1-1 后端字段级校验错误未在前端透出（共享/独立模式均存在）【已修复 ✅ 2026-10-24】

- **现象**：后端返回 422 且 `errors[{fieldName,errorMessage}]` 完整，UI 仅 toast「请求数据校验失败」，用户无法定位具体字段。
- **复现步骤**：
  1. 打开「新建租户」弹窗；
  2. 租户编码填 65 位、其余合法；
  3. 提交 → 观察 toast。
- **根因**：[admin.ts](file:///e:/ERPv2/eprv3/src/Qlx.Web/src/api/admin.ts) 的 `request<T>` 仅取 `body.message ?? body.code`，丢弃 `errors[]`；`ApiResponse<T>` 类型亦未声明 `errors`。
- **影响**：V-1 双层校验的「前端 UX 反馈」链路不完整，后端安全边界本身正常。
- **修复内容**：
  1. [admin.ts](file:///e:/ERPv2/eprv3/src/Qlx.Web/src/api/admin.ts)：`ApiResponse<T>` 补齐 `errors` 类型；新增 `ApiError`（携带 `code` + `fieldErrors`），`request<T>` 在 `success=false` 与 HTTP 错误两条路径均透传字段错误；
  2. [QlxFormDialog.vue](file:///e:/ERPv2/eprv3/src/Qlx.Web/src/components/crud/QlxFormDialog.vue)：新增可选 prop `fieldErrors`（键=字段 prop），经 `el-form-item :error` 在字段旁展示（向后兼容全部复用方）；
  3. [PortalTenantListView.vue](file:///e:/ERPv2/eprv3/src/Qlx.Web/src/views/portal/PortalTenantListView.vue)：onCreate 捕获 `ApiError` 后把 `fieldErrors` 映射到表单；打开弹窗/重新提交时清空。
- **回归验证**：浏览器实测非法编码 `ABC-INVALID` 提交 → 字段旁红字「租户编码须以小写字母开头，仅含小写字母/数字/短横线，长度 2~64」+ toast 总提示（截图 27）；前端 `npm run build` 0 错误、vitest 100/100 通过。

### P1-2 预配中租户暴露无效「启用/停用」操作，且报错文案中英混杂【已修复 ✅ 2026-10-24】

- **现象**：独立模式创建后状态为「预配中」，操作列仍显示「启用」；点击并确认后 toast「租户当前状态 **Pending** 不支持启用/停用」。

  2. 列表该行操作列点「启用」；
