### T-P0-1：修复独立库租户保存模块授权 500

**现象**：`PUT /api/portal/admin/tenants/{id}/modules` 对独立库租户 qlx-demo 返回 500：
`DbUpdateConcurrencyException: expected to affect 1 row(s), but actually affected 0 row(s)`。共享库租户 upg-smoke 同操作正常。

**代码位置**：
- 服务：[PortalTenantAdminService.SaveLicenseAsync](file:///e:/ERPv2/eprv3/src/Qlx.Modules.Portal/Services/PortalTenantAdminService.cs#L243-L319)
- 仓储：[PortalAdminRepositories.FindTrackedWithModulesAsync](file:///e:/ERPv2/eprv3/src/Qlx.Modules.Portal/Repositories/PortalAdminRepositories.cs#L73-L75)
- 实体：[TenantModule](file:///e:/ERPv2/eprv3/src/Qlx.Modules.Portal/Domain/Tenancy/TenantModule.cs)、[Tenant](file:///e:/ERPv2/eprv3/src/Qlx.Modules.Portal/Domain/Tenancy/Tenant.cs)、[LicenseRecord](file:///e:/ERPv2/eprv3/src/Qlx.Modules.Portal/Domain/Tenancy/LicenseRecord.cs)

**根因（已确认，2026-10-24）**：

EF Core 变更跟踪 + 主键值生成策略冲突，与租户数据库模式（独立库/共享库）无关，仅因数据形态不同而表现不同：

1. `SnowflakeKeyConvention` 将全部 `long` 主键配置为 `ValueGenerated.OnAdd` + `SnowflakeIdValueGenerator`（`GeneratesTemporaryValues = false`）+ `SqlServerValueGenerationStrategy.None`，设计意图是「Id 由应用层雪花生成器赋值」。
2. `SaveLicenseAsync` 在 `tenant.AddModule(module)` **之前**显式调用 `module.AssignId(snowflake.NextId())`（`LicenseRecord` 同样在 `AddRange` 前显式置键）。
3. 经导航集合被 EF 发现的实体若**主键已置值**，EF 无法区分「新增」与「已存在」，将其判定为 `Modified`，生成 `UPDATE por_tenant_modules ... WHERE Id = @id`；该行尚不存在 → 影响 0 行 → 抛 `DbUpdateConcurrencyException: expected to affect 1 row(s), but actually affected 0 row(s)`。
4. 共享库租户（upg-smoke）此前均是「已有行改状态」的真实 UPDATE，故同样调用路径不报错；独立库租户（qlx-demo）本次是「新增 bas 行」，暴露了该缺陷。
5. 对比参照：`CreateAsync` 虽也 `AssignId`，但随后经 `AddModulesAsync`（`DbSet.AddRange`）显式标记 `Added`，故不受影响。

**已实施修复**：
- [PortalTenantAdminService.cs:298-310](file:///e:/ERPv2/eprv3/src/Qlx.Modules.Portal/Services/PortalTenantAdminService.cs#L298-L310)：移除 `TenantModule` 与 `LicenseRecord` 的显式 `AssignId`，改由 EF 值生成器在 `SaveChanges` 时统一赋值（同样是雪花 Id），并就地注释说明禁止原因，防止回归。
- 同期按 C-5 补缓存失效（原方案第 4 步）：见「六、遗留问题闭环」。

**实测结果**：
- `PUT /api/portal/admin/tenants/{qlx-demo}/modules` 请求 `["support","bas"]` → **200**；`por_tenant_modules` 中 bas 行 `Status=1` 正确落库，`por_license_records` 生成 Granted 记录。
- 回归：回收 bas（UPDATE 路径）→ 200，`Status=2` + Revoked 记录；共享库租户 upg-smoke 无变更保存 → 200。
- LocalDB 集成测试（新增）复现同一写入路径，落库 2 行；以突变验证（临时注入 `AssignId`）该测试立即失败，确认守卫有效。

**验收结论**：原 4 条验收标准全部达成；新增 `PortalTenantModuleInsertSqlServerTests` 作为长期回归守卫。

**风险（已解除）**：修复仅收窄「新增实体置键」一处，不涉 EF 版本或 DateTimeOffset 行为；已回归租户创建、启停、授权新增/回收路径。

**实测结果**：修正 6 行（各租户 support 模块），执行后 `DATENAME(tz, LicensedAt) <> '+00:00'` 的残留行数 = **0**。生产环境须经变更工单 + 备份后执行。

### 6.1 C-5 缓存失效（写路径只删不写）

**问题**：`SaveLicenseAsync` 提交授权变更后未失效 `_portal:license:{tenantId}`，租户登录态 modules claim 可能读到旧值（违反 C-5「失效优先」）。

**已实施修复**：
1. [ModuleLicenseService.cs:26-33](file:///e:/ERPv2/eprv3/src/Qlx.Modules.Portal/Services/ModuleLicenseService.cs#L26-L33)：新增唯一键构建入口 `BuildCacheKey(long tenantId)`（经 `QlxCacheKey.BuildPortalKey("license", …)`）；读路径改用该方法，消除散装字符串拼 key（C-1-2）。
2. [PortalTenantAdminService.cs:42-44](file:///e:/ERPv2/eprv3/src/Qlx.Modules.Portal/Services/PortalTenantAdminService.cs#L42-L44)：注入 `ICacheService`。
3. [PortalTenantAdminService.cs:310-315](file:///e:/ERPv2/eprv3/src/Qlx.Modules.Portal/Services/PortalTenantAdminService.cs#L310-L315)：`SaveChangesAsync` **提交成功后**调用 `RemoveAsync(许可键)`；严格「先提交事务 → 再删缓存」，不做双写、不先删后提交。

**实测**：手工种入物理键 `qlx:_portal:license:{tenantId}`（`EXISTS=1`）→ 调用保存授权接口（200）→ `EXISTS=0`，证明真实 Redis 上已完成失效。
