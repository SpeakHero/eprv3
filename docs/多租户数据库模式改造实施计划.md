# ERPv3 多租户数据库模式改造实施计划

> 版本：v1.8\
> 日期：2026-10-22\
> 状态：✅ 主计划完成（B0~B7 全部关闭；P2 预留任务不阻塞）\
> 依据：[多租户数据库模式补充设计.md](多租户数据库模式补充设计.md) v1.1\
> 定位：把设计文档 §9「改造清单」落成**可执行的批次、任务、依赖与优先级顺序**；不重复设计结论，不新增设计范围。\
> 基线：本文「现状」均基于 2026-10-21 当前代码核对，不引用历史结论。

***

## 0. 结论摘要

1. **当前代码是「门户库 + 每租户独立库」两库形态**：`Program.cs` 启动时迁移 `AuditDbContext`、`PortalDbContext`，再手工遍历所有租户库迁移 Bas；四库中的**共享库、租户共享库尚未存在**，`glb_*` / `plog_*` / `log_*` / RLS / 写入守卫均未落地。
2. **最高优先级不是升级任务，而是底座与共享租户开通链路**：先完成「模型与配置 → 路由双分支 → 预配/迁移分支」，否则新建共享租户会直接进入独立库预配流程。
3. **隔离红线必须紧跟开通链路**：共享租户一旦可开通，若没有写入守卫、租户缓存键、单据编号租户段、架构测试与越权用例，就存在跨租户串数据风险，不能进入联调。
4. **四库职责归位（审计并库、租户日志、共享库全局项）是 P0，但全局消息/任务部分依赖 2D 信息中心模块**；本期可先完成基础设施、审计路由与共享库只读通道，`glb_*` 业务随 2D 落地，**不提前造支撑模块**。
5. **共享 → 独立升级（P1）必须等底座 + 隔离 + 四库门禁全部通过后启动**，禁止与底座批次并行。

## 1. 优先级与执行规则

### 1.1 优先级定义

| 级别 | 含义 | 判定标准 |
| --- | --- | --- |
| **P0** | 不上线即事故：共享租户无法开通，或开通后存在串数据/越权/日志越库风险 | 与设计 §9 的 P0 对齐 |
| **P1** | 本期收尾：升级、巡检、前端完整体验、运维文档 | 与设计 §9 的 P1 对齐 |
| **P2** | 预留：只留接口/配置/骨架，不实现业务 | 与设计 §9 的 P2 对齐 |

### 1.2 执行规则（硬约束）

| # | 规则 |
| --- | --- |
| R1 | **按批次顺序推进，不跳批次**；同一批次内按任务编号顺序推进 |
| R2 | 每个任务完成后执行：`dotnet build` 0 警告 → 相关单测/集成测试全绿 → Host 冒烟；通过后再进下一任务 |
| R3 | 每批次结束执行一次**全量回归 + 数据库升级验证**（含存量库、全新库两种起点） |
| R4 | 任何涉及共享库/租户共享库的代码，**禁止出现 `EnsureDeleted` / `DROP DATABASE`**；迁移失败只标记、不删库 |
| R5 | 共享租户开通、升级切换、连接信息变更三处必须统一调用 `Invalidate + PreloadAsync` |
| R6 | 本文未列出的改动默认不做；P2 能力只留抽象，不写业务实现 |

### 1.3 批次门禁（Definition of Done）

一个批次只有在以下全部满足后才能关闭：

- `dotnet build` 0 警告 0 错误；
- 该批次新增/修改的单测与集成测试全绿；
- 架构测试全绿（尤其表归属、TenantId 唯一索引、禁止跨库引用）；
- Host 以「已有门户库 + 已有独立租户库」启动成功，且存量租户连接解析行为不变；
- 文档（设计/计划/配置说明）同步更新，无互相冲突表述。

## 3. 总体实施路线与优先级顺序

### 3.1 依赖关系

```text
B0 模型与配置底座
  └─► B1 路由与连接双分支
        ├─► B2 预配 / 迁移 / 启动装配
```

## 5. B0 已冻结的决策项（2026-10-21 冻结）

以下 7 项已在 B0 结束前形成书面结论，后续批次（B1~B7）一律按此执行，不得再改口：

| # | 决策项 | 冻结结论 |
| --- | --- | --- |
| D1 | 缓存键格式 | 统一为 `tenant:{id}:{module}:{key}`；B3 一次性替换旧键（`tenantCode:module:key`），不双写 |
| D2 | 审计历史数据 | B4-03 采用「停写 → 导出 → 导入 `plog_*` → 切换」；不做双写长期并存 |
| D3 | 共享库开发期建库 | 开发环境允许由显式开关控制自动建库；生产必须预配；任何环境禁止删库 |
| D4 | 按模块历史表范围 | 仅租户共享库启用 `HistoryTablePerModule`（`__EFMigrationsHistory_{module}`）；独立库默认单表 |

| D6 | 存量租户回填 | 迁移回填 `DatabaseMode=Isolated`（已落库验证），不改变任何连接与业务行为 |
| D7 | RLS 启用范围 | 本期租户共享库强制开启；独立库默认关闭并保留开关 |

> 附加冻结：`TenantDatabaseMode` 的层位固定为 `Qlx.Abstractions.Tenancy`（`Shared=1`、`Isolated=2`），任何模块不得复制该枚举。
