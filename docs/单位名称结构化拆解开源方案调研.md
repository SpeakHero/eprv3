# 单位名称结构化拆解开源方案调研与实施建议

> **版本**：v1.0
> **日期**：2026-10-25
> **调研范围**：可将完整中文单位名称拆解为「地域 / 行业 / 组织性质（组织形式） / 核心名称（字号）」的免费开源、可商用工具与算法库
> **结论**：全市场仅有一个开箱即用的专用库 `companynameparser`（Python，Apache-2.0，自评 94.8%/94.5%），但已停更且仅覆盖企业名称；**不存在**能覆盖企业、事业单位、机关、社会组织的通用开源方案。生产落地建议采用 **词典 + 规则引擎（.NET 自研）为主、NER/LLM 兜底** 的混合方案。

---

## 1 问题定义与标准依据

### 1.1 法定四要素结构

依据《企业名称登记管理规定》（国务院令第734号）第六条及《企业名称登记管理规定实施办法》（市场监管总局令第82号）第八条：

> 企业名称一般由 **行政区划名称 + 字号 + 行业或者经营特点 + 组织形式** 依次组成。

这是规则拆解的法律基础，同时明确了三类合法例外，解析器必须支持：

| 例外 | 示例 | 对解析的影响 |
|---|---|---|
| 跨省经营可不含行政区划 | 华为技术有限公司 | 地域为空，剩余整体易被误判为字号 |
| 综合经营可不含行业 | 某某实业有限公司 | 行业为空 |
| 行政区划可后置并加括号 | 某某科技（武汉）有限公司 | 地域不在名称首位 |
| 分支机构 / 集团 / 外商投资企业 | 中国建设银行股份有限公司湖北省分行 | 出现两个地域、两个组织形式 |
| 非企业单位不适用该规定 | 中国科学院计算技术研究所、市市场监管局 | 需事业单位 / 机关 / 社会组织专用词表 |

### 1.2 “组织性质”概念澄清（重要）

需求中的“组织性质”需拆成两个互不相同的概念，否则无法验收：

| 概念 | 含义 | 能否从名称文本得到 |
|---|---|---|
| **组织形式** | 有限公司、股份有限公司、有限责任公司、分公司、合伙企业、个人独资企业、个体工商户、农民专业合作社、集团、研究院、中心、局、委、办、协会、基金会等 | **能**，由后缀词表匹配得到 |
| **登记注册类型（所有制性质）** | 国有、集体、私营、港澳台投资、外商投资等 | **不能**，名称中通常不含该信息，只能来自营业执照 / 登记注册类型代码字段 |

因此方案只承诺拆出“组织形式”，不承诺从名称推断“国有/民营/外资”。若业务确需所有制性质，必须接入登记数据字段，不能用名称猜。

### 1.3 名称文本的固有局限

- 名称中的“行业用语”不等于实际行业（大量“科技公司”实际从事贸易）。
- 行政区划是登记地，不一定是经营地。
- 园区、开发区、新区不属于标准行政区划，必须单独维护别名表。
- 简称、俗称、品牌名与注册名称不一致时，需别名映射或人工复核。

### 2.1 许可合规说明

- Apache-2.0 / MIT 均允许商用、修改、闭源分发，**无 copyleft、无授权费**，但需保留版权声明与 NOTICE 文件——属于“低限制”，而非“零条件”。
- Apache-2.0 含显式专利授权，比 MIT 更适合长期商业产品。
- 引入第三方词典数据时，须单独核对数据来源声明；代码许可不自动覆盖仓库内的第三方语料。

## 3 方案逐项评估

### 3.1 companynameparser（唯一开箱即用的专用库）

- **原理**：jieba 分词 + 地名 / 行业 / 后缀 / 符号词典 + 顺序约束 + 后处理，非神经网络。
- **输出**：`place`、`brand`、`trade`、`suffix`、`symbol`。
- **中文适配**：仅中文；对含行政区划、四要素齐全的企业注册名称适配最好。
- **扩展能力**：
  - 词典文件可替换（`place_path` / `suffix_path` / `trade_path`）；
  - `set_custom_split_file(file)` 支持按完整名称精确覆盖，格式为 `完整名称,地域,字号,行业,组织形式,符号`；
  - 无规则 DSL，复杂规则需改 Python 源码。
- **短板**：停更近 4 年；无 .NET / Java 版本；不覆盖事业单位、机关、社会组织；无地域名称会整体退化为 brand。
- **准确率**：作者自评严格完全匹配准确率 94.8%、召回率 94.5%；该指标基于其自建评测集，样本外泛化明显下降（见第 4 章实测）。

### 3.2 cpca（地域字段最佳补充）

- **能力**：提取省 / 市 / 区并映射 `adcode`，支持简称、别名、缺省层级推断，返回剩余地址。
- **局限**：不识别“开发区 / 工业园区 / 新区”等非标准行政区划；无乡级（街道 / 乡镇）；对园区类会漏。
- **可扩展性**：内置行政区划数据，扩展需改数据源与匹配逻辑，工作量小。
- **注意**：在 Python 3.14 + 新版 setuptools 下仍依赖 `pkg_resources`，需固定 `setuptools<81`。

### 3.3 HanLP 1.x（Java 侧最实用）

- 提供分词、词性、机构名识别（`nt`），可加载自定义词典，适合 Java / Spring 体系。
- 输出为“整段机构名”，不含四要素切分，必须再写规则。
- **许可分界（关键）**：仓库代码 Apache-2.0；但 **HanLP 2.x 预训练模型与 RESTful API 为 CC BY-NC-SA 4.0（禁止商用）**。商用只能评估 1.x 及其数据包，且需核对数据包内第三方语料声明。
- 准确率：无四要素评测；通用机构名 NER 在 MSRA 类语料上的 F1 常见区间约 0.85–0.90，但该指标不能直接迁移到本任务。

### 3.4 PaddleNLP UIE（零样本兜底）

- 通过 schema 自定义标签（地域 / 字号 / 行业 / 组织形式），无需标注即可抽取。
- 问题：span 抽取会重叠、边界不稳定（“行业”与“字号”常互相吞并），仍需规则约束与校验。
- 需要 PaddlePaddle 运行时，CPU 可跑但吞吐一般；适合离线批处理或独立推理服务，不适合直接嵌入 .NET 进程。
- 许可：PaddleNLP 与 `uie-base` 模型卡均为 Apache-2.0。

### 3.5 nerpy + bert4ner-base-chinese

- Python + PyTorch，Apache-2.0，小体量项目。
- 仅输出 ORG 实体整段，不能拆分四要素；可参考 CLUENER 指标评估，不具备单位名称专用评测。

### 3.6 jieba / pkuseg（分词组件）

- 均为 MIT，可商用；jieba 支持自定义词典与词性标注，`nt` 可标注机构名。
- 只能作为自研规则引擎的分词前置，不能独立完成拆解。

### 3.7 Qwen2.5（LLM 兜底）

- 7B / 14B / 32B 为 Apache-2.0，可本地部署、可商用（3B 与 72B 使用其他许可）。
- 优点：可处理非标准名称、简称、混合表述；缺点：非确定性、可能编造字段、需 GPU、需自建评测集。
- **定位**：仅作为“规则未命中”的候选生成器，输出必须过规则校验，不得作为唯一链路。

## 4 实测验证

### 4.1 环境与步骤

- 环境：Windows + Python 3.14.8，临时虚拟环境。
- 依赖：`companynameparser`（PyPI 最新版）、`cpca`、`setuptools<81`。
- 样本：10 条，覆盖标准企业名、央企、分支机构、事业单位、机关、园区企业、无地域名称。

```powershell
python -m venv .venv
.venv\Scripts\pip install companynameparser
.venv\Scripts\pip install "setuptools<81" cpca
```

### 4.3 结论

- 企业标准名称 6 条中 4 条完全正确；事业单位、机关、无地域名称全部失败。
- 与“自评 94.8%”不矛盾：其评测集以规范企业名称为主，**样本外泛化明显下降**。
- cpca 的省 / 市 / 区抽取稳定，但“工业园区”未识别为行政区划，需自建园区别名表。
- 结论：专用库适合做**离线基线**，不适合作为生产唯一链路。

### 4.4 可复现调用方式

```python
import companynameparser

print(companynameparser.parse("武汉海明智业电子商务有限公司"))

# 返回字符偏移，便于回填原串 / 高亮
print(companynameparser.parse("武汉海明智业电子商务有限公司", pos_sensitive=True))

# 自定义精确覆盖：custom.txt 每行 = 完整名称,地域,字号,行业,组织形式,符号
companynameparser.set_custom_split_file("custom.txt")
```

import cpca

## 5 能力对比与适用场景

### 5.1 对比矩阵

| 方案 | 四要素完整性 | 中文适配 | 准确率依据 | 自定义扩展 | 适合场景 |
|---|---|---|---|---|---|
| companynameparser | 高（企业）/ 低（非企业） | 企业名称强 | 自评 94.8%/94.5%，样本外明显下降 | 词典 + 整名覆盖 | 离线基线、批量清洗、评测集生成 |
| cpca | 仅地域 | 行政区划强，园区弱 | 无单位名称官方指标 | 改数据源 | 补全省市区 / adcode |
| HanLP 1.x | 低（仅 ORG 整段） | 强 | 无四要素评测 | 自定义词典 | Java 体系内做分词 / NER 前置 |
| PaddleNLP UIE | 中（span 需后处理） | 强 | 无四要素评测 | schema 可改 | 零样本兜底、独立推理服务 |
| nerpy / bert4ner | 低 | 中 | CLUENER 上 ORG 约 0.80 F1（榜首 83.6） | 需微调 | 研究 / 实验 |
| Qwen2.5 | 中高（需评测） | 强 | 无公开四要素指标 | Prompt / 微调 | 低置信度兜底、人工复核辅助 |
| 自研规则引擎 | 高（可覆盖全类型） | 可做到最强 | 取决于词表与验收集 | 完全可控 | 生产落地（推荐） |

### 5.2 准确率说明

- 仅 companynameparser 公布了针对单位名称的指标（且为自评、严格完全匹配）。
- 其余方案的准确率均为“通用 NER / 地址抽取”指标，**不能直接作为四要素拆解准确率**。
- CLUENER2020 数据集最佳模型 F1 约 83.6（CLUE 榜单），普通 BERT-base 约 78–80；这说明通用 NER 上限低于“规范企业名 + 规则”。

## 7 推荐实施路径（.NET）

### 7.1 总体架构

```
名称归一化（全半角、括号、空白、繁简）
        ↓
行政区划词典（Aho-Corasick 最长匹配，含简称 / 别名 / 园区）
        ↓
组织形式后缀词典（最长匹配）
        ↓
行业词典（GB/T 4754-2017 关键词 + 行业常用语）
        ↓
字号 = 首尾剥离后的剩余中间片段（校验 ≥ 2 汉字）
        ↓
顺序 / 长度 / 合法性校验 → 置信度评分
        ↓
低置信度进入人工复核队列（可选 LLM 候选建议）
```

### 7.2 词典与数据源（全部公开可商用）

| 词典 | 数据来源 | 用途 |
|---|---|---|
| 行政区划 | 民政部行政区划代码（省 / 地 / 县 / 乡四级，每年 1 月发布；2026 年起在国家地名信息库发布） | 地域词典 + adcode |
| 行业 | GB/T 4754-2017《国民经济行业分类》代码表（自行整理关键词，避免直接复制标准全文） | 行业词表 |
| 组织形式 | 《企业名称登记管理规定》及《企业名称申报指引（2025年版）》 | 后缀词表与排列规则 |
| 登记类型 | 市场监管总局《关于市场主体统计分类的划分规定》《关于划分企业登记注册类型的规定》 | “组织性质”独立字段（非名称字段） |
| 非企业单位 | 事业单位 / 机关 / 社会组织登记管理相关规定 | 局 / 委 / 办 / 院 / 校 / 所 / 中心 / 协会 / 学会 / 基金会等后缀 |

> 说明：GB/T 4754-2017 标准文本受版权保护，建议整理“代码 + 关键词”事实表使用，不直接复制标准全文。

### 7.3 匹配算法要点

1. **最长匹配 + 顺序约束**：行政区划只能出现在名称头部（或括号内）；组织形式必须在尾部；行业落在两者之间。
2. **字号最短化原则**：行业词匹配成功后，将“行业词左侧剩余部分”作为字号，避免把行业吞进字号。
3. **冲突打分**：当同一片段可同时命中地名与字号、或行业与字号时，按词典权重、位置、长度打分，低分转人工。
4. **园区别名表**：工业园区、开发区、新区、自贸区等单独维护，允许“苏州工业园区”整体作为地域。
5. **分支机构特例**：出现两个组织形式时，末尾为分支机构类型，前一个为主体组织形式。
6. **括号地域**：识别 `（武汉）`、`(武汉)` 形式并归入地域字段。
7. **幂等与可回溯**：输出命中词典项、字符偏移、置信度，便于复核与规则调优。

### 7.5 分阶段实施

| 阶段 | 内容 | 产出 |
|---|---|---|
| P1 | 用 companynameparser 离线跑历史数据，生成候选与基线 | 评测集初稿、字段分布统计 |
| P2 | C# 规则引擎 MVP：行政区划 + 组织形式 + 行业三本词典 | 可运行解析服务、单测 |

### 7.6 验收指标

- 字段级完全匹配率（按地域 / 字号 / 行业 / 组织形式分别统计）。
- 字级 F1（用于容忍“有限公司”与“有限责任公司”等等价表述）。
- 覆盖率（可解析比例）与人工复核率。
- 建议初始阈值：规范企业名称字段级 ≥ 90%；非企业单位 ≥ 75%；复核率 ≤ 15%。

### 7.7 与本仓库规范的边界

名称拆解输出的是**原始结构化字段**（地域代码、行业代码、组织形式枚举、字号文本），属于后端数据加工，不违反 `global-cache-layering-standard.md` 的 B-2；**枚举中文名、图标、展示拼接仍由前端公共层完成**。若解析结果需缓存，按 C-1~C-5 走 `ICacheService`，键含租户与数据版本。

## 8 风险与边界

| 风险 | 说明 | 应对 |
|---|---|---|
| 字号与行业边界歧义 | “精密机械厂”“建设银行”类名称 | 行业最长匹配 + 字号最短化 + 冲突打分 |
| 园区 / 开发区不在标准行政区划 | cpca 与多数词典均漏 | 单独维护别名表 |
| 无地域 / 无行业名称 | 华为技术有限公司 | 允许字段为空，禁止强行填充 |
| 非企业单位规则缺失 | 事业单位、机关、社会组织 | 独立后缀表与规则分支 |
| 名称 ≠ 事实 | 登记地、行业用语不代表实际经营 | 明确字段语义，禁止用于风控推断 |
| 所有制性质不可推断 | 名称不含“国有/民营/外资” | 依赖登记注册类型字段，不猜 |
| 第三方库停更 | companynameparser 2022 后无更新 | 仅作离线基线，不进生产运行时 |
