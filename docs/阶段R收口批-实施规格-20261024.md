## 一、总则（不可协商项）

1. **R-1 先行**：未完成版本控制初始化前不提交任何业务代码改动。
2. **每项完成即验证**：`dotnet build`（构建前先停 `Qlx.Host` 进程，规避 MSB3027 文件锁假失败）+ `dotnet test`（基线 848 只增不减），前端 `npx vitest run`（基线 108 只增不减）+ `npm run build`。
3. **缓存合规（C-x）**：所有读穿路径必须 `ICacheService.GetOrCreateAsync`；写路径只删缓存不写；键一律经 `QlxCacheKey`；TTL 必须有抖动（默认由提供方施加）；空值走 NullMarker。
4. **职责边界（B-x）**：后端只下发扁平原始字段 + 安全裁剪，树组装/格式化/枚举映射全部在前端公共层。
5. **校验（V-x）**：前端新增校验仅为 UX 预校验，后端 422 契约与独立校验一律保留。
6. **编码（N-x）**：本次不新增需要业务编码的实体；若涉及（如 R-9 配置项），编码由 `IEncodingGenerator` 生成，前端不传码。
7. **ID 混淆（G-3）**：所有对外 DTO 必须是具名 record/class，属性名 `Id` / 以 `Id` 结尾的 `long` 由 `QlxIdJsonMetadata` 自动 Hashids 化；禁止匿名对象承载业务 Id。
8. **响应契约（G-1）**：业务 API 统一 `ApiResponse<T>`（`{ code, data, message }`），前端统一经共享 `@/core/http` 解包。
