# ERPv3 多租户数据库模式补充设计

> 所属阶段：阶段二（支撑功能 B-0：多租户数据库模式）\
> 日期：2026-10-22（初版）；2026-10-24（回写）\
> 状态：✅ **已落地**（D10 混合租户数据库模式 / D11 三层隔离 / D12 四库分离 / D13 日志两层不复制 + 全局数据只存一份 均已在代码实现并通过测试；详见 §9.11 改造清单的实际实施状态与 `项目资产登记台账-20261024.md` 遗留项 L-02/L-03）\
> 定位：`docs/开发推进计划.md` 中 D10/D11/D12/D13 的展开说明，专题描述**固定四类库**的职责、流程、边界与改造清单。\
> **四库不变量**：全平台**始终只有四类库**——①共享库（所有租户都要用的库）②门户库 ③租户共享库 ④独立租户库。**禁止新增第五个库**（不设独立日志库、任务库、总日志库）；平台日志/审计并入门户库，Hangfire 队列并入共享库。\
> **日志不复制**：平台日志/审计只写门户库（`plog_*`），租户操作/登录日志只写本租户库（`log_*`），两侧互不复制、互不跨库直查；**审计只审计平台对租户的管理动作，租户内部操作不进平台审计**。\
> **全局数据只存一份**：平台推送的公告/任务/消息落在共享库（`glb_*`）**一份**，租户端用只读连接**优先读取共享库全局项**，再与租户库自建项合并；租户库只存「已读/完成/回执」状态，**不再每租户复制一份正文**。全局项租户不可拒收、不可删除，仅可标记已读/完成。\
> **本期范围**：只实现「门户管理员人工决定租户使用**租户共享库**还是**独立租户库**」；会员（付费）体系自动推荐为**预留设计**，不编码。\
> **不变量**：无论现在还是将来，**租户数据库模式切换必须由门户管理员人工确认并触发**，系统只提供推荐与预检，永不自动切换。

## 1. 目的与边界

### 1.1 要解决的问题

| #   | 问题              | 本文回答                                                                  |
| --- | --------------- | --------------------------------------------------------------------- |
| Q1  | 门户管理数据放在哪里      | 门户库（独立、唯一控制面）                                                         |
| Q2  | 小租户每个都建库成本太高怎么办 | 默认落租户共享库，一个库承载多个租户，用 `TenantId` 区分                                    |
| Q3  | 大租户有性能/合规诉求怎么办  | 升级为独立租户库，数据物理隔离                                                       |
| Q4  | 谁来定用哪种          | **门户管理员人工决定**（本期唯一判定来源）                                               |
| Q5  | 以后会员付费体系怎么接     | 预留 `ITenantDatabaseModePolicy` 扩展点：会员体系只产出「推荐建议」，仍由门户人工确认             |
| Q6  | 租户共享库下如何防跨租户越权  | 三层隔离（EF 过滤 + 写入守卫 + RLS + 巡检）                                         |
| Q7  | 日志放在哪里          | **两层、不复制**：平台日志/审计写门户库 `plog_*`；租户操作/登录日志写本租户库 `log_*`；不设独立日志库，也不下沉副本 |
| Q8  | 门户任务/消息如何到达租户   | 共享库 `glb_*` **只存一份**；租户用只读连接优先读取全局项，再合并租户库自建项；租户本地只存已读/完成状态，不复制正文     |
| Q9  | 审计范围到哪          | **只审计平台对租户的管理动作**（开通/升级/停用/许可/敏感查看）；租户内部操作只落租户日志，不进平台审计               |
| Q10 | 为什么不是每租户复制一份    | 租户数 × 消息数 = 写放大；副本漂移、撤回不一致、还要维护出站箱/幂等/死信；改为「全局数据一份 + 租户状态叠加」          |
| Q11 | 库会不会越加越多        | **不会**：固定共享库 / 门户库 / 租户共享库 / 独立租户库四类；日志、队列、全局消息都归入已有四库，禁止新增第五类库       |

| 本期做（P0）                                 | 预留不实现（P2）                                     |
| --------------------------------------- | --------------------------------------------- |
| 四库分离（门户库/共享库/租户共享库/独立租户库）与独立账号          | 会员等级 → 数据库模式自动推荐                              |

| 全局消息/任务在共享库 `glb_*` 只存一份，租户只读优先读取       | 租户拒收/退回平台任务消息                                 |
| 租户库只存已读/完成/回执状态（不复制正文）                  | 全局项按租户个性化改写                                   |
| 审计边界：只审计平台对租户的管理动作                      | 租户内部操作审计上报平台                                  |

### 1.3 明确不做（避免范围蔓延）

| 项                                       | 原因                                                                    |
| --------------------------------------- | --------------------------------------------------------------------- |
| **动态表前缀**（同一库内按租户切换表前缀）                 | EF 模型需按前缀缓存、每租户每模块各迁一次、表数量按「租户×模块」爆炸、跨租户运维困难；隔离效果与 `TenantId` 相同但成本翻倍 |
| 跨库 JOIN / 跨库事务                          | 门户库与租户库物理分离后无法保证；统计走事件/汇总表                                            |
| 门户库承载业务表                                | 控制面与数据面混淆，租户侧账号即可触达路由与加密凭据                                            |
| 租户共享库 `DROP DATABASE` / `EnsureDeleted` | 一次误删即全共享租户数据丢失                                                        |
| 降级（Isolated → Shared）                   | 会丢失隔离与审计链；需要时走导出 + 归档 + 重建租户                                          |
| 建「总日志库」或独立日志库/任务库                       | 库越拆越多、运维成本上升；日志并入门户库、队列并入共享库，固定四类库                                    |
| **每租户复制一份平台全局消息/任务**                    | 写放大（租户数 × 消息数）、副本漂移、撤回不一致；改为共享库一份 + 租户本地状态叠加                          |
| 平台直查租户日志/业务表                            | 控制面越权；平台只看下发登记与回执汇总，不直查租户 `log_`                                      |
| 租户内部操作进入平台审计                            | 平台只审计「对租户的管理动作」；租户内部审计由租户日志承担                                         |
| 新增第五个数据库                                | 任何新能力只能归入共享库/门户库/租户共享库/独立租户库                                          |

## 2. 术语与库定位

### 2.1 叫法统一（先消除歧义）

| 常见叫法           | 本文术语                          | 含义                                                        |
| -------------- | ----------------------------- | --------------------------------------------------------- |
| 公共库 / 共享库（含糊）  | **需按语境区分**                    | 指「所有租户都要用的平台级公共数据」→ **共享库**；指「多租户共用业务库」→ **租户共享库**        |
| 门户库、平台库、控制库    | **门户库（Portal DB）**            | 租户、用户、成员、模块许可、参数、路由、加密凭据 + 平台日志/审计（`plog_*`）；不存业务数据       |
| 共享库（所有租户都要用的库） | **共享库（Platform Shared DB）**   | 平台级公共数据：全局公告/任务/消息、消息模板、任务定义、公共字典 + Hangfire 队列表；平台写、租户只读 |
| 租户共享库、共享业务库    | **租户共享库（Shared Tenant DB）**   | 一个库承载 N 个租户，业务表用 `TenantId` 区分                            |
| 独立库、专有库        | **独立租户库（Isolated Tenant DB）** | 一个租户一个库，物理隔离                                              |
| 审计库、平台日志库、日志库  | **已取消**                       | 不设独立库；平台日志/审计并入**门户库** `plog_*`                           |
| 任务库            | **已取消**                       | 不设独立库；Hangfire 队列并入**共享库**                                |
| 租户日志           | **租户日志表（Tenant Log Tables）**  | 租户库内 `log_*` 表（租户共享库/独立库同结构、带 `TenantId`），租户自管            |
| 全局项            | **共享库** **`glb_*`**           | 平台推送的公告/任务/消息，只存一份，所有租户共享读取                               |
| 状态叠加           | **租户库** **`*_global_state`**  | 租户侧只存已读/完成/回执，引用 `GlobalId`，不复制正文                         |

> 结论：**门户库（控制面）≠ 共享库（平台公共数据面）≠ 租户共享库（租户业务面）**，三者物理分离。平台日志/审计是门户库的一部分，租户日志是租户库的一部分，**互不复制、互不跨库直查**；全局消息/任务在共享库只存一份，租户通过只读连接读取后与本地状态合并。

```text
                                         │ 读写（唯一写入口）

                          │  plog_ 平台日志/审计/回执      │
                          └───────┬──────────────┬───────┘
              路由行(租户共享)     │              │  路由行(独立)+加密凭据
                                  ▼              ▼
        ┌──────────────────────────────┐   ┌──────────────────────────────┐
        │ ③ 租户共享库 qlx_tenant_shared│   │ ④ 独立租户库 qlx_tenant_xxx   │

        │  *_global_state（状态叠加）    │   │  同左                          │
        └──────────────▲───────────────┘   └──────────────▲───────────────┘
                       │ 只读（租户侧）                     │ 只读（租户侧）
                       └──────────────┬───────────────────┘
                                      │
                          ┌───────────┴──────────────────┐
                          │  ② 共享库 qlx_shared          │  平台公共数据面
                          │  glb_ 全局公告/任务/消息/模板  │  平台写、租户只读
                          │  公共字典 + hangfire_* 队列     │
                          └───────────▲──────────────────┘
                                      │ 写（仅门户宿主）
                                      └── 门户管理端发布

  读取顺序（租户收件箱/任务列表）：
    1) 先读共享库 glb_* 的全局项（只读连接，按 GLOBAL 或目标 TenantId 过滤）
    2) 再读本租户库自建项 + *_global_state（已读/完成/回执）
    3) 应用层合并返回；禁止跨库 JOIN

  不复制清单：
    ✗ 平台消息/任务正文不复制进租户库
    ✗ 平台日志/审计不复制进租户库
    ✗ 租户日志不上报门户库
```

### 2.3 各库职责与运维属性

| 库                           | 角色          | 存什么                                                                                                                    | 连接来源                                                                                                 | 数据库账号                                       | 备份/恢复             | 故障影响                                    |
| --------------------------- | ----------- | ---------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------- | ----------------- | --------------------------------------- |
| ① 门户库 `qlx_portal`          | 控制面（唯一）     | `por_*` 全部表 + OpenIddict + **`plog_operation`/`plog_audit`/`plog_push_receipt`**                                       | `Qlx:Portal:PortalConnectionString`（固定）                                                              | 门户专用账号（建表/迁移/读写）                            | 最高等级（RPO 最小），单独备份 | 全平台不可用（登录、许可、路由全断）                      |
| ② 共享库 `qlx_shared`          | 平台公共数据面     | **`glb_*`**：全局公告/任务/消息、消息模板、任务定义、公共字典 + **Hangfire 队列表**                                                               | 写：`Qlx:PlatformShared:ConnectionString`（仅门户宿主）；读：`Qlx:PlatformShared:ReadOnlyConnectionString`（租户宿主） | 平台写账号 + **租户只读账号（仅 SELECT** **`glb_*`/视图）** | 独立备份（数据量小、可重建队列表） | 租户收件箱看不到全局项（本地项仍可用）、后台任务暂停；**不影响登录与业务** |
| ③ 租户共享库 `qlx_tenant_shared` | 数据面         | 业务表（`bas_/pur_/sal_/stk_/hr_/fin_/inv_/ctr_/prj_/eqp_/apr_/msg_/job_/log_/fil_/prt_`）+ `*_global_state`，全部含 `TenantId` | `Qlx:Tenancy:SharedDatabase`（固定）                                                                     | 业务读写账号，**无**建库权限                            | 整库备份，粒度=全共享租户     | 所有共享租户业务不可用；门户管理与全局收件箱仍可用               |
| ④ 独立租户库 `qlx_tenant_*`      | 数据面         | 同租户共享库表结构                                                                                                              | `por_tenant_databases` 路由行 + Data Protection 凭据                                                      | 每租户独立账号（理想）或共用业务账号（可接受）                     | 可按租户单独备份/恢复       | 仅该租户业务不可用                               |
| 租户日志表 `log_*`               | 数据面（位于租户库内） | 租户操作/登录日志（**仅本租户**，无平台副本）                                                                                              | 随所在租户库连接                                                                                             | 租户业务账号读写                                    | 随租户库备份            | 只影响该库日志可见性，不阻断业务                        |

> 全平台**只有以上四类库**（四行）；日志表、全局状态表、Hangfire 表分别归入已有四库，**不得为此新增数据库**。

| B10 | 全平台固定四类库，禁止新增第五个库                         | 配置校验：启动期断言连接串只对应四类库；评审新增库提案                                  |

## 3. 数据模型

### 3.1 模式枚举

| 枚举                   | 值              | 含义     |
| -------------------- | -------------- | ------ |
| `TenantDatabaseMode` | `Shared = 1`   | 落租户共享库 |
| <br />               | `Isolated = 2` | 落独立租户库 |

- `Tenant.DatabaseMode`：新增属性，默认 `Shared`。
- 领域方法 `Tenant.ChangeDatabaseMode(TenantDatabaseMode mode)`：**只允许** **`Shared → Isolated`**，其余组合抛 `BusinessException`。
- 存量租户迁移时回填 `Isolated`（保持现网行为不变）；新租户代码默认 `Shared`。

### 3.2 路由行语义（`por_tenant_databases`）

共享与独立**共用同一张路由表**，靠字段区分，避免解析器、详情页、升级任务出现两套查询：

| 字段                                        | 共享租户                                 | 独立租户                                | 说明                               |
| ----------------------------------------- | ------------------------------------ | ----------------------------------- | -------------------------------- |
| `TenantId`                                | 有                                    | 有                                   | 一对一                              |
| `DbHost` / `DbPort` / `DbName`            | 租户共享库主机/端口/库名（如 `qlx_tenant_shared`） | 独立库主机/端口/库名                         | 共享值可冗余存，便于排障                     |
| `EncryptedDbUser` / `EncryptedDbPassword` | **空**                                | 有（Data Protection 加密）               | 空表示「使用租户共享库统一连接」                 |
| `Status`                                  | `Active` / `Migrating`               | `Active` / `Migrating` / `Archived` | 复用现有 `TenantDatabaseStatus`      |
| `DatabaseMode`（新增）                        | `Shared`                             | `Isolated`                          | 冗余但可独立查询，避免每次 JOIN `por_tenants` |
| `PoolCode`（预留）                            | `default`                            | 空                                   | 未来多共享池时使用，本期固定 `default`         |

### 3.3 租户状态与数据库状态组合

| 租户状态                 | 数据库状态            | 含义           | 允许操作          |
| -------------------- | ---------------- | ------------ | ------------- |
| `Provisioning`       | `Migrating`      | 正在建库/迁移      | 等待；失败可重试      |
| `Active`             | `Active`         | 正常           | 登录、业务、升级      |
| `Active`             | `Migrating`（升级中） | 共享→独立复制/切换窗口 | 只读或短暂停写       |
| `Disabled`           | `Active`         | 租户被停用        | 不可登录；数据保留     |
| `Archived`           | `Archived`       | 归档只读         | 仅管理员导出        |
| `ProvisioningFailed` | `Migrating`      | 预配失败         | 门户重试；独立库保留待重试 |

| ---------------------------- | --- | --- | --------------- | ------------------------------------------------ |

| 字段                                | 所在表                   | 含义                                              |
| --------------------------------- | --------------------- | ----------------------------------------------- |
| `GlobalId`                        | 共享库 `glb_*`           | 全局项唯一标识，跨租户共享                                   |
| `Scope`                           | `glb_msg_messages`    | `GLOBAL`（所有租户）或 `TARGETED`（按 `TargetTenantIds`） |

## 5. 全流程

### 5.1 新租户开通（门户人工选模式）

```text
门户管理员填写租户信息 + 选择数据库模式（默认共享）
        │
        ├─ 模式 = Shared ─────────────────────────────────────────────┐
        │   1. 事务内写 por_tenants（DatabaseMode=Shared）              │
        │   2. 写 por_tenant_databases 路由行：                        │
        │      DbName=租户共享库名、凭据空、DatabaseMode=Shared、       │
        │      Status=Active、PoolCode=default                        │
        │   3. 写 por_tenant_modules（默认模块授权）                    │
        │   4. 写 por_tenant_members（首位管理员）                      │
        │   5. 写 por_license_records（授权轨迹）                       │
        │   6. 不建物理库；不触发独立库迁移任务                          │
        │   7. resolver.PreloadAsync/Invalidate 预热                     │
        │   8. 返回租户详情，模式=租户共享库                             │
        └──────────────────────────────────────────────────────────────┘
        │
        └─ 模式 = Isolated ───────────────────────────────────────────┐
            1. 事务内写 por_tenants（DatabaseMode=Isolated,           │
               Status=Provisioning）                                  │
            2. 写路由行：DbName=前缀+租户编码、凭据（可空=集成认证）、  │
               DatabaseMode=Isolated、Status=Migrating                │
            3. 写模块授权/成员/授权记录                               │
            4. 提交事务 → resolver.PreloadAsync 预热                    │
            5. TenantMigrationService 后台：建库 → 按模块迁移 →         │
               MarkTenantActive + MarkActive                          │
            6. 失败：MarkProvisioningFailed + 尝试次数+1；门户可重试    │
            └──────────────────────────────────────────────────────────┘
```

**关键约束**

| #    | 约束                                              |
| ---- | ----------------------------------------------- |
| F1-1 | 共享分支**绝不建库**，只写路由行；租户共享库必须已存在且已迁移（启动期保证）        |
| F1-2 | 两个分支都在**单事务**内完成门户库写入（租户 + 路由 + 模块 + 成员 + 授权记录） |
| F1-3 | 独立分支建库/迁移在事务外异步执行；失败不回滚门户记录，改为标记失败可重试           |
| F1-4 | 新建租户默认 `Shared`；页面明示「租户共享库成本低，独立库物理隔离」，并提示后期可升级 |
| F1-5 | 不允许新建时直接指定「独立库」以外的第三种模式                         |

### 5.2 登录与请求路由

```text
请求 → 认证（身份/租户 Token） → TenantContext 解析 tenantId
     → ITenantDatabaseResolver.Resolve(tenantId)
          ├─ 命中缓存：
          │    mode=Shared   → SharedDatabase 连接（固定）
          │    mode=Isolated → 路由行凭据解密后的连接
          └─ 未命中：抛 InvalidOperationException（快速失败，不放宽）
     → TenantDbContext.OnConfiguring 按连接串 UseSqlServer
     → 全局过滤 TenantId + 写入守卫 + （租户共享库）RLS 会话上下文
```

| #    | 规则                                                                              |
| ---- | ------------------------------------------------------------------------------- |
| F2-1 | 解析器只认 `por_tenant_databases`，不查 `por_tenants.DatabaseMode`（避免双写不一致）             |
| F2-2 | 共享租户在缓存中与独立租户同样占位，`Resolve` 不区分调用方                                              |
| F2-3 | 路由缺失/库不可用：返回明确业务错误码（`TENANT_DB_NOT_READY` / `TENANT_DB_UNAVAILABLE`），不返回 500 堆栈 |
| F2-4 | 升级切换完成后必须 `Invalidate(tenantId)` + `PreloadAsync`，否则旧连接继续指向租户共享库                |
| F2-5 | 门户管理请求（无租户 Token）不受租户库可用性影响                                                     |

### 5.3 租户共享库迁移（只执行一次）

```text
Host 启动
  → 门户库迁移（独立，正常执行）
  → 若存在共享租户或租户共享库已配置：
       获取数据库级应用锁（SQL Server: sp_getapplock，超时等待）
       逐模块按依赖拓扑迁移（bas → support → ...）
       每个模块写入独立历史表 __EFMigrationsHistory_{module}
       释放锁
  → 独立租户库按租户逐个迁移（租户共享库已完成的模块不重复跑）
```

| #    | 规则                                                                                |
| ---- | --------------------------------------------------------------------------------- |
| F3-1 | 租户共享库迁移**必须**在应用锁内执行；多实例并发启动时后者等待，不得跳过                                            |
| F3-2 | 租户共享库迁移只做 `Migrate`，**禁止** `EnsureDeleted` / `DROP DATABASE` / 重建库                |
| F3-3 | 租户共享库迁移失败：整体标记失败并告警；**不删库、不回滚已成功模块**，下次从断点继续                                      |
| F3-4 | 每模块独立历史表（`__EFMigrationsHistory_bas`、`__EFMigrationsHistory_support`…），独立库可继续共用单表 |
| F3-5 | 租户共享库表数量 = 一套业务表，不随租户数增长                                                          |

### 5.4 独立库预配与迁移

```text
Provisioning 租户扫描（后台，间隔 ScanIntervalSeconds）
  → 取租户 + 路由行
  → 若库不存在：用 master 连接 CREATE DATABASE（仅独立库）
  → 逐模块迁移（拓扑顺序、超时控制、失败计数）
  → 全部成功：TenantDatabase.MarkActive + Tenant.Activate
  → 失败：Tenant.MarkProvisioningFailed；超过 MaxRetryCount 告警
  → 首个模块即失败且为「本次新建的独立库」→ 可选清理（开关控制，默认关闭）
```

| #    | 规则                                                                              |
| ---- | ------------------------------------------------------------------------------- |
| F4-1 | 建库只允许在 `Isolated` 分支执行；共享分支直接返回                                                 |
| F4-2 | 迁移失败默认**保留库与已迁移表**，便于排障与重试；自动删库需显式配置 `AllowDropOnFirstModuleFailure=false` 默认关闭 |
| F4-3 | 升级产生的目标独立库同样走本流程，但租户状态不回到 `Provisioning`（由升级任务自身状态机管理）                          |
| F4-4 | 独立库连接信息变化（主机/端口/库名/账号）必须 `Invalidate` 缓存                                        |

### 5.5 共享 → 独立升级（本期人工触发）

**触发**：门户管理员在租户详情页点「升级为独立库」→ 二次确认（输入租户编码 + 选择目标库名/主机）→ 生成升级任务。

```text
① Preparing
   校验：租户存在且 mode=Shared；无进行中的升级；目标库不存在或为空
   写任务记录（状态机 Preparing）
   建目标库 + 按模块迁移（拓扑顺序）

② Copying
   按模块、按主键区间分批复制当前租户行（租户共享库 → 独立库）
   批量大小参数化（默认 1000 行/批）
   记录每表断点（表名 + 最后主键），失败可从断点续传
   复制期间租户共享库照常读写（后续靠增量补齐）

③ Verifying
   行数比对（每表 count）
   关键表抽样比对（按主键 hash 摘要）
   外键/唯一索引一致性检查
   不一致 → 任务失败，目标库保留供人工排查

④ Cutover（短窗口，建议分钟级）
   暂停该租户写入（返回 503/业务码，或全局只读开关）
   复制增量（按 UpdatedAt/RowVersion 补差）
   切换路由行：DbName/DbHost/凭据 → 目标库、DatabaseMode=Isolated、
              Status=Active
   提交门户库事务
   resolver.Invalidate + PreloadAsync
   恢复写入
   租户仍使用原 Token（tenantId 不变，无需重新登录）

⑤ Done
   写审计（操作人、耗时、复制行数、校验摘要）
   发消息通知门户管理员与租户管理员
   目标库成为正式库；租户共享库中的该租户行进入保留期（默认 30 天）后由
   `tenant.shared_data.clean` 清理（参数化）
```

| #    | 规则                                                           |
| ---- | ------------------------------------------------------------ |
| F5-1 | 只允许 `Shared → Isolated`；反向无接口、无任务、无按钮                        |
| F5-2 | 升级任务幂等：同一租户同时只允许一个升级任务（分布式锁 `tenant:upgrade:{tenantId}`）     |
| F5-3 | 任一步失败：路由仍指向租户共享库（租户无感），目标库保留供重试/人工排查                         |
| F5-4 | Cutover 前必须完成 Verifying；禁止跳过校验直接切换                           |
| F5-5 | 切换后必须失效解析器缓存；否则新请求仍写租户共享库导致双写分叉                              |
| F5-6 | 升级期间租户登录不受影响（身份认证走门户库）                                       |
| F5-7 | 不支持「升级后立即删除租户共享库数据」；保留期由参数 `tenant.shared.retention_days` 控制 |

### 5.6 降级（Isolated → Shared）

| 项      | 结论                               |
| ------ | -------------------------------- |
| 是否提供   | **不提供**                          |
| 需要时怎么做 | 导出数据 → 归档独立库 → 门户新建租户（共享模式）→ 导入  |
| 为什么    | 降级后数据与其它租户混放，隔离强度下降、审计链断裂、备份粒度丢失 |

### 5.7 租户停用 / 归档 / 删除

| 操作           | 共享租户                                       | 独立租户                      |
| ------------ | ------------------------------------------ | ------------------------- |
| 停用（Disabled） | 只改租户状态；数据不动                                | 同左                        |
| 归档（Archived） | 路由行置 `Archived`；业务表数据保留                    | 库置只读/离线，路由行 `Archived`    |
| 删除           | **只删该租户业务行**（按 `TenantId`，分批 + 审计），**不删库** | 库备份后物理删除，需双重确认 + 保留期 + 审计 |
| 门户记录         | `por_tenants` 逻辑删除保留（审计追溯）                 | 同左                        |

### 5.8 故障与降级

| 故障                       | 表现                           | 处理                           |
| ------------------------ | ---------------------------- | ---------------------------- |
| 门户库不可用                   | 全平台不可用                       | 最高优先级恢复；门户库独立备份/主从           |
| 租户共享库不可用                 | 共享租户业务全断；独立租户不受影响；门户管理可用     | 门户展示「租户共享库不可用」；租户请求快速失败并给业务码 |
| 共享库不可用（`glb_*`/Hangfire） | 租户收件箱看不到全局项、后台任务暂停；登录与业务不受影响 | 门户展示「共享库不可用」；收件箱降级为本地项并提示    |
| 某独立库不可用                  | 仅该租户业务断                      | 门户标记该租户数据库异常，其余正常            |
| 解析器缓存失效/未预热              | 请求报 `TENANT_DB_NOT_READY`    | 启动期强制预热；提供管理端「刷新路由缓存」        |

### 5.10 日志分层流程（不复制、不跨库）

```text
门户管理员/身份认证 ──► 门户库 plog_operation / plog_audit（写一次，唯一）
租户用户业务/登录   ──► 本租户库 log_operation / log_login（写一次，唯一）
                                  │
                                  └─ 平台不查、不抽、不汇总；租户日志不报门户

查询：
  平台日志/审计 → 门户管理端只读门户库 plog_*
  租户日志      → 租户端只读本租户库 log_*（L1 过滤 + RLS）
```

| #   | 规则                                                                               |
| --- | -------------------------------------------------------------------------------- |
| L-1 | 日志写入**不得阻塞主业务**：租户日志异步批量写；队列满降级本地缓冲并告警                                           |
| L-2 | **不做跨库复制**：平台日志不写租户库，租户日志不写门户库；无出站箱、无下沉任务、无死信重放                                  |
| L-3 | 敏感字段（凭据、密钥、Token）在两侧日志中**都必须脱敏**                                                 |
| L-4 | **平台审计不复制、不下发**：租户侧看不到平台审计原文                                                     |
| L-5 | 租户库不可用：只影响本租户日志写入（缓冲重试），门户操作不回滚；门户库不可用不影响租户日志                                    |
| L-6 | 保留期独立：门户日志按 `Qlx:Portal:Audit:RetentionDays`；租户日志按参数 `tenant.log.retention_days` |

### 5.11 平台全局消息 / 任务（只存一份 + 读取优先 + 状态叠加）

```text
发布（仅门户管理端）：
  门户管理端 → 写共享库 glb_msg_messages / glb_job_definitions（一份）
             → 平台审计 plog_audit 记「发布动作」
             → SSE 通知在线租户（只发 GlobalId，不发正文副本）

租户读取（优先共享库，再租户库）：
  1) 只读连接查 glb_*：Status=Published 且 (Scope=GLOBAL 或 TargetTenantIds 含本租户)
  2) 查本租户库：自建 msg_*/job_*（Source=Tenant）+ *_global_state（已读/完成）
  3) 应用层合并 → 返回收件箱/任务列表（正文来自共享库，状态来自租户库）

租户处理：
  标记已读/完成 → 写本租户库 msg_global_state / job_global_state
               → 经 POST /api/support/push/receipts 回传 → 门户库 plog_push_receipt

撤回/过期（仅平台）：
  glb_* 置 Revoked / Expired → 租户下次读取即不可见；历史状态保留，不删租户数据
```

| #   | 规则                                                             |
| --- | -------------------------------------------------------------- |
| P-1 | 全局项 `ForceAccept=1`，租户端**不可拒收、不可删除**，只能标记已读/完成；平台撤回是唯一例外       |
| P-2 | **不复制正文**：租户库只存 `*_global_state`（`GlobalId` + 状态）；新增租户无需补发历史副本 |
| P-3 | 租户停用期间全局项仍 `Published`；恢复后立即可见，不依赖任何补投任务                       |
| P-4 | 共享库只读连接**只允许 SELECT** `glb_*`/预置视图；禁止写入、禁止跨库 JOIN              |
| P-5 | 合并去重键 = `GlobalId`；同一全局项在收件箱只出现一次，状态以租户库为准                     |
| P-6 | 共享库不可用：收件箱降级为「仅本地项」并提示；业务功能不受影响                                |
| P-7 | 上行（回执/反馈/工单）走 API + 门户库 `plog_push_receipt`，禁止租户直连门户库          |

## 6. 隔离与安全

### 6.1 三层隔离适用矩阵

| 层       | 措施                                                    | 租户共享库                                                                              | 独立库  | 说明                         |
| ------- | ----------------------------------------------------- | ---------------------------------------------------------------------------------- | ---- | -------------------------- |
| L1 应用层  | EF 全局查询过滤（`TenantId`）                                 | 必须                                                                                 | 必须   | 独立库也保留，防止代码误用连接            |
| L1 应用层  | `TenantWriteGuardInterceptor`（自动填租户 / 禁改 / 拒绝跨租户更新删除） | 必须                                                                                 | 必须   | SaveChanges 拦截             |
| L1 应用层  | 缓存键统一 `tenant:{id}:` 前缀                               | 必须                                                                                 | 必须   | 租户共享库下漏加即串数据               |
| L2 数据库层 | RLS（SQL Server：`SESSION_CONTEXT` + Security Policy）   | 必须（能强制）                                                                            | 建议开启 | 独立库启用可作为纵深防御               |
| L2 数据库层 | 其他库 RLS                                               | PostgreSQL `set_config`+RLS；Oracle `DBMS_SESSION`+VPD；**MySQL 无原生 RLS → 降级 L1+L3** | 同左   | 能力标记 `RlsCapability`       |
| L3 检测层  | `TenantIsolationAuditor` 周期巡检                         | 必须                                                                                 | 建议   | 抽查跨租户可见性、策略覆盖、唯一索引         |
| L3 检测层  | 架构测试（实体含 TenantId、唯一索引含 TenantId、表归属）                 | 必须                                                                                 | 必须   | CI 红线                      |
| L3 检测层  | 越权回归用例                                                | 必须                                                                                 | 必须   | A 租户 Token 读 B 租户 → 空集/403 |

### 6.2 账号权限矩阵

| 账号           | 门户库                 | 共享库（`glb_*`）            | 租户共享库   | 独立租户库         | master            |
| ------------ | ------------------- | ----------------------- | ------- | ------------- | ----------------- |
| 门户应用账号       | 读写 + 迁移（含 `plog_*`） | 读写 + Hangfire（唯一写入口）    | 无       | 无（除预配期）       | 无                 |
| 共享库业务账号（租户侧） | 无                   | **只读** **`glb_*`/预置视图** | 无       | 无             | 无                 |
| 租户共享库业务账号    | 无                   | 无                       | 读写 + 迁移 | 无             | 无                 |
| 独立库业务账号      | 无                   | 无                       | 无       | 读写 + 迁移       | 无                 |
| 预配/运维账号      | 无                   | 无                       | 无       | 建库 + 迁移（仅任务期） | `CREATE DATABASE` |
| 租户用户         | **永不直接连库**          | 同左                      | 同左      | 同左            | 无                 |

> 开发环境可用同一 LocalDB/集成认证简化；**生产环境必须分账号**，启动期校验四类连接串账号互不相同，且租户侧共享库账号只有 SELECT 权限，否则告警（严格模式直接启动失败）。

### 6.3 租户共享库特有风险控制

| 风险             | 控制                                    |
| -------------- | ------------------------------------- |
| 噪声邻居（大租户拖慢小租户） | 参数化配额 + 慢查询告警 + 套餐 SLA；有强诉求的租户引导升级独立库 |
| 单表数据量          | 关键大表按 `TenantId` 建索引；分区/归档策略按租户       |
| 备份/恢复粒度        | 只能整库；恢复会回滚所有共享租户 → 升级独立库是唯一细粒度方案      |
| 误删/误改          | 写入守卫 + RLS + 禁止 DROP + 软删 + 审计        |
| 运维排障           | 所有业务表必须含 `TenantId` 且建索引，便于按租户过滤      |

### 6.4 日志与全局读取通道的隔离要求

| 项     | 要求                                                                                                              |
| ----- | --------------------------------------------------------------------------------------------------------------- |
| 账号    | 租户侧读共享库使用**只读账号**，与门户账号、租户业务账号均不同；只授予 `glb_*`/预置视图 SELECT                                                       |
| 会话上下文 | 读写租户库（含 `*_global_state`）必须带 `TenantId` 并设置 RLS 上下文；禁止无租户上下文批量写                                                 |
| 唯一索引  | `msg_global_state` 唯一索引 `(TenantId, GlobalMessageId, UserId)`；`job_global_state` 唯一索引 `(TenantId, GlobalJobId)` |
| 越权    | 平台日志查询只读门户库 `plog_*`；租户日志查询只读本租户 `log_*`；全局项读取只读 `glb_*`                                                        |
| 写边界   | 租户只写本租户库状态表，**永不写共享库**；平台只写门户库与共享库，**永不写租户库**                                                                   |
| 审计    | 「发布/撤回全局项」本身作为平台操作写入门户库 `plog_audit`，租户侧不可见                                                                     |
