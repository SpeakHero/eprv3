```
Step 1: 身份认证

  grant_type=urn:qlx:grant:portal_identity
  client_id=erp-web
  login_account=qlxadmin
  password=Qlx@2026
→ access_token + refresh_token + qlx_tenants (Hashids tenant_id)

Step 2: 换取 qlx-dev 租户级 Token

  Authorization: Bearer <identity_access_token>
→ tenant_access_token（后续所有 /api/support/* 调用的 Bearer 头）
```

### 1.2 审批中心 `/api/support/approvals`

#### 写操作 API

| # | 路由 | Method | 请求体 | 关键校验 |
|---|------|--------|--------|---------|
| A1 | `/start` | POST | `StartApprovalRequest` (Controller 端覆盖 InitiatorUserId 为当前用户) | ApprovalDefinitionCode 必须是已启用流程 |
| A2 | `/{instanceId}/approve` | POST | `ApprovePayload? { Comment? }` | 当前用户必须是当前节点待办人 |
| A3 | `/{instanceId}/reject` | POST | `RejectPayload { Reason }` | Reason 必填；当前用户必须是当前节点待办人 |
| A4 | `/{instanceId}/withdraw` | POST | `WithdrawPayload? { Reason? }` | 发起人本人；当前节点无任何人处理过 |
| A5 | `/{instanceId}/urge` | POST | `UrgePayload? { Message? }` | 当前节点存在待办任务 |
| A6 | `/{instanceId}/tasks/{taskId}/add-sign` | POST | `AddSignPayload { AddSignerUserId, Reason?, IsBeforeCurrent? }` | 当前任务节点 AllowAddSign=true |
| A7 | `/{instanceId}/tasks/{taskId}/transfer` | POST | `TransferPayload { ToUserId, Reason? }` | 转办目标必须是租户成员 |
| A8 | `/delegates` | POST | `SupportCreateDelegateRequest` | 委托期有效；BizTypes 空=全部 |
| A9 | `/delegates/{delegateId}/revoke` | POST | 无 | 仅委托人本人可撤销 |

#### 关键 DTO（API 请求体）

```jsonc
// A1 发起审批
{
  "ApprovalDefinitionCode": "flow.expense.claim",  // 4 条默认流程之一
  "BizType": "expense_claim",
  "BizId": "EXP-TEST-001",
  "BizNo": "EXP-20261023-0001",
  "Title": "差旅报销：北京-成都往返机票",
  "Description": "2026-10-20 业务出差",
  "BizData": { "total_amount": 3280.00 },  // 分支求值变量
  "FormJson": "{\"amount\":3280,\"attendees\":2}"
}
// → 返回 ApiResponse<string> = instanceId (Hashids 混淆串)

// A3 驳回
{ "Reason": "预算超标，请拆分后重新提交" }

// A6 加签
{ "AddSignerUserId": "WDR60al02yXA", "Reason": "法务意见重要", "IsBeforeCurrent": true }
```

#### 种子审批流程（租户懒种子自动种入）

| 流程编码 | 名称 | BizType | 节点数 | 条件分支 |
|---------|------|---------|--------|---------|
| `flow.purchase.request` | 采购申请审批 | pur_request | 3 | total_amount≥50000 跳过总经理 |
| `flow.expense.claim` | 费用报销审批 | expense_claim | 2 | total_amount≥5000 升级管理员 |
| `flow.contract.review` | 合同评审审批 | contract_review | 3 | 全员会签 |
| `flow.labour.salary` | 劳务工资表审批 | labour_salary | 2 | 全员会签 |

**发起审批前置**：流程定义 + 节点 + 分支由 `ApprovalFlowRegistry` 在首次查询时懒种子；无需人工预先初始化。

### 1.3 文件中心 `/api/support/files`

| # | 路由 | Method | 请求体 | 关键校验 |
|---|------|--------|--------|---------|
| F1 | `/upload` | POST (multipart/form-data) | `file` + `bizModule?` + `docType?` | 文件扩展名白名单；SYNC ≤ 100MB；ASYNC > 100MB |
| F2 | `/{id}` | DELETE | 无 | 软删进回收站；目录无存活子级 |
| F3 | `/{id}/restore` | POST | 无 | 回收站中存在 |
| F4 | `/acl/{id}/grant` | POST | `FileAclPayload { SubjectType, SubjectId, Permission }` | SubjectType: 1=用户/2=角色/3=组织；Permission: 位掩码 |
| F5 | `/acl/{id}/revoke` | POST | `FileAclPayload { SubjectType, SubjectId, Permission }` | 撤销该主体全部 Allow 授权 |

**上传 Curl 示例**：
```bash
curl -X POST "http://localhost:5002/api/support/files/upload?bizModule=pur&docType=contract" \
  -H "Authorization: Bearer $TENANT_TOKEN" \
  -F "file=@./invoice-2026.pdf"
```

**存储后端**：LocalFileStorageBackend，Root = `App_Data/files`（相对 Host 进程启动目录）。  
**ACL Payload**：
```jsonc
{ "SubjectType": 1, "SubjectId": "*", "Permission": 15 }  // 全部主体 + Read+Write+Delete+Manage
```

| # | 路由 | Method | 请求体 | 关键校验 |
|---|------|--------|--------|---------|
| J1 | `/trigger` | POST | `JobTriggerPayload` | taskCode 必须是已启用的服务任务；mode=sync/async |
| J2 | `/{executionId}/cancel` | POST | 无 | 仅 PENDING/QUEUED/RUNNING 可取消 |
| J3 | `/definitions/{taskCode}/toggle` | POST | `JobTogglePayload { Enabled }` | 启用=同时解除熔断暂停 |
| J4 | `/{executionId}` | GET | — | 查询执行状态 |
| J5 | `/{executionId}/logs` | GET | — | 执行日志（时间升序） |
| J6 | `/definitions` | GET | — | 当前租户任务定义清单 |

**触发 Curl 示例**（SYNC 阻塞等待完成）：
```bash
curl -X POST "http://localhost:5002/api/support/jobs/trigger" \
  -H "Authorization: Bearer $TENANT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"taskCode": "job.execution.clean", "mode": "sync"}'
```

**可选触发的内置任务**（无需 seed）：

| taskCode | 名称 | 模式 | 说明 |
|----------|------|------|------|
| `job.execution.clean` | 执行记录清理 | SYNC | 清理 >30 天的 job_executions |
| `file.temp.purge` | 临时文件清理 | SYNC | 删除 >7 天临时目录文件 |
| `file.recycle.cleanup` | 回收站清理 | SYNC | 删除 >30 天回收站文件 |
| `audit.archive` | 审计归档 | SYNC | 归档 >90 天审计日志 |
| `session.clean` | 会话清理 | SYNC | 清理过期会话 |
| `file.chunk.assemble` | 分片合成 | ASYNC | 合成上传分片（ASYNC 模式） |
| `file.format.convert` | 格式转换 | ASYNC | 文档格式转换（ASYNC 模式） |
| `job.schedule.dispatch` | CRON 调度 | ASYNC | 分发 CRON 任务（Hangfire） |
| `message.archive.run` | 消息归档 | ASYNC | 归档 >90 天消息 |
| `message.send.digest` | 消息摘要 | ASYNC | 定时发送消息摘要 |
| `approve.timeout.scan` | 审批超时扫描 | ASYNC | 扫描超时审批任务 |

**注意**：CRON 调度（Hangfire）在开发环境用内存存储，Host 重启丢失；需改为 SqlServer 存储验证跨重启持久化。当前 SYNC 模式任务不依赖 Hangfire，可直接验证。

### 1.5 打印中心 `/api/support/printing/templates`

| # | 路由 | Method | 请求体 | 关键校验 |
|---|------|--------|--------|---------|
| P1 | `/` | POST | `PrintTemplateCreatePayload` | 租户内模板编码唯一；初始状态 Draft |
| P2 | `/{id}` | PUT | `PrintTemplateUpdatePayload` | 内容变更版本自增 |

| P4 | `/code/{code}/render` | POST | 请求体即模板变量 JSON | 仅 Enabled 态模板；Scriban 语法 + `qrcode:xxx` 占位符 |

**模板创建 Curl 示例**：
```bash
curl -X POST "http://localhost:5002/api/support/printing/templates" \
  -H "Authorization: Bearer $TENANT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "TemplateCode": "po.v1",
    "Name": "采购订单打印模板 V1",
    "BizType": "pur_order",
    "ContentHtml": "<h1>采购订单 #{{ order_no }}</h1><p>供应商: {{ supplier_name }}</p><div>{{ qrcode: order_no }}</div>",
    "Css": "h1 { color: #1a5caa; }"
  }'
```

**渲染 Curl 示例**：
```bash
# 先启用模板 P3
curl -X POST "http://localhost:5002/api/support/printing/templates/{id}/status" \
  -H "Authorization: Bearer $TENANT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"Status": 1}'

# 再渲染
curl -X POST "http://localhost:5002/api/support/printing/templates/code/po.v1/render" \
  -H "Authorization: Bearer $TENANT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "order_no": "PO-2026-10001", "supplier_name": "XX 科技有限公司" }'
# → 返回 ApiResponse<string> = 渲染后的 HTML（含 base64 二维码）
```

### 1.6 信息中心 `/api/support/messages`

> **关键说明**：信息中心**没有直接发送消息的 API**。消息写入由审批终态、任务执行完成/失败、系统公告等业务事件触发。写操作聚焦于**收件箱管理**和**订阅管理**。

| # | 路由 | Method | 请求体 | 关键校验 |
|---|------|--------|--------|---------|
| M1 | `/inbox/{inboxId}/read` | POST | 无 | inboxId 必须属于当前用户 |
| M2 | `/read-all` | POST | 无 | 当前用户全部收件箱项标记已读 |
| M3 | `/inbox/{inboxId}/delete` | POST | 无 | 软删收件箱项 |
| M4 | `/sent/{messageId}/retry` | POST | 无 | 仅发送方；强制重试渠道投递 |
| M5 | `/global/{globalId}/state` | POST | `GlobalItemStatePayload { State }` | State: READ/ACCEPTED/DELETED |
| M6 | `/subscriptions/{msgType}/toggle` | POST | `SubscriptionTogglePayload { Enabled }` | TODO/URGE 强制订阅拒绝关闭 |
| M7 | `/stream` | GET (SSE) | — | 需租户级 Token；Last-Event-ID 续传 |

**消息驱动来源**（用于测试前的数据准备）：

| 触发源 | 产生消息 | 验证方式 |
|--------|---------|---------|
| 审批终态（Complete/Reject/Withdraw） | 通知发起人 | 发起审批 → 完成/驳回 → GET /inbox |
| 后台任务执行失败 | 告警通知 | 触发 SYNC 任务并制造异常 → GET /inbox |
| 系统公告（平台写 glb_messages） | 全局消息 | SSE 订阅 → 平台发布 → 客户端实时接收 |
