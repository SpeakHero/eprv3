## 项目需求背景

### 〇、文档定位与架构基线

本文档为**业务开展层**文档，定义淇利馨集团全流程数字化运营管理平台的业务需求。系统核心技术底座以《SaaS ERP v3 架构需求规格说明书》（saas-architecture-spec.md）为**核心基础**，淇利馨集团作为平台租户落地全部业务。架构映射关系：

| 业务概念（本文档） | SaaS 架构机制（架构规格） |
|-------------------|--------------------------|
| 淇利馨集团（含各子公司） | 平台**租户（Tenant）**，独立数据库物理隔离 |
| 「集团-子公司-部门-项目」四级组织 | 租户内**组织树 + 数据权限范围**（分级授权原则的落地机制） |
| 八大业务模块 + 三个扩展模块 | 门户授权的**租户模块许可（tenant_modules）**，门户统一启停 |
| 登录与统一身份（第六章） | 架构规格 6.x：三阶段登录（身份认证→租户选择→Token）、右上角身份直切、外部 IdP/SSO |
| 系统管理员/集团管理员 | 租户内角色体系（tenant_admin / 自定义角色），门户不参与租户内部管理 |
| 审批留痕、操作日志、审计日志 | 日志双层：租户库 `log_*`（租户自管）+ 门户日志库（平台日志/平台审计）；平台审计只审计平台对租户的管理动作 |
| 通知中心、流程配置中心 | 租户内平台级共享服务 |

**职责边界**：业务规则与流程变更在本文档演进；多租户、身份、权限、模块许可等架构机制变更在架构规格演进，二者冲突时以架构规格为准。

### 一、企业概况

四川淇利馨集团有限公司是一家聚焦建筑产业链的多元化集团企业，以四川淇利馨企业管理有限公司为控股主体，下辖四川淇利馨贸易有限公司、四川淇利馨建筑劳务有限公司两家核心业务子公司，形成「贸易 + 劳务 + 管理」一体化业务布局，核心经营范畴包括：

- **贸易板块**：建筑材料、金属结构、机电设备、劳保用品等物资的批发与零售，配套供应链管理、仓储服务、工程设备租赁等，服务川渝区域建筑工程项目与商贸客户；
- **建筑劳务板块**：建筑劳务分包、工程管理服务、劳务人员派驻与管理，承接各类建筑工程劳务作业；
- **集团管理板块**：全集团的人事行政、财务管理、票据管控、经营决策与风险管控。

集团业务链路贯穿**供应商采购→仓储物流→销售/劳务交付→财务结算→票据核销**全流程，涉及多组织、多部门、多岗位协同，对流程合规、分级管控、数据准确性要求高。

### 二、数字化转型动因与核心痛点

当前集团运营仍以线下纸质流程 + Excel 台账为主，数字化程度较低，随着业务规模扩张与组织层级完善，现有模式已无法满足精细化管控与合规经营要求，核心痛点如下：

1. **流程线下流转，审批效率低下且管控缺失**  
   采购申请、销售定价、费用报销、人事异动、劳务用工、款项支付等所有业务均依赖纸质单据线下签字，审批层级多、跨公司/跨部门流转慢、周期长；审批规则不透明，无法按金额大小、业务类型、风险等级实现差异化分级管控，存在越权审批、流程跳级风险，且审批过程无完整留痕，事后无法追溯。

2. **数据孤岛严重，业财数据脱节**  
   采购、销售、仓储、劳务、财务、人员数据分散在不同人员的 Excel、纸质台账中，数据标准不统一、更新不同步；业务单据与财务凭证、票据信息脱节，对账成本高、差错率高，无法实现业财票一体化联动。

3. **全链路管控能力不足，经营风险滞后**  
   采购价格、库存周转、销售回款、劳务成本、费用支出缺乏实时管控手段；商品与物资出入库无系统化校验，劳务人员异动无闭环流程，容易出现库存账实不符、成本超支、用工风险等问题，风险发现滞后，无法前置管控。

4. **票据管理混乱，合规风险高**  
   进项发票、销项发票、费用票据、劳务票据以纸质管理为主，存在丢失、重复报销、真伪核验难等问题；票据与业务单据无法一一对应匹配，税务合规与审计追溯难度大，不符合财税监管要求。

5. **经营决策缺乏数据支撑**  
   全集团经营数据无法实时汇总，管理层不能及时掌握采购成本、销售毛利、库存周转、劳务效能、资金状况等核心指标，决策依赖经验与滞后报表，无法快速响应市场与业务变化。

### 三、项目建设目标

本项目旨打造集团统一的**全流程数字化运营管理平台**，覆盖所有子公司与全部业务板块，实现「业务全线上、流程全审批、数据全贯通、风险全可控」的全数据化转型，具体目标：

1. **流程线上化**：基础信息、采购、销售、物流、商品、人员、财务、票据八大业务流程线上办理，替代线下纸质流转，实现业务申请-审批-执行-归档全闭环；
2. **审批层级化**：建立「集团-子公司-部门-项目」四级审批体系，支持按业务类型、金额区间、风险等级灵活配置多级审批、联合会签、条件流转、驳回重审，全程留痕可追溯；
3. **数据一体化**：打通各业务模块数据，实现业务、财务、票据数据同源联动，一处录入、全链路共享，消除数据孤岛；
4. **管控精细化**：实现分级授权、数据隔离、风险前置管控，所有业务节点可配置、可监控、可预警；
5. **决策数据化**：构建集团统一经营数据视图，实时输出多维度报表与分析指标，支撑管理层经营决策。

### 四、核心业务覆盖范围

平台覆盖集团全价值链八大核心业务模块，支撑全流程数字化管控，其中「基础信息中心」为所有业务模块提供统一、唯一的基础数据底座。另设**合同管理、项目管理、设备与租赁管理**三个扩展业务模块，贴合建筑集团「以合同为依据、以项目为核算单元」的经营实际，按业务成熟度分阶段建设。

#### 4.0 全模块通用能力要求

为避免各模块重复建设，以下能力由平台统一提供，各业务模块直接接入：

| 通用能力 | 需求说明 |
|---------|---------|
| 统一审批流引擎 | 所有业务单据统一接入审批引擎，支持按单据类型、金额区间、组织层级配置审批链；支持逐级审批、跨级驳回、加签、会签、委托代办、催办；审批记录全程留痕（操作人、时间、意见、IP） |
| 统一单据编号 | 单据号全局规则：`业务前缀 + 组织码 + 年月 + 流水号`（如 CG-SQ-2026-10-0001），连续不重复，作废不回收 |
| 统一单据状态机 | 单据生命周期：草稿 → 待审批 → 审批中 → 已生效 / 已驳回 → 执行中 → 已完成 / 已作废；状态流转由事件驱动，不允许越级跳变 |
| 统一导入导出 | 各列表页支持 Excel 模板导入、筛选结果导出；导入需校验编码合法性与数据权限 |
| 统一打印模板 | 各单据提供标准打印模板（支持公司抬头、审批签章区、二维码溯源） |
| 统一操作日志 | 单据的新增、修改、删除、审批、作废全量记录，可按单据反查操作历史 |

#### 4.1 基础信息中心

**模块定位**：全平台唯一基础数据底座，所有业务模块引用其数据，禁止各模块私自维护副本。

> **详细需求**：[模块需求/01-基础信息中心.md](模块需求/01-基础信息中心.md)（页面级功能、实体字段、规则 R1-R10、审批链、权限点、期初方案）

| 功能子项 | 需求拆解 | 关键管控点 |
|---------|---------|-----------|
| 组织架构管理 | 「集团-子公司-部门-项目」四级树型结构维护：新增/调整/合并/停用节点；每个节点含编码、名称、负责人、上级节点、生效日期 | 编码全局唯一；停用节点须无在办业务与在职人员；结构调整保留历史版本（可按日期回看任意时点架构） |
| 岗位管理 | 岗位档案（编码、名称、所属组织、职责说明）、编制数设定、在岗人数实时统计 | 超编制入职/调入时强制走集团审批（审批流程引擎自定义）；岗位停用需先完成人员安置 |
| 商品分类与编码规则 | 多级商品分类树（如：建材→钢材→螺纹钢）；定义分类编码规则（分类码+流水码）；维护计量单位及换算关系（吨/千克、件/箱） | 分类编码全局唯一，已被商品引用的分类禁止删除；单位换算关系变更需留痕 |
| 供应商档案 | 基本信息、营业执照与资质证书影像、银行账户、开票信息、合作记录；供应商评级（A/B/C/黑名单）与评级历史 | 新供应商必须经准入审批方可被采购引用；黑名单供应商全局禁采；银行账户/开票信息变更需审批留痕 |
| 客户档案 | 基本信息、信用等级与信用额度、回款账户、开票信息、合作记录 | 新客户准入审批；信用额度调整走分级审批；信用等级下调自动触发在售订单复检 |
| 人员主数据 | 员工与劳务人员两类：基本信息、身份证件、联系方式、紧急联系人、关联组织与岗位、入离职状态 | 身份证号全局唯一防重；人员主数据仅本人/HR/授权管理员可见，敏感字段（证件号、银行卡）脱敏展示 |
| 数据字典 | 全平台枚举统一维护（单据类型、币种、税率、付款方式、行业分类等）支持租户级别的自定义，每个租户可维护独立的字典项（如：币种、税率、付款方式）；支持集团级与子公司级两级字典 | 集团级字典子公司只读；字典项被引用后禁止物理删除，仅可停用 |
| 统一编码体系 | 组织码、商品码、供应商码、客户码、人员工号、单据号的编码规则集中定义与发放 | 编码规则一经启用不可修改规则本身，仅可调整流水区段；保证全局唯一、可追溯 |

#### 4.2 采购管理

**模块定位**：覆盖「需求→申请→订单→入库→对账→付款」采购全链路，联动基础信息中心（供应商/商品）、商品管理（库存）、财务管理（应付/付款）、票据管理（进项发票）。

> **详细需求**：[模块需求/02-采购管理.md](模块需求/02-采购管理.md)

| 功能子项 | 需求拆解 | 关键管控点 |
|---------|---------|-----------|
| 采购申请 | 需求部门/项目发起，支持按商品明细批量填写数量、期望单价、期望交期、用途说明；支持从库存预警一键生成补货申请 | 按金额区间自动匹配审批链（如 5 万以下部门级、5-50 万子公司级、50 万以上集团级）；关联部门预算，超预算预警或强制升级审批 |
| 询比价管理 | 对采购申请发起询价，登记多家供应商报价，生成比价表 | 比价结果需审批确认；成交价高于历史采购均价 N% 时强制附加说明并升级审批 |
| 采购订单 | 由已批准申请生成或手工创建；含价税分离（税率、税额、价税合计）、交付批次、收货仓库、付款条款；支持订单变更与关闭 | 订单生效前必须审批；供应商黑名单/资质到期自动拦截下单；变更金额超原订单 10% 重新走审批 |
| 采购入库 | 到货登记 → 数量清点 → 质量验收 → 生成入库单；支持分批到货、差异登记（短交/超交/破损） | 入库数量不得超订单剩余可入量（超交需单独审批）；验收合格后库存即时增加；入库单自动生成财务应付暂估 |
| 采购退货 | 基于入库单发起退货申请，登记退货数量、原因、责任方 | 退货出库联动库存扣减与应付冲减；需原审批链同级审批 |
| 采购对账 | 按供应商/账期汇总「订单-入库-发票」三单对账，生成对账单 | 三单不符（数量、单价、税率差异）必须逐笔说明后方可提交；对账单确认后转应付账款 |
| 采购结算 | 对账单关联付款申请，联动财务模块付款与核销 | 付款金额不得超对账确认金额；支持预付款、进度款、质保金分期管理 |

#### 4.3 销售管理

**模块定位**：覆盖「报价→订单→出库→回款」销售全链路，强化定价审批与信用管控，联动客户档案、库存、财务应收、销项票据。

> **详细需求**：[模块需求/03-销售管理.md](模块需求/03-销售管理.md)

| 功能子项 | 需求拆解 | 关键管控点 |
|---------|---------|-----------|
| 销售报价 | 报价单（客户、商品明细、报价、税率、有效期）；报价版本管理与历史查询 | 低于成本价或指导价下浮超 N% 的报价强制升级审批；报价超有效期自动失效 |
| 销售订单 | 由报价单转化或手工创建；含交付计划、收货地址、回款条款；支持变更与关闭 | 下单自动校验客户信用额度与在途应收，超额冻结提交并提示走特批；毛利为负订单强制集团审批 |
| 销售出库 | 发货申请 → 仓库拣货 → 出库核验 → 客户签收登记；支持分批发货 | 出库数量不得超订单剩余量；信用超额客户出库需特批放行；出库即生成应收与库存扣减 |
| 销售退货 | 退货申请、质检入库、退款/换货处理 | 退货需核对原出库单；退款走财务付款流程；退货入库联动库存与应收冲减 |
| 销售对账 | 按客户/账期生成对账单（发货明细、退货明细、已回款明细） | 客户确认（线上确认或线下盖章回传影像）后转应收核销依据 |
| 回款管理 | 回款计划（按订单条款自动生成）、到账登记、认领核销、逾期台账 | 回款逾期自动预警并通知业务负责人；逾期超 N 天自动下调客户信用等级；支持一笔回款拆分核销多笔订单 |

#### 4.4 物流管理

**模块定位**：承载仓储实物的「收、发、存、转、配」作业管理，与商品管理共享库存数据，支撑跨项目、跨公司物资调度。

> **详细需求**：[模块需求/04-物流管理.md](模块需求/04-物流管理.md)

| 功能子项 | 需求拆解 | 关键管控点 |
|---------|---------|-----------|
| 仓库档案 | 仓库/库区/库位三级档案，关联所属组织（公司/项目）；仓库类型（自有/租赁/项目临时仓） | 仓库编码全局唯一；停用仓库需先清空库存 |
| 入库作业 | 承接采购入库、退货入库、调拨入库、盘盈入库四类来源；作业单含清点、上架库位登记 | 所有入库必须有来源单据，禁止无单入库；上架完成后库存可售 |
| 出库作业 | 承接销售出库、采购退货出库、调拨出库、盘亏出库、领用出库；含拣货、复核、交接登记 | 出库前校验库存可用量，禁止负库存；大额出库（按金额阈值）需审批 |
| 物资调拨 | 跨仓库/跨项目/跨公司调拨申请 → 审批 → 调出方发货 → 在途跟踪 → 调入方收货确认 | 跨公司调拨自动升级至集团审批；在途库存独立台账，超 N 天未确认收货自动预警 |
| 配送管理 | 配送单（关联出库单）、车辆/司机登记、路线与签收；支持客户/项目签收影像上传 | 签收完成后订单状态自动推进；签收差异（短少/破损）登记并转入异常处理 |
| 库存盘点 | 盘点计划（按仓库/品类/周期）、初盘/复盘录入、差异处理（盘盈盘亏单） | 盘点期间冻结相关库存异动；盘盈盘亏单必须审批后方可调整账面库存 |
| 库存预警 | 安全库存上下限、库龄/积压预警、临期批次预警（如有批次效期） | 预警触发自动推送通知中心，并可一键生成采购补货申请或调拨建议 |

#### 4.5 商品管理

**模块定位**：维护商品/物资主档案与库存价值台账，是采购、销售、物流、财务成本核算的共同数据源。

> **详细需求**：[模块需求/05-商品管理.md](模块需求/05-商品管理.md)

| 功能子项 | 需求拆解 | 关键管控点 |
|---------|---------|-----------|
| 商品档案 | 承接基础信息中心的分类与编码规则，维护具体商品：规格型号、条码、计量单位、批次属性（是否启用批次/效期）、默认税率、参考成本价、指导价 | 商品编码全局唯一；已被业务单据引用的商品禁止删除仅可停用；关键字段（税率、单位）变更需审批 |
| 期初建账 | 系统上线初期库存期初录入（数量、单价、金额），按仓库分批录入 | 期初数据经审批后一次性过账，过账后不可直接修改，只能通过调整单修正 |
| 库存台账 | 实时库存（数量、单价、金额）按「商品×仓库」维度；支持移动加权平均计价 | 台账由出入库单据自动驱动，禁止手工直接改台账；所有变动可反查来源单据 |
| 出入库流水 | 全量流水查询：单据号、类型、数量、单价、金额、经办人、时间 | 流水不可删除；提供按商品/仓库/时间/单据类型的多维筛选与导出 |
| 成本调整 | 因价格差错、盘盈盘亏等原因发起成本调整单 | 调整必须附原因与审批；调整影响自动同步财务成本核算 |

#### 4.7 财务管理（整体参考柠檬云成熟的做法）

**模块定位**：承接各业务模块生成的财务数据，实现凭证、报销、资金、成本、往来、报表一体化，支撑业财联动与预算管控。

> **详细需求**：[模块需求/07-财务管理.md](模块需求/07-财务管理.md)

| 功能子项 | 需求拆解 | 关键管控点 |
|---------|---------|-----------|
| 凭证管理 | 手工凭证录入；业务单据（入库、出库、报销、收付款）按凭证模板自动生成凭证；凭证审核、过账、红冲 | 自动凭证模板可配置（单据类型→科目映射）；已审核凭证禁止直接修改，只能红冲调整 |
| 费用报销 | 报销单（费用类型、明细、关联票据影像）、个人借款冲抵、报销进度查询 | 费用标准按职级/费用类型配置，超标强制附加说明并升级审批；票据管理模块自动查重，同一张发票禁止二次报销 |
| 付款申请 | 采购付款、费用付款、预付款、保证金付款统一入口；关联合同/订单/对账单 | 付款必须关联已生效业务依据；大额付款按金额分级审批；付款完成后自动回写业务单据结算状态 |
| 收款管理 | 到账登记、客户回款认领、核销应收账款 | 未认领款项挂账预警；核销关系可追溯（回款↔订单↔发票） |
| 成本核算 | 按项目/订单归集直接成本（材料、劳务、费用），输出成本明细与毛利分析 | 成本数据自动取数自采购、库存、劳务结算，禁止手工平调；月末结转需财务负责人审批 |
| 往来账款 | 应收账款、应付账款台账；账龄分析（30/60/90/180 天） | 超账龄自动预警；坏账计提走审批流程 |
| 预算管控 | 年度/月度预算编制（按组织、费用类型）、预算执行占用、执行率分析 | 报销与采购申请提交时实时校验预算余额；超预算单据自动升级审批链 |
| 银行账户与资金管理 | 银行账户台账（基本户/一般户/农民工工资专户等）、账户余额登记、银行流水导入与对账、资金日报 | 开销户需审批；银行流水与账面逐笔勾对，差异限期处理；专户资金用途受限管控，禁止挪用 |
| 资金计划 | 月度资金收支计划编制（按公司/项目）、计划执行跟踪、资金缺口预警 | 付款申请纳入资金计划校验，无计划或超计划付款强制升级审批 |
| 承兑汇票管理 | 应收/应付承兑汇票台账（票号、出票人、承兑行、金额、到期日）、收票登记、背书转让、贴现、到期托收全流程登记 | 票据到期前自动预警；背书转让需审批并与应付账款联动核销；逾期未托收票据进入异常清单 |
| 财务报表 | 资产负债表、利润表、现金流量表；管理报表（资金日报、应收应付汇总、费用分析） | 集团层可合并各子公司报表；报表数据可下钻至凭证与业务单据 |

#### 4.8 票据管理

**模块定位**：实现「进项、销项、费用、劳务」四类票据全生命周期管理，与业务单据一一关联，满足税务合规与审计追溯。

> **详细需求**：[模块需求/08-票据管理.md](模块需求/08-票据管理.md)

| 功能子项 | 需求拆解 | 关键管控点 |
|---------|---------|-----------|
| 进项发票 | 发票采集（扫描/OCR 识别/手工录入/税局接口按需对接）、真伪查验、认证抵扣登记 | 发票代码+号码全局查重；查验结果（真伪、状态）留痕；认证抵扣状态按月汇总 |
| 数电票适配 | 全面数字电子发票（数电票）的接收、查验、用途确认与归档；销项数电票开具登记 | 数电票以 20 位发票号码唯一查重；XML/OFD 版式源文件归档保存，满足电子会计凭证存档合规要求 |
| 销项发票 | 开票申请（关联销售订单/对账单）→ 审批 → 开票登记 → 交付记录；红字发票申请与红冲 | 开票金额不得超订单可开票余额；红冲必须关联原蓝字发票并审批 |
| 费用票据 | 报销场景票据的采集、查验、与报销单关联 | 与费用报销联动查重，杜绝一票多报；票据影像强制上传 |
| 劳务票据 | 劳务公司开具的劳务发票、完税凭证登记与核验 | 与劳务结算单一一对应；未收齐合规票据的结算款挂起不付 |
| 票据匹配 | 「订单/入库单/发票」三单匹配、「销售单/出库单/发票」匹配，匹配结果台账 | 不匹配项进入异常清单，限期处理；匹配关系支持双向追溯（票查单、单查票） |
| 税务台账 | 进销项发票汇总、税额统计、税负率分析、申报辅助数据输出 | 台账按月锁定；输出格式满足报税取数要求 |
| 归档管理 | 票据影像与实物归档（归档号、存放位置）、借阅登记与归还跟踪 | 归档后票据只读；借阅超期未还自动预警 |

### 六、登录与统一身份（参考电子税务局）

登录与身份体系完全参考电子税务局成熟交互，详细设计见 doc/登录体系产品设计文档.md 与 doc/登录体系技术架构文档.md：

1. **多合一登录**：单一登录入口，企业标识（租户号/企业自定义名称，选填）搭配账号（用户名/手机号/身份证号任一）与密码完成身份校验，无需区分不同登录类型的单独入口；
2. **企业直达与选择**：登录时填写了企业标识的，认证通过后直接进入该企业，不展示选择页；未填写企业标识的，登录成功后统一展示关联企业列表供选择，仅关联一个企业时直接进入；
3. **右上角身份直切**：无论以何种方式登录，进入工作台后右上角始终展示全部可切换身份（企业 × 角色），点击免密直接切换（含跨企业），即选即生效，交互参考电子税务局身份切换；
4. **前端技术栈**：登录页、企业选择页、工作台及全部业务页面统一采用 Vue3 + TypeScript + Element Plus，页面 UI、交互逻辑、布局规范参考电子税务局；
5. **页面架构**：整体分为顶部导航栏、横向模块导航条（悬停展开完整菜单）、主内容区三部分（电子税务局式布局，2026-10-16 决策），主内容区复用浏览器原生多标签页承载各业务页面，禁止单独开发自定义标签页组件；
6. **跨标签页一致性**：重点解决跨标签页的数据同步、状态共享、事件通信问题，同一企业多标签页身份一致、操作无状态冲突；
7. **账号安全**：密码哈希存储，连续失败锁定，会话滑动过期，登录与身份变更全程审计留痕。

### 七、核心管控原则

1. **层层审批原则**：所有业务单据必须经对应层级审批后方可生效，无审批或审批不全的业务不得进入下一环节；支持逐级审批、跨级驳回、委托代办、加签会签等多种审批模式，审批过程全程留痕，记录操作人、操作时间、审批意见。
2. **分级授权原则**：基于四级组织架构实现权限分级隔离，不同层级、不同岗位人员仅可查看与操作授权范围内的功能与数据；子公司数据独立隔离，集团层可汇总查看与跨公司审批。
3. **全链路追溯原则**：支持从业务单据→审批记录→出入库凭证→财务凭证→票据影像的全链路反向追溯，满足审计、合规与财税管控要求。
4. **数据唯一原则**：核心基础数据（商品、客户、供应商、人员）统一维护，全链路共享，避免多头录入与数据不一致。
